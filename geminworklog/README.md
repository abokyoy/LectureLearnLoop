# Gemini工作日志系统

## 目录说明

本目录用于存储所有Gemini CLI编程工作的详细日志记录，确保每次开发工作都有完整的文档追踪。

## 文件命名规范

### 日志文件命名
- **格式**: `YYYY-MM-DD_session_XXX.md`
- **示例**: `2024-09-29_session_001.md`
- **说明**: 
  - `YYYY-MM-DD`: 工作日期
  - `session_XXX`: 当天的会话编号（001, 002, 003...）

### 特殊文件
- `工作日志模板.md` - 标准工作日志模板
- `README.md` - 本说明文件
- `summary_weekly.md` - 周总结报告
- `summary_monthly.md` - 月总结报告

## 使用流程

### 1. 开始新的工作会话
```bash
# 1. 复制模板文件
cp 工作日志模板.md 2024-09-29_session_002.md

# 2. 编辑文件，填写会话信息
# 3. 在工作过程中实时更新日志
```

### 2. 工作日志记录要点

#### 必须记录的内容
- **会话基本信息**: 时间、目标、涉及模块
- **核心改动**: 文件修改、新增功能、问题修复
- **发现的问题**: 技术问题、架构问题及其原因分析
- **测试结果**: 功能测试、集成测试的结果
- **下次计划**: 待完成的任务和计划

#### 建议记录的内容
- **性能分析**: 响应时间、内存使用情况
- **代码质量评估**: 规范性、架构合规性
- **用户体验评估**: 界面交互、功能完整性
- **学习收获**: 新技术、解决思路、最佳实践
- **风险评估**: 技术风险、进度风险等

### 3. 工作会话结束
- 完善日志内容
- 总结本次会话的主要成果
- 规划下次工作重点
- 更新相关文档

## 日志质量标准

### 优秀日志的特征
- ✅ **完整性**: 包含所有必要信息
- ✅ **准确性**: 描述准确，无误导信息
- ✅ **清晰性**: 结构清晰，易于理解
- ✅ **可追溯**: 能够根据日志重现工作过程
- ✅ **有价值**: 对后续工作有指导意义

### 常见问题避免
- ❌ 过于简略，缺少关键信息
- ❌ 只记录结果，不记录过程和原因
- ❌ 技术细节不够，无法重现
- ❌ 问题分析不深入，只描述现象
- ❌ 缺少测试验证和质量评估

## 日志分类标签

### 工作类型标签
- `[FEATURE]` - 新功能开发
- `[BUGFIX]` - 问题修复
- `[REFACTOR]` - 代码重构
- `[OPTIMIZE]` - 性能优化
- `[DOCS]` - 文档更新
- `[TEST]` - 测试相关
- `[CONFIG]` - 配置变更

### 优先级标签
- `[HIGH]` - 高优先级
- `[MEDIUM]` - 中优先级
- `[LOW]` - 低优先级

### 状态标签
- `[COMPLETED]` - 已完成
- `[IN_PROGRESS]` - 进行中
- `[BLOCKED]` - 被阻塞
- `[PENDING]` - 待处理

## 周期性总结

### 周总结 (每周五)
- 汇总本周所有工作会话
- 分析主要成果和问题
- 评估进度和质量
- 规划下周工作重点

### 月总结 (每月最后一天)
- 汇总本月所有工作内容
- 分析技术成长和项目进展
- 总结经验教训和最佳实践
- 制定下月发展计划

## 文件管理规则

### 归档规则
- 当前月份的日志保持在根目录
- 历史月份的日志移动到对应的年月子目录
- 重要的总结报告长期保留

### 目录结构示例
```
geminworklog/
├── 2024-09/                    # 当前月份
│   ├── 2024-09-29_session_001.md
│   ├── 2024-09-29_session_002.md
│   └── summary_weekly_39.md
├── 2024-08/                    # 历史月份
│   └── [历史日志文件]
├── 工作日志模板.md
├── README.md
└── summary_monthly_2024-08.md
```

## 最佳实践建议

### 1. 实时记录
- 在工作过程中实时更新日志
- 不要等到工作结束才开始写日志
- 重要的决策和发现立即记录

### 2. 详细描述
- 技术细节要足够详细，便于后续重现
- 问题分析要深入到根本原因
- 解决方案要包含具体步骤

### 3. 客观记录
- 如实记录遇到的问题和困难
- 不隐瞒失败的尝试和错误的决策
- 客观评估代码质量和性能

### 4. 前瞻规划
- 每次工作结束都要规划下次重点
- 识别潜在风险和挑战
- 制定应对策略和备选方案
