## 引言
本文件为 LectureLearnLoop 项目的数据库设计文档，聚焦于用户表、知识点表、练习记录表、积分交易表以及新增的记忆追踪、导入历史等表结构的数据模型与实现。经过从双SQLite/PostgreSQL架构到纯PostgreSQL后端的完全迁移，系统现在采用简化的单一数据库架构，专注于PostgreSQL的高性能和功能特性。文档涵盖实体关系、字段定义、主键/外键、索引与约束、数据验证规则与业务规则、Schema 图与示例数据、数据访问模式、缓存策略与性能优化、数据生命周期与归档策略、迁移路径与版本管理，以及数据安全、隐私与访问控制等主题。目标是帮助开发者与维护者快速理解并正确使用数据库层。

## 项目结构
本项目采用 Python Web 服务架构，数据库相关代码集中在 server/database 与 server/dal 目录中：
- schema_postgres.py：PostgreSQL 数据库 Schema 定义（DDL）
- schema_import.py：导入历史相关表的 DDL
- dal/__init__.py：数据访问层入口（对外暴露的查询/写入接口）
- routes_knowledge.py / routes_credits.py / routes_memory.py：知识管理、积分、记忆相关的 HTTP 路由
- knowledge_management.py / credits_service.py：领域服务层，封装业务逻辑
- auth.py：认证与权限控制
- config.py：配置项（数据库连接、日志等）
- app.py：应用启动与路由注册

#### 用户表（USERS）
- 主键：id（UUID）
- 唯一约束：username、email
- 关键字段：
  - password_hash：密码哈希值
  - is_active：账户状态
  - created_at、updated_at：时间戳
- 索引建议：
  - 对 username、email 建立唯一索引（由唯一约束保证）
  - 对 is_active 建立普通索引以支持常见筛选
- 业务规则：
  - 用户名与邮箱全局唯一
  - 密码必须通过安全哈希存储，禁止明文
  - 账户激活状态影响登录与资源访问

#### 知识点表（KNOWLEDGE_POINTS）
- 主键：id（UUID）
- 外键：user_id 引用 USERS(id)
- 关键字段：
  - title、content：标题与内容
  - status：状态枚举（如草稿、已发布、已归档）
  - tags：标签 JSONB，便于灵活检索
  - metadata：扩展元数据 JSONB，支持更丰富的属性
  - created_at、updated_at：时间戳
- 索引建议：
  - 对 user_id 建立索引以加速按用户查询
  - 对 status 建立索引以支持过滤
  - 对 tags 使用 GIN 索引以支持 JSONB 查询
  - 对 metadata 使用 GIN 索引以支持复杂查询
- 业务规则：
  - 仅用户本人可编辑其知识点（需鉴权）
  - 状态变更需遵循工作流（草稿→已发布→已归档）

### 数据访问模式
- DAL 入口提供统一的查询与写入方法，直接面向PostgreSQL数据库。
- 服务层封装业务逻辑，DAL 仅暴露数据操作能力。
- 移除了复杂的数据库抽象层，简化了数据访问流程。

```mermaid
flowchart TD
Start(["进入 DAL"]) --> CheckTxn["检查事务上下文"]
CheckTxn --> |有事务| ExecInTxn["在事务中执行"]
CheckTxn --> |无事务| ExecAuto["自动提交模式"]
ExecInTxn --> MapResult["映射结果集"]
ExecAuto --> MapResult
MapResult --> End(["返回结果"])
```

## 性能考虑
- 索引策略：
  - 对用户表：username、email 唯一索引；is_active 普通索引
  - 对知识点表：user_id、status 索引；tags、metadata 使用 GIN 索引
  - 对练习记录表：user_id + knowledge_point_id 复合索引；completed_at 索引
  - 对积分交易表：user_id + occurred_at 复合索引；type 索引
  - 对记忆错误表：user_id + knowledge_point_id 复合索引；difficulty、last_reviewed 索引
  - 对记忆知识点表：user_id + knowledge_point_id 复合索引；next_review、retention_score 索引
  - 对导入历史表：user_id + status 复合索引；source_type、started_at 索引
- 查询优化：
  - 避免 N+1 查询，批量加载关联数据
  - 分页与游标查询，防止大结果集拖慢响应
  - 使用覆盖索引减少回表查询
- 事务与锁：
  - 积分交易使用事务确保一致性
  - 热点账户余额更新使用行级锁或乐观并发控制
  - 记忆复习调度使用适当的隔离级别
- 缓存策略：
  - 热点知识点可缓存（Redis），设置过期时间与失效策略
  - 用户基本信息缓存，减少频繁读取
  - 待复习知识点列表缓存，提高复习效率
- 连接池：
  - 合理配置PostgreSQL连接池大小，避免连接耗尽
  - 监控慢查询与长事务

## 故障排查指南
- 常见问题：
  - 连接失败：检查PostgreSQL数据库配置与网络连通性
  - 事务冲突：查看锁等待与死锁日志
  - 索引缺失：分析慢查询日志并补充索引
  - 权限错误：检查认证与授权逻辑
  - 记忆调度异常：检查 next_review 时间计算逻辑
  - 导入失败：查看导入历史记录中的错误信息
- 诊断步骤：
  - 启用详细日志，记录 SQL 与参数
  - 使用 EXPLAIN ANALYZE 分析查询计划
  - 监控连接池与事务时长
  - 校验数据一致性与完整性约束
  - 检查记忆复习调度的时间窗口
  - 分析导入任务的状态流转

### 数据生命周期与归档策略
- 活跃数据：
  - 近 6 个月的练习记录与积分交易保持热数据
  - 近 3 个月的记忆错误与记忆知识点保持热数据
- 归档数据：
  - 超过 6 个月的练习记录与积分交易归档至历史表或冷存储
  - 超过 3 个月的记忆数据归档至历史表
  - 超过 1 年的导入历史记录归档
- 清理策略：
  - 删除长期未激活的用户及其关联数据（经确认与通知）
  - 清理失败的导入历史记录（保留最近 30 天）
- 备份与恢复：
  - 定期全量备份与增量备份
  - 制定灾难恢复演练计划

  - 先在小流量环境验证迁移脚本

  - 用户数据严格隔离，防止跨用户访问
