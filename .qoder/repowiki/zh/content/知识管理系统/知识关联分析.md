## 架构总览
知识关联分析的整体流程如下：
- 前端通过 api.js 调用 routes_knowledge.py 提供的接口。
- 路由层将请求转发至 knowledge_management.py 进行编排。
- 编排器根据触发条件选择关联策略，必要时调用 similarity_matcher.py 进行相似度计算。
- 结果持久化到数据库（db_adapter.py），由 schema_postgres.py 定义的数据模型支撑。
- 前端 knowledge_base.html 渲染图谱并进行交互。

## 详细组件分析

### 知识点自动关联触发条件
- 触发时机
  - 新增或更新知识点时触发增量关联。
  - 用户主动点击“重新关联”或“批量关联”时触发全量或范围关联。
  - 后台定时任务扫描未关联或弱关联的知识点对。
- 触发条件
  - 内容维度：关键词重叠、主题标签一致、语义相似度超过阈值。
  - 上下文维度：同课程/同会话/同时间窗内出现。
  - 业务规则：依据业务规则总览中的约束决定是否允许建立关联。
- 去重与幂等
  - 基于（源知识点ID，目标知识点ID，关系类型）三元组去重。
  - 同一批次内避免重复计算与重复写入。

```mermaid
flowchart TD
Start(["开始"]) --> CheckTrigger{"是否满足触发条件？"}
CheckTrigger --> |否| EndNoop["结束不执行"]
CheckTrigger --> |是| BuildCandidates["构建候选知识点对"]
BuildCandidates --> Score["计算关联强度"]
Score --> Threshold{"是否超过阈值？"}
Threshold --> |否| Discard["丢弃该候选对"]
Threshold --> |是| Persist["持久化关联关系"]
Persist --> EndOK["结束已更新"]
Discard --> EndOK
```

### 关联强度计算方法
- 多因子加权
  - 语义相似度：来自 similarity_matcher.py 的向量或嵌入相似度。
  - 共现强度：在同一上下文窗口内的出现频次。
  - 时序相关性：先后出现的顺序一致性与时序衰减。
  - 业务权重：依据业务规则赋予不同关系类型的权重。
- 归一化与阈值
  - 对原始分数进行归一化，确保跨主题可比。
  - 设置全局/局部阈值以过滤噪声边。
- 稳定性控制
  - 引入历史边权重平滑，避免单次波动导致剧烈变化。
  - 对高频但低质量的边进行降权或屏蔽。

```mermaid
flowchart TD
A["输入：知识点A与B"] --> S1["计算语义相似度"]
A --> S2["统计共现次数"]
A --> S3["计算时序相关性"]
S1 --> W["加权融合"]
S2 --> W
S3 --> W
W --> N["归一化"]
N --> T{"是否超过阈值？"}
T --> |是| R["输出：关联强度"]
T --> |否| X["丢弃"]
```

### 知识图谱构建算法
- 节点关系提取
  - 从知识点元数据、文本内容与上下文事件中提取潜在关系。
  - 关系类型包括：前置知识、后继知识、并列概念、冲突修正、示例-概念等。
- 边权重计算
  - 使用上述关联强度方法为每条边赋权。
  - 结合关系类型进行差异化缩放。
- 图结构优化
  - 剪枝：移除低于阈值的边，降低图密度。
  - 聚类：对高连通子图进行社区划分，辅助导航与折叠。
  - 布局：采用力导向或层次布局提升可读性。
  - 索引：为常用查询字段建立索引，加速检索与遍历。

Extract --> Edges["带权重边集合"]
Edges --> Optimize["图结构优化"]
Optimize --> Graph["最终知识图谱"]

### 关联规则发现机制
- 共现分析
  - 统计知识点在同一会话/课程/时间窗内的共现频率。
  - 使用置信度与支持度筛选强规则。
- 时序关联
  - 基于先后出现顺序构建有向边，考虑时序衰减函数。
  - 识别典型学习路径与常见误区序列。
- 内容相似性匹配
  - 借助 similarity_matcher.py 计算语义相似度，合并近义知识点。
  - 对相似度高但无显式关系的知识点建立“近似等价”边。

RuleA --> Merge["规则合并与去重"]
RuleB --> Merge
RuleC --> Merge
Merge --> Output["输出关联规则集"]

### 批量处理流程与增量更新机制
- 批量处理
  - 支持按课程/会话/日期范围拉取知识点子集。
  - 分片并行计算，限制并发数以避免资源争用。

### 关联质量评估指标与优化策略
- 评估指标
  - 精确率/召回率：基于人工标注或抽样校验。
  - F1 值：综合衡量准确性与完整性。
  - 覆盖率：被关联知识点占总知识点的比例。
  - 平均边权重：反映整体关联强度水平。
  - 图密度与连通分量数：衡量图结构与可导航性。
- 优化策略
  - 动态阈值：根据数据集规模与分布自适应调整。
  - 负样本挖掘：识别误报边并加入惩罚项。
  - 特征工程：引入更多上下文特征（如章节位置、难度等级）。
  - 在线学习：随用户反馈逐步校准权重与阈值。

## 性能与可扩展性
- 计算复杂度
  - 相似度计算通常为 O(n^2) 级别，需通过分片与缓存降低开销。
  - 图遍历与布局算法复杂度与节点/边数量相关，建议按需加载子图。
- 缓存与索引
  - 缓存热点知识点与相似度结果，减少重复计算。
  - 为常用查询字段建立复合索引，提升检索性能。
- 扩展性
  - 支持横向扩展：将相似度计算与批量任务拆分为独立服务。
  - 插件化策略：允许替换相似度算法与关系提取规则。

## 故障排查指南
- 常见问题
  - 关联过少：检查阈值设置、相似度模型与业务规则。
  - 关联过多：提高阈值、增加负样本惩罚、启用图剪枝。
  - 更新延迟：检查增量事件队列与并发配置。
  - 可视化卡顿：减少一次性渲染节点数，启用分页与懒加载。
- 定位步骤
  - 查看后端日志与错误堆栈。
  - 核对数据库记录与索引状态。
  - 在前端控制台检查 API 响应与网络耗时。
- 恢复措施
  - 重置阈值并重新运行增量任务。
  - 清理无效边与孤立节点。
  - 回滚到上一稳定版本策略。
