模块由三层组成：
- 提供商抽象层（`llm_provider_factory.py`）：定义 `LLMProvider` 基类及 `OllamaProvider`/`GeminiProvider`/`DeepSeekProvider`/`QwenProvider`/`SiliconFlowVisionProvider` 五个实现，统一 `call(prompt, context, usage_out, images)` 接口；`LLMProviderFactory` 单例根据配置 `llm_provider` 字段选择实例并缓存，同时承担计费路由——有登录用户时走 `_call_billed`（先试用户自备 Key，失败回落系统 Key；视觉调用强制走 SiliconFlow VL），无用户上下文走 `_call_legacy`。
- 调用日志层（`llm_call_logger.py`）：`LLMCallLogger` 单例以 `start_llm_call` / `record_first_byte` / `end_llm_call` 三段式记录每次调用的 provider、model、首字节时间、总耗时、成功状态、错误信息，并按天写入 `logs/llm_calls_YYYYMMDD.jsonl`，暴露 `get_statistics()` 聚合统计。
- API 调试日志层（`llm_logger.py`）：独立的 `LLMLogger` 为 Gemini/Ollama/Qwen/DeepSeek 各提供专用 `log_*_call` 方法，输出人类可读的 `.log` 与结构化 `_detailed.jsonl`，面向具体 Provider 实现做输入输出快照。
依赖方向：`llm_provider_factory.py` → `llm_call_logger.py`（通过便捷函数 `start_llm_call`/`record_first_byte`/`end_llm_call`），两个日志模块彼此独立、互不引用。
