以 `app.py` 的 `create_app()` 为唯一装配点：先通过 `config.load_config()` + dotenv 加载 `.env`，创建 `DatabaseManager`（内部封装 `database/db_adapter.py` 的 psycopg2 ThreadedConnectionPool）并挂到 `app.config['DB_CONN_FACTORY']`，再依次调用 `init_auth_table` / `init_credits_tables` / `init_import_tables` 建表并恢复导入任务，最后按阶段注册 pages_bp → auth_bp → kb_bp → bridge_bp → notes_bp → credits_bp → admin_bp → memory_bp 八个 Blueprint。

内部分层清晰：
- 配置层：`config.py` 是唯一配置入口，提供 `load_config()`（兼容旧 app_config.json 键名）、`get_flask_secret_key()`（持久化到 `data/flask_secret.key`）、运行时配置读写（`runtime_config.json`）。
- 数据层：`database/db_adapter.py` 提供 `ConnWrapper`/`CursorWrapper`，将 SQLite 风格 SQL（`?` 占位符、`CURRENT_TIMESTAMP`、`INSERT OR IGNORE`）翻译为 PostgreSQL 方言，并通过 `RETURNING id` 回填 lastrowid；业务代码仅依赖统一的 `DatabaseError`/`IntegrityError`/`OperationalError` 异常族。
- 服务层：`services/` 下 fsrs_service、import_service、paddle_doc_client、practice_service、error_slicer 封装跨进程外部能力。
- 路由层：`routes_*.py` 每个文件对应一个 Blueprint，只负责 HTTP 参数解析与 JSON 响应，不直接持有 DB 连接。
- 模板与静态资源：`templates/`（Jinja2，含 spa_layout/base/pages/components）、`static/`（前端 JS/CSS/pdfjs）。

依赖方向单向：routes → services → database/config；Blueprint 之间不互相 import 业务类，仅通过 `app.config` 共享 `DB_CONN_FACTORY` 与 `debug_logger` 单例。
