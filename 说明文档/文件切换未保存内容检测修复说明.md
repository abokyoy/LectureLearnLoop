# 文件切换未保存内容检测修复说明

## 问题描述

用户反馈：在编辑文件A时，如果没有保存的情况下点击文件结构中的另一个文件B，系统没有弹出保存提示对话框，而是直接切换到文件B，可能导致编辑内容丢失。

## 问题分析

### 原始问题
1. **页面切换检测正常**：点击侧边栏菜单（如"学-从资料学习"）时，未保存内容检测工作正常
2. **文件切换检测缺失**：在同一页面内点击文件树中的其他文件时，没有触发未保存内容检测
3. **系统不一致**：两种导航方式的行为不一致，用户体验不佳

### 技术原因
1. **检测范围有限**：未保存内容守卫系统只在`loadContent`方法（页面级导航）中生效
2. **文件点击处理独立**：文件树的点击处理函数`handleFileClick`没有集成未保存内容检测
3. **状态管理分离**：页面有自己的`hasUnsavedChanges`变量，但没有与新的守卫系统同步

## 修复方案

### 1. 修改文件点击处理逻辑

#### 网课笔记页面 (`online_course_notes.html`)
**修改位置**：`handleFileClick`函数（第5190-5221行）

**修改前**：
```javascript
if (type === 'file' && path.endsWith('.md')) {
    // 检查是否在编辑模式且有未保存的更改
    if (isEditMode && hasUnsavedChanges && currentFilePath && currentFilePath !== path) {
        // 使用旧的保存逻辑
        saveCurrentFile(function() {
            loadFileContentAndSwitchToEdit(path, name);
        });
    } else {
        // 直接加载文件
        loadFileContent(path, name);
    }
}
```

**修改后**：
```javascript
if (type === 'file' && path.endsWith('.md')) {
    // 使用新的未保存内容守卫系统检查
    if (window.UnsavedChangesGuard && currentFilePath && currentFilePath !== path) {
        console.log('🛡️ 检查文件切换时的未保存内容');
        
        // 使用守卫系统检查是否可以导航
        window.UnsavedChangesGuard.canNavigate(function() {
            console.log('✅ 用户确认切换文件，加载新文件: ' + path);
            
            // 重置守卫状态
            if (window.UnsavedChangesGuard) {
                window.UnsavedChangesGuard.reset();
            }
            
            // 根据当前模式加载文件
            if (isEditMode) {
                loadFileContentAndSwitchToEdit(path, name);
            } else {
                loadFileContent(path, name);
            }
        });
    } else {
        // 无未保存内容或同一文件，直接加载
        console.log('✅ 无未保存内容，直接加载文件: ' + path);
        
        if (isEditMode && currentFilePath && currentFilePath !== path) {
            loadFileContentAndSwitchToEdit(path, name);
        } else {
            loadFileContent(path, name);
        }
    }
}
```

#### 从资料学习页面 (`learn_from_materials.html`)
**修改位置**：`handleFileClick`函数（第801-823行）

应用了相同的修改逻辑，确保两个页面的行为一致。

### 2. 文件加载后重新注册编辑器

#### 问题
当用户切换到新文件后，未保存内容守卫系统需要重新监控新的文件编辑器。

#### 解决方案
在`loadFileContent`函数的文件加载完成回调中添加重新注册逻辑：

**网课笔记页面**（第5303-5346行）：
```javascript
// 重新注册编辑器到未保存内容守卫系统
setTimeout(function() {
    const editContent = document.getElementById('edit-content');
    if (editContent && window.UnsavedChangesGuard) {
        // 取消之前的监控
        window.UnsavedChangesGuard.reset();
        
        // 重新注册当前文件的编辑器
        window.UnsavedChangesGuard.registerEditor(editContent, filePath, function() {
            return new Promise((resolve, reject) => {
                // 保存回调逻辑
                if (filePath && editContent.value) {
                    console.log('💾 执行网课笔记保存 (文件切换后)');
                    
                    if (window.pybridge && window.pybridge.save_file) {
                        window.pybridge.save_file(filePath, editContent.value, function(result) {
                            // 处理保存结果
                            try {
                                const response = typeof result === 'string' ? JSON.parse(result) : result;
                                if (response.success) {
                                    console.log('✅ 网课笔记保存成功 (文件切换后)');
                                    originalContent = editContent.value;
                                    hasUnsavedChanges = false;
                                    hideUnsavedIndicator();
                                    resolve();
                                } else {
                                    console.error('❌ 网课笔记保存失败 (文件切换后):', response.error);
                                    reject(new Error(response.error));
                                }
                            } catch (e) {
                                console.error('❌ 解析保存响应失败 (文件切换后):', e);
                                reject(e);
                            }
                        });
                    } else {
                        reject(new Error('保存功能不可用'));
                    }
                } else {
                    reject(new Error('没有文件路径或内容'));
                }
            });
        });
        
        console.log('✅ 文件切换后重新注册编辑器到未保存内容守卫');
    }
}, 500);
```

**从资料学习页面**应用了相同的逻辑，使用对应的保存API。

### 用户体验改进

2. **数据保护**：防止用户在文件切换时意外丢失编辑内容
3. **友好提示**：统一的保存提示对话框，提供"保存"、"不保存"、"取消"三个选项

### 技术改进

2. **状态同步**：新旧系统的状态保持同步
3. **自动重新注册**：文件切换后自动重新设置编辑器监控

3. **空文件切换**：从空文件切换到其他文件，不应该触发保存提示

- ✅ 保存提示对话框正常显示和交互

- ✅ 控制台日志显示正确的调试信息

## 技术要点

### 关键实现
1. **条件检查**：`window.UnsavedChangesGuard && currentFilePath && currentFilePath !== path`
2. **异步处理**：使用回调函数处理用户选择后的导航
3. **状态重置**：切换文件前重置守卫系统状态
4. **延迟注册**：使用500ms延迟确保DOM元素完全加载

### 兼容性考虑
1. **向后兼容**：保留原有的变量和函数，确保现有功能不受影响
2. **渐进增强**：新的守卫系统作为增强功能，不影响基础功能
3. **错误处理**：完善的错误处理和降级机制

### 性能优化
1. **条件执行**：只在必要时执行未保存内容检测
2. **延迟注册**：避免在文件加载过程中重复注册
3. **状态缓存**：合理使用状态缓存减少重复计算

## 总结

通过这次修复，LectureLearnLoop系统的未保存内容检测功能现在覆盖了所有导航场景：

1. **页面级导航**：侧边栏菜单切换（已有功能）
2. **文件级导航**：文件树中的文件切换（新增功能）
3. **浏览器级导航**：页面刷新、关闭、切换标签页（已有功能）

这确保了用户在任何情况下都不会意外丢失编辑内容，显著提升了系统的可靠性和用户体验。
