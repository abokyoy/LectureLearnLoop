## 一、知识点提取流程

### 1.1 提取触发

**来源**：`app_flask.py` L147-170，`knowledge_management.py` L2118-2167

**[已确认] subject_name 来源规则**：用户在「资料学习」页面**先选择/输入学科名称**，提取时将 `subject_name` 随 `text` 一同发送到后端。当前后端 `api_extract_knowledge()` 缺少此参数，是待修复的 BUG。

用户在「资料学习」页面输入文本，调用 `POST /api/knowledge/extract`，传入 `text` 字段。

**后端流程**（`extract_and_process_knowledge_points`）：
```
1. 调用 LLM 提取核心概念（extract_knowledge_points）
   ※ 已知 BUG：app_flask.py 调用时只传 text，缺少 subject_name 参数，实际会抱 TypeError
   ※ 该 BUG 待修复，修复前此 API 将返回 500
2. 对每个提取到的知识点，查找相似已有知识点（find_similar_knowledge_points）
3. 返回格式：
   {
     "subject_name": "...",
     "processed_points": [
       {
         "extracted_point": {concept_name, core_definition},  ※ LLM 输出字段名
         "similar_points": [{id, point_name, score}...],
         "match_status": "已存在相似知识点" | "无相似知识点（新知识点）"
       }
     ]
   }
```

### 1.2 知识点确认（merge / new / skip）

**来源**：`knowledge_management.py` L2169-2224

用户对每个提取结果执行三种操作之一：

| 操作 | 传入参数 | 后端行为 |
|------|---------|---------|
| `merge` | `existing_id: int` | 调用 `merge_to_existing_point()`，追加描述到已有知识点，建立笔记 UUID 关联 |
| `new` | `subject_name: str` | 调用 `save_knowledge_point()`，新建知识点，建立笔记 UUID 关联 |
| `skip` | - | 跳过，不保存 |

> **[已确认]** merge 时，若用户修改了 point_name，**新名称覆盖旧名称**。用户确认弹窗中应展示当前旧名称，允许修改。

### 1.3 LLM 提取 Prompt 规范

**来源**：`knowledge_management.py` L318-400（KnowledgePointManager.extract_knowledge_points）

Prompt 要求 LLM：
- 仅提取学科**核心概念**，不提取举例和练习
- 输出 JSON 数组，每个元素包含：
  - `concept_name`（中文名）  ※ 注意：非 `point_name`，入库前靠双字段兼容读取
  - `core_definition`（1-2句精准核心定义） ※ 注意：非 `core_description`
- 输出数量控制：短材料 1-7 个知识点，长材料 ≤ 8 个
- 禁止输出 Markdown 代码块，直接输出 JSON

## 二、知识点相似度匹配规则

**来源**：`similarity_matcher.py`（全文263行）

### 2.1 匹配算法

提供两种模式，优先使用 Embedding，不可用时回退到启发式：

**模式1：Embedding（Ollama nomic-embed-text）**
```
综合得分 = 0.3 × 余弦相似度(embedding) + 0.7 × 名称顺序比(SequenceMatcher)
全名精确匹配（normalize后）→ 得分 ≥ 0.99
名称 ratio ≥ 0.95 → 得分 ≥ 0.95
```

**模式2：启发式回退（无 Ollama 时）**
```
综合得分 = 0.75 × 名称顺序比 + 0.25 × (0.6×顺序比全文 + 0.4×Jaccard token重叠)
```

### 2.2 阈值

- `best_match()` 接受阈值：`min_score = 0.35`（低于 0.35 视为无匹配）
- 相似度结果按得分降序排列，可取 top_k

> **[已确认]** 当前使用 `min_score = 0.35`。这个阈值是初步设定，实际运行中根据误匹配情况动态调整。

## 三、知识点熟练度算法（mastery_score）

**来源**：`overlay_drag_corgi_app.py`（Qt版本实现，Flask版尚未迁移此 API）

### 3.1 难度权重定义

| 难度等级 | 权重 |
|---------|------|
| 容易 | 1.0 |
| 中等 | 1.2 |
| 困难 | 1.5 |

### 3.2 计算公式

```python
weighted_score = 0
total_weight = 0
for result in detailed_results:
    weight = difficulty_weights.get(result['difficulty'], 1.0)  # 未知难度默认1.0
    if result['is_correct']:
        weighted_score += weight
    total_weight += weight

if total_weight > 0:
    mastery_score = int((weighted_score / total_weight) * 100)
else:
    mastery_score = int(accuracy * 100)  # 无题可算时用正确率兜底

mastery_score = max(0, min(100, mastery_score))  # clamp [0,100]
```

**核心逻辑**：做对难题得分更高，同样正确率下做难题熟练度更高。

### 3.3 调用时机（三通道，2026-10-01 全量留痕落地）

知识点详情页共有**三个练习通道**，用户在页内逐题作答后提交，后端一律：**落 `practice_records` 流水 → 答错题自动入 `error_questions` 错题池 → 按难度加权重算并落库 `mastery_score` → 失效该科目脑图缓存**。

| 通道 | 端点 | 题型 | 判分方式 |
|------|------|------|---------|
| 熟练度评估 | `.../generate-assessment` + `.../assessment` | **纯选择题 10 题**（保持不变，判分纯净） | 本地按首字母 |
| 基于笔记练习 | `.../generate-practice`(source=notes) + `.../practice-submit` | **8 题混合**：单选3/判断2/填空2/简答1 | 客观题本地归一判分；简答题 **LLM 判分**（消耗积分） |
| 举一反三练习 | `.../generate-practice`(source=analogy) + `.../practice-submit` | 同上 8 题混合 | 同上 |

**结构化出题契约**：笔记/举一反三通道由 LLM 返回严格 JSON 数组（8 题，字段 `type/question/options/correct_answer/difficulty/explanation`），逐题类型校验非法即报错。

**判分归一规则**：单选=首字母大写相等；判断=归一到「正确/错误」（接受 对/错/√/×/true/yes 等变体）；填空=去空白+大小写归一+全角标点转半角后，与 `correct_answer` 按 `|`（兼容全角｜）分隔的任一可接受答案相等；简答=学生答案与参考答案一起交 LLM 判对错并给一句点评。

**简答判分失败策略**：LLM 判分失败或结果不完整 → 整体报错**不落库**（避免半套留痕），用户可重试。

**未评估哨兵**：新建知识点 DB 落库 `mastery_score = -1`（Qt 旧语义返回体回填 50 仅供展示兼容），展示层统一显示「未评估」，**禁止当 0 分展示或参与均值/推荐排序权重**。

**[已确认]** mastery_score 采用**全量重算**：每次做完练习，从该知识点的所有历史答题记录重新计算熟练度。新答题影响整体分数，不会因单次失误归零。

### 3.4 选择题选项随流水留存（2026-10-01 错题翻卡改造）

- 每次作答（三个练习通道均含）落 `practice_records` 时同时写入 **题型（question_type）与选项（options_json）**；选择题没有留存选项的错题视为数据缺失。
- 判断题/填空题/简答题无选项，`options_json` 落 NULL。
- 错题查询（`/api/kb/errors`）JOIN 流水带回题型与选项；选项 JSON 损坏时降级为无选项，不得打挂整个列表。
- **存量旧错题不补选项**（用户裁定）：复习时降级显示题干+答案+解析，并标注「该题未保存选项（旧数据）」。

### 3.5 判分结果页显示原题选项（2026-10-08 用户要求落地）

- 三个结构化通道的**即时判分结果页**，选择题必须完整列出原题选项（A/B/C/D 文本）：正确答案绿色浅底高亮+对勾，用户误选项红色浅底+「（你选的）」标注；不得只展示字母不展示选项内容。
- 判断题/填空题/简答题无选项时不显示选项区；「你的答案/正确答案/解析/AI 点评」信息行保留。
- 误选标注仅在答案落在合法选项字母范围或与选项文本相等时生效（防自由文本巧合误标，同口径支持判断题文本答案）。
- 数据源为页面本地已答题目数组（按 question_index 回取），不新增后端字段；刷新后回看走错题翻卡路径（见 4.3）。

## 四、错题熟练度规则

**来源**：`knowledge_management.py` L1239-1252（ErrorQuestionManager.append_proficiency）

**[已确认] 增量参数**：
- 学习率（答对）：`learning_rate = 0.2` → 当前60分答对后：`60 + (100-60) × 0.2 = 68`
- 遗忘率（答错）：`forget_rate = 0.3` → 当前60分答错后：`60 × (1-0.3) = 42`

### 4.1 存储方式

每次更新调用 `append_proficiency(error_question_id, proficiency)`：
1. clamp 到 `[0, 100]`
2. 写入 `error_proficiency_history` 表（追加，不覆盖历史）
3. 同步更新 `error_questions.current_proficiency` 字段

### 4.2 渐进式更新规则

**调用方**负责计算新值，`append_proficiency` 只做 clamp + 写入。

增量算法（从原 Qt 代码分析）：
```
初始值 = 20
答对一题：新值 = 当前值 + (100 - 当前值) × learning_rate  （learning_rate 约 0.2）
答错一题：新值 = 当前值 × (1 - forget_rate)               （forget_rate 约 0.3）
```

> **[待确认]** 上述 learning_rate / forget_rate 具体数值未在 Flask 版代码中直接找到，需确认是否在 `practice_service.py` 中实现。

### 4.3 错题翻卡复习（2026-10-01，用户裁定的核心复习形态）

**来源**：`static/js/pm_pages.js`（bootMemoryErrors/goReviewError）、`routes_knowledge.py`（memory_overview 推荐复习）

- 「记错题」页**默认卡片复习模式**，可切列表；列表仍作全量管理视图（展开区含选项/答案/解析）。
- 卡片可**点击翻转**：正面 = 题干 + 选项（不标答案）；背面 = 正确答案 + 我的答案 + 选项（按索引字母 A/B/C/D 高亮正确项，与答题页同契约）+ 解析。
- 翻卡队列 = **全部待复习错题按推荐序**：熟练度升序，未评估/null 视作最弱排最前（与总览推荐同口径），无截止到期概念，逐张「标记已复习，下一题」无脑连续翻。
- 待复习全部翻完 → 完成页，可进入**已复习巩固轮**继续翻；标记请求在途时锁定导航防跳卡。
- 总览「推荐复习错题·去复习」**直达**翻卡序列：旗标 `pm_pending_review`（学科+错题 id，10s 过期消费即清），非第一学科也能落在正确学科队列并定位到对应卡；不在队列则从头翻。
- 存量无选项旧题：背面显示「该题未保存选项（旧数据）」降级提示（见 3.4）。

## 五、知识脑图缓存规则

**来源**：`knowledge_management.py` L2477-2538（MindmapManager）

### 5.1 查询流程

```
1. 查 DB（knowledge_mindmaps 表，按 user_id + subject_name 查询）
2. 有缓存 → 直接返回（cache_status: "from_cache"）
3. 无缓存 → 调用 LLM 生成 → 保存 DB → 返回（cache_status: "newly_generated"）
```

### 5.2 脑图数据结构

```json
{
  "nodes": [
    {"id": "center", "name": "学科名", "type": "center", "level": 0, "x": 400, "y": 300},
    {"id": "category_1", "name": "基础概念", "type": "category", "level": 1},
    {"id": "kp_1", "name": "知识点名", "type": "knowledge_point", "level": 2}
  ],
  "edges": [
    {"source": "center", "target": "category_1", "relation": "包含", "direction": "forward"},
    {"source": "category_1", "target": "kp_1", "relation": "细分为", "direction": "forward"}
  ]
}
```

节点类型枚举：`center`（根）/ `category`（分类）/ `knowledge_point`（知识点）  
关系类型枚举：`包含` / `细分为` / `依赖于` / `关联到`

### 5.3 版本管理

每次 `save_mindmap()` 时 `version` 字段自增（`version + 1`），可用于检测过期。

> **[已确认]** 脑图永动期保持缓存，**只有用户点击“重新生成”按钮时**才触发 LLM 重新生成。新增知识点不会自动刷新脑图。

## 六、LLM 调用路由规则

**来源**：`llm_provider_factory.py`（全文452行），`app_config.json`

### 6.1 提供商选择

当前配置（`app_config.json`）决定主提供商：
```json
{"llm_provider": "Qwen", ...}
```

工厂根据 `llm_provider` 字段路由到对应 Provider 实例：
- `"Ollama"` → `OllamaProvider`（本地模型，无需 API Key）
- `"Gemini"` → `GeminiProvider`
- `"DeepSeek"` → `DeepSeekProvider`
- `"Qwen"` → `QwenProvider`

### 6.2 配置热重载

`LLMProviderFactory.call()` 每次调用时检查 `config_hash`，若配置发生变化（用户在设置页修改了 API Key 等），自动重建 provider，无需重启服务。

### 6.3 LLM 调用日志

每次调用都通过 `LLMCallLogger` 单例记录，写入 `logs/llm_calls_YYYYMMDD.jsonl`，包含：
- provider、model、prompt 前200字、response 前200字、耗时、成功/失败

> **[已确认]** LLM 提供商失败时**直接报错**给用户，不尝试自动切换备选提供商。用户可在设置页面手动切换后重试。`knowledge_management.py` 中的历史手写降级链（DeepSeek→Gemini→Ollama→规则）属应收敛的技术债，应迁移到统一工厂。

## 十一、用户积分与充值规则（2026-09-28）

**来源**：`credits_service.py`、`routes_credits.py`、`routes_admin.py`、`llm_provider_factory.py`（`_call_billed`）、`auth.py`（登录赠送 / ASR 闸口）、`database/schema_credits.py`

### 11.1 换算口径

- **Token → 积分**：`积分 = round(总Token / 换算比例, 1)`；换算比例默认 **4000 Token = 1 积分**，可由管理员在后台配置（`credits_token_ratio`）。比例下限为 1（防误配小数导致除零）。
- 有 Token 消耗时**最小扣 0.1 积分**（避免微量调用免费）。
- **录音转文字（ASR）**：`分钟 = ceil(秒/60)`，`积分 = 分钟 × 每分钟费率`（`credits_asr_per_minute` 默认 1，即 1 分钟 = 1 积分）。自报时长封顶 24 小时，防异常值。
- **充值比例**：`credits_per_yuan` 默认 100 积分 = 1 元（仅用于展示与卡密面值参考）。

### 11.2 扣费时机（所有 AI 操作统一收敛到 `call_llm`）

| 场景 | 计费方式 | 来源端点/入口 |
|------|---------|--------------|
| AI Chat、生成练习题、答案评判、总结、脑图、提炼知识点 | 按 Token 折算扣分 | 全部经 `LLMProviderFactory.call_llm → _call_billed` |
| 录音转文字 | 按分钟扣分 | 停止录音后前端上报 `/api/credits/asr-charge` |
| 大模型连接测试 | 与正式调用同预检（不足即拦截，不实际扣分） | `/api/llm_test` |

### 11.3 系统 Key vs 用户自备 Key

- **用户自备 Key**（设置页配置，`user_llm_config`）：调用**不扣分**，但仍记一条 `delta=0, use_own_key=1` 的流水供审计；调用失败/返回空 → 自动**回落系统 Key 并按正常扣分**。
- **系统 Key**（管理员后台配置，`system_config`）：先做**余额预检**，`balance ≤ 0` 拦截并提示充值；调用成功后按 Token 扣分。
- **自备 Key 为空串语义**：设置页留空表示「保持原 Key 不变」；显式清除需勾选清除标记，防止误删 Key 后静默回落系统 Key 扣分。
- **ASR 只走系统 Deepgram Key**，用户级 Key 不影响转写计费。

### 11.4 余额不足的拦截

- **录音前**：`/api/asr/config` 下发转写密钥前预检，`balance ≤ 0` 返回 402 拒绝开启录音。
- **录音后**：录音已实际发生，`asr-charge` **允许扣成负余额**（欠费），后续 LLM 调用预检会拦截直至补齐。
- **LLM 调用**：预检不过抛 `InsufficientCreditsError`，前端 Chat 显示充值引导、非 Chat 场景 toast 提示。

### 11.5 每日登录赠送

- 每个自然日**首次登录**赠送 `credits_daily_bonus`（默认 100 积分）。
- 并发幂等：条件 UPDATE（`last_bonus_date <> 今日`）+ `rowcount` 判定，保证同一日只发一次。
- 配置为 0 即关闭赠送（管理员可在后台调整）。

### 11.6 卡密充值

- 管理员**批量生成**卡密（`activation_codes`，面值可配），电商渠道售卖。
- 用户在站内「我的积分」输入卡密**兑换**入账（`/api/credits/redeem`）。
- **防并发重复兑换**：PG 用 `FOR UPDATE` 行锁，SQLite 靠事务原子性；状态流转 `active → used`，条件更新保证同一码只成功一次。
- 卡密可**作废**（`active → void`）；已使用的不可作废。流水 note 仅保留卡密后 4 位（掩码），不泄漏全码。

### 11.7 管理员豁免与审计

- `is_admin=1` 用户调用系统 Key/ASR **不消耗积分**（预检直接放行、扣分为 0），但**仍记流水**（note 标注「管理员不消耗积分」），可审计用量。
- 管理员后台可对**任意用户手工调整**积分（`/api/admin/adjust`），采用相对更新防并发覆盖，拒绝使余额变负的调整，且校验目标用户存在。

### 11.8 前端呈现

- **AI Chat 窗口顶部**：实时积分徽章（余额 ≤ 0 变红）。
- **Chat 回复尾部**：打字机播完追加「本次消耗 N 积分 · 余额 M」注脚（会话被中断/取代时不追加，防串话）。
- **非 Chat 场景**：统一 `llHandleBilling` 钩子，API 响应含计费字段时 toast 提示扣分并刷新徽章。

## 十五、错题智能分析（2026-10-13，用户裁定方案 B）

**来源**：`services/error_analyze.py`、`services/task_registry.py`、`llm_provider_factory.py`（SiliconFlowVisionProvider）、`routes_knowledge.py`（error-analyze 端点）、`templates/pages/knowledge_base.html`

### 15.1 触发与入口

- 错题编辑弹窗内，题目内容（编辑框）非空时显示「🧠 智能分析」按钮；把当前草稿（文字+图片）整体送去整理成规范错题。
- 图片引用只认 vault 内相对路径（远程 http/data URL 在输入侧被剔除，输出侧模型返回的远程引用同样被剔除，入库内容只指向 vault 内文件）。

### 15.2 三步管线（Paddle 版面 → 切片 → 视觉大模型）

- **第一步**逐图 PaddleOCR 版面分析：得出文字区域矩形框（含识别文字）与图形区域矩形框；图形框按比例映射回本地原图裁剪成切片文件存 vault（`{原名}_figN.png`）。
- **第二步**把 MD 原文 + 版面结构（文字块/图形块/切片清单）+ 原图与各切片图片统一发给能看图的大模型，让它决定如何重新排版组织这道题。
- **第三步**模型按 JSON 契约返回：题干（MD）、学生解答转录、错因分析、正确答案、解析。
- **防错双保险**：题干文字逐字采用 OCR 与用户手输内容，模型只负责排版/理解/错因；OCR 与视觉互为校对。用户裁定的“图必须用 Paddle 切片”不依赖模型自觉：代码侧确定性保底（题干若引用原图且该图有切片，强制替换为切片路径）。
- 单图版面分析失败不拖垮整任务：该图降级为只发原图给大模型。

### 15.3 回填与入库（用户裁定）

- 分析完成后**先 confirm 再回填**（防静默覆盖已录内容）：回填题目内容/正确答案/解析三栏，回填后仍可编辑，**点保存才入库**。
- 用户的解答过程**如实**转录（含错误步骤，不得修正简化），并入「解析」字段开头小节「## 我的解答（如实转录）」；错因分析写「## 错在哪里」（错在哪一步、为什么错、大概率哪个知识点薄弱）；正确答案与解析写在各自字段。
- 模型返回题干为空视为任务失败，前端提示手填。

### 15.4 模型选择与扣分口径（用户裁定：与文字调用一致）

- 用户配置了支持视觉的模型 → 用用户的（不扣系统积分）；未配置/不支持看图 → 系统配置的视觉大模型（硅基流动 Qwen3-VL，走统一计费链）。
- 草稿无图片时自动退化走普通文字模型（同一入口，不强制走 VL）。
- 扣分只在模型调用成功后发生；服务端瞬态失败（5xx/网络异常）不扣分，允许自动重试（最多 3 次尝试）；模型返回内容解析失败**不重发请求**（防已扣分重复消耗）。
- 超时/失败后用户重点击：同一用户+同一草稿+同一图清单命中运行中任务时复用（在飞去重），**绝不起第二个任务、绝不双扣分**。
- 降级保底：任何环节失败，用户原内容保留，可重试或手动补录。

### 15.5 批量新增错题（2026-10-14 上线；2026-10-15 改分组批量调用，用户裁定）

**来源**：`services/error_batch.py`、`services/error_analyze.py`（`recognize_group`）、`routes_knowledge.py`（error-batch 端点）、`templates/pages/knowledge_base.html`

- **入口与动线**：知识库错题面板「批量新增错题」→ 多图上传（本地多选/手机拍照，先落 vault 截图/）→ 逐图全屏框选（一题一框，支持缩放/拖拽平移，框选默认开启）→ 提交后台识别 → 结果列表勾选入库（逐题走单题入库接口，不新建入库链路）。
- **识别口径（2026-10-15 用户裁定：切片图一次全给大模型，返回一组题）**：同一源图的裁剪图按**每组≤3 题**分组，每组**一次**视觉大模型调用返回 JSON 数组（题号 q 与元素绑定，模型编号不可信时宁缺题不串题）；组内单题失败/缺题**逐题回退**单题管线重识别（回退题另计一次积分）。
- **过小拦截**：裁剪短边不足 32px（下游 Qwen3-VL 硬限制宽高>28px）在服务层拦截，该题直接失败置灰，**不外呼不扣分**。
- **积分提示（用户裁定：去术语化）**：提交确认只告知「识别 N 道题，预计共消耗约 N×0.2 积分」，不得出现「版面分析/大模型调用次数」等术语；实际扣分按 token 计量。
- **失败隔离与进度**：单题失败不拖垮整批（该题置灰可查原因）；原图损坏仅该图全框失败；失败题裁片及其图形切片自动清理；进度逐题上报，部分完成后仍可查看已成功题目。

## 十六、错题公式显示（2026-10-13，用户裁定方案 A + 编辑弹窗）

**来源**：`static/js/md_render.js`、`static/js/pm_pages.js`、`templates/pages/knowledge_base.html`、`static/js/note_vditor.js`

### 16.1 定界符与识别口径

- 支持两种 LaTeX 定界符写法：`$…$`（行内）/`$$…$$`（块级），以及 `\(…\)`/`\[…\]`（OCR 变体）。
- `\$` 是字面美元符，不当公式定界符。
- **货币防误判**：`$5 和 $6` 这类「$ 后紧跟数字」的写法不识别为公式（数学式极少以纯数字开头）；代价是 `$5x$`（5 倍 x）这类写法显示原文。
- 未闭合的 `$` 围栏兜底：按原文保留，不吞后文。

### 16.2 渲染范围（全落点，用户裁定）

- **知识库错题列表**：题干、选项、答案、解析全部走「Markdown + 公式」管线。
- **错题练习页 / 错题记忆页**：错题行、翻卡正背面、选项、关联错题。
- **评估与练习面板**：答题时的题干/选项，判分结果的原题/你的答案/正确答案/解析/AI 点评。
- **编辑弹窗**：Vditor KaTeX 引擎实时渲染预览；**存储的仍是 MD 原文**（`$` 定界保留），老错题无需迁移，显示时自动渲染。

### 16.3 渲染管线与安全线（用户裁定方案 A）

- 两步法：Markdown 渲染**之前**把公式摘成占位符保护（防 marked 咬坏下划线/反斜杠）→ 正文经 Markdown+净化清洗 → 清洗**之后**再用 KaTeX 回填渲染。不扩大清洗器白名单，公式渲染永远发生在净化之后。
- KaTeX 全本地 vendor（0.16.9），不依赖外网 CDN。
- 降级链：KaTeX 缺失 → 公式还原 `$…$` 原文纯文本；单条公式语法错 → 红字显示不中断整段；Markdown 库缺失（练习/记忆页本就不加载）→ 正文纯文本但**公式仍渲染**；公式件自身异常不阻断图文显示。

### 16.4 智能分析公式定界口径（2026-10-13 验收追加，用户裁定方案 A）

**来源**：`services/error_analyze.py`（提示词硬性规则 7 + `_wrap_bare_latex`）、`tools/migrate_bare_latex.py`

- 视觉大模型转录“我的解答（如实转录）”时偶发输出**无定界符的裸 LaTeX**（如 `\Delta=(m-2)^{2}`），而显示端只认带定界公式 → 此类入库内容必须规范化。
- **源头双保险**（与其他可校验业务规则同口径）：提示词硬性规则要求所有字段公式用 `$…$`/`$$…$$` 包裹（公式内容仍逐字如实，仅加定界，规则自身声明与如实转录不冲突）；代码侧 `_wrap_bare_latex` 确定性保底：整行裸 LaTeX（含反斜杠命令/上下标结构/数学命令白名单——命令名须完整结束防前缀误命中）自动包成 `$$…$$` 并保留行首缩进；已带 `$/\(/\[` 定界的行、跨行块内部行（opener 按行内计数跟踪，含行中部 `\[`）、标题/图片引用、Markdown 列表/引用行、Windows 路径类文本、剥除 `{…}` 后公式外中文（含标点）≥2 字的叙述行一律不动（宁漏不错包；评审后收紧口径，2026-10-13）。
- **存量数据**：`tools/migrate_bare_latex.py` 三段式迁移（dry-run 清单 → 逐类抽样核 OLD/NEW → 备份原值后 --apply）；包裹幂等，重跑不二次包。
- 包裹只加定界符不改公式内容，与“如实转录”规则（15.3）不冲突。

### 16.5 公式定界符落库兜底（2026-10-15，用户裁定 A+B）

**来源**：`knowledge_management.py`（`_wrap_math_safe` + 4 个落库入口）、`tools/migrate_bare_latex.py`、`tools/fix_error_1253_delims.py`

- **堵源头（B）**：题干/正确答案/解析三个展示字段在**所有入库路径**落库前统一过 `_wrap_math_safe`（复用 16.4 同一 `_wrap_bare_latex` 实现，幂等）：练习流水入池、手动录题、错题编辑、收藏保存。不依赖上游（LLM/人工粘贴/照片转录）自觉。
- **纪律不变**：用户原始作答（user_answer）一律不碰（如实留原文）；兜底异常不阻断落库，但留 `math_wrap_failed` 日志防静默失效；None/空串语义（字段不动）原样保持。
- **能力边界（诚实口径）**：兜底只处理「整行裸 LaTeX」；中英混合叙述行（如「Δ=(n-4)^2≥0。方程可化为…」）按保守判定刻意不包——这类内容需靠智能分析链路（提示词强制 $）或人工编辑加定界，否则保持纯文本显示。
- **纯数字不进公式**：`$4$` 这类「$ 后紧跟数字」写法会被 16.1 货币防误判规则丢弃、显示露出生文本——规范化数据时纯数字保持裸文本写法（#1253 二修实测教训）。
- **存量（A）**：`migrate_bare_latex.py` 覆盖范围补上收藏表题干（与错题同题干聚合键同口径）；混合叙述行个案（错题 #1253）用 `fix_error_1253_delims.py` 按语义手工分段加定界（备份+同题干整组同步+事务内回读断言）。

## 十九、知识点→微课生成（S1 一期 + 二期交互仿真/语音旁白 + 四期讲解页课堂化，2026-10-30/11-03）

**来源**：`routes_micro_course.py`、`services/micro_course.py`、`static/js/pm_pages.js`（bootMicroCourse 段）、`templates/pages/micro_course.html`、`database/schema_postgres.py`（micro_courses/micro_scenes）

### 19.1 一期规则（生成链路与状态机）

- **入口两个**：知识点详情页「重讲这个知识点」；薄弱点报告脑图红色薄弱节点「讲这个薄弱点」（须有错题证据，无 kp 时按错题证据反查锚定）。发起前积分预估弹窗先行（按 6 页展示，实际 3~8 页）。
- **两阶段生成、逐页增量落库**：大纲 1 次 LLM → 逐页每页 1 次；每页完成即写库，前端 3s 轮询直接读库（不依赖内存任务表，抗重启）。页面五型：explain/example/quiz/interactive/summary。
- **失败绝不重发**：单页失败/校验非法 → 标 failed 留原因；积分不足 → 该页起余页截断标 failed。在飞去重（应用层预检+DB 部分唯一索引）。单页重生成仅用户主动触发，双重乐观锁。
- **中断恢复**：重启钩子把在飞课非终态页全部标 failed，课程状态「收敛+残页清扫」成对执行。生成中不可删除；删除为整课物理删除。
- **随堂题闭环**：quiz 页作答走公共引擎 pmPractice + submitPointPractice——判分/错题入池/FSRS 与既有练习同链。

### 19.2 二期：交互仿真（实验页）

- **大纲可含 0~1 页 interactive**（超出自动降级为 explain 并留 outline_downgrade 日志）；页内容为自包含 HTML（内联脚本/样式，上限 12000 字）+ 标题 + 讲稿。（**七期更新**：interactive 改为每课固定 1 页且正文翻开时才生成，见 19.9；降级纪律不变）
- **沙箱铁律**：前端以 `iframe srcdoc + sandbox="allow-scripts"`（绝不加 allow-same-origin）+ `referrerpolicy=no-referrer` 渲染；宿主注入 shim（报错/高度上报），父层消息三重校验（节点活性+来源窗口匹配+消息形状）。外链检测**只警告不置败**：done + error_note 警示文案，页面照常可看。
- **轮询不清零**：scene 区指纹（seq:status:内容长度:内容前24字）未变时复用原 DOM 节点，实验操作状态与朗读不被轮询重建打断。

### 19.3 二期：语音旁白（浏览器原生 TTS）

- **每页必带讲稿**（narration，清洗后 ≤600 字）；quiz 页契约升级为 `{narration, questions}` 对象（断档升级，存量 0 行）。
- 朗读条：朗读本页/停止/语速（0.8x/1x/1.25x 循环）/自动朗读开关（默认桌面开、触屏关，存 localStorage）；分句 ≤80 字，优先中文音色，无中文语音仅提示不判死。
- **防竞态口径**：切页/离开即 stopSpeak（代数令牌使旧回调失效）；主动停过的页不被自动朗读重入（stoppedKey）；同页内容未变不重发（朗读键去重）；Chrome 长句 10s 保活 ping。零外传、零成本（不经服务端）。

### 19.4 二期：LLM 超时口径

- 微课两处生成调用（大纲/页面）超时 **180s**（实验页实测 67~87s，60s 必挂）；LLM 工厂全链支持可选 timeout 透传，**不传则各 provider 用原默认值**，其他业务零变化。

### 19.5 三期：入口管理（知识点↔微课双向关联）

- **知识点页历史露出**：该知识点已有微课时，「重讲这个知识点」按钮文案变「（已有 N 门）」，右侧露出「微课历史」chip；展开后每行状态徽标+课名+页进度+相对时间，点击直达该微课；无历史时 chip 隐藏与旧版一致。计数含生成中/失败课（徽标区分状态）。
- **预估弹窗历史行**：有历史时弹窗显示「已生成过 N 门，最新：xxx（状态）」+「打开最新一课」；派发「开始生成」期间取消/打开旧课按钮同步锁定防回包劫持导航。
- **列表反向直达**：「我的微课」卡片显示锚定知识点名徽标，点击跳回知识点详情页（双向入口闭环）。
- **锚定口径**：历史归属以创建时写入的 `source_ref.anchor_kp_id` 为准（与 create 同经 `_resolve_anchor_kp`，薄弱点入口生成的课按错题证据反查锚定归位）；存量无锚旧课不入历史（预期限制）。新端点 `GET /api/micro-course/history`（kp_id 或 error_ids 二选一 ≤60），扫描上限 500 门；历史为增强项：拉取失败一律静默，绝不阻塞生成主流程。
- **直达旗标契约**：知识点→微课用 `pm_pending_course`，列表→知识点用 `pm_pending_point`（10s 过期，消费即清+幂等）。

### 19.6 四期：讲解页课堂化升级（A1 聚光灯 + A2 交互图解）

- **A1 聚光灯逐段播放（纯前端，零契约改动，存量课全生效）**：讲解/例题/小结页正文按 markdown 顶层结构切成块序列（`splitMdBlocks`：标题/段落/连续列表/表格/引用各成一块，代码围栏与表格内空行不切、缩进续行并入）。头部朗读条旁「逐段播放」按钮开启后：非当前块加 `mc-spot-dim`（半透明+轻模糊）淡出，当前块 `mc-spot-lit` 点亮（不透明+左侧主色竖条+缓慢 scrollIntoView 跟随）。有朗读时讲稿按句推进、聚光灯按 `floor(句序*块数/总句数)` 比例映射；无朗读按 2.5s/块定时推进。控件：播放/暂停、上/下一段手动跳块、退出恢复全量。切页 `spotStop` 归零、挂 `tts.gen` 代数令牌防串页、轮询重建后按块索引重放 dim 态。新 Tailwind 类需 `build:css` 重建。
- **A2 交互图解（生成链路，向后兼容）**：explain 节可带可选布尔 `has_widget`（prompt：仅当「动手调参看变化」显著优于纯文字才标，全课至多 1 页）；`validate_outline` 归一——非 explain 恒 False、超额降级 False（不整单作废，沿二期降级纪律）。命中页正文调用后**追加一次独立 LLM 调用**（scene="微课图解生成"，prompt 与 interactive 共用硬性规则常量 `_HTML_HARD_RULES_CORE` 防漂移）产出 `{"html"}`，校验复用 `MAX_HTML_LEN=12000`+外链只警告。
- **widget 失败语义**：图解调用失败/超时/非法/积分不足（含 `InsufficientCreditsError`）全部**内层消化** → `content["widget"]=None` + `error_note` 留痕，该页正文照旧 done，**绝不置败整页或截断整课**；积分走 `_call_billed` 正常计量。
- **存储与渲染**：content_json 增可选 `widget` 字段（无 schema 变更，旧课无字段 falsy 兼容，regenerate 自动生效）。前端 explain 块序列中 widget iframe 插正文第 2 块后，复用二期 `simDoc` 沙箱管线（`sandbox="allow-scripts"` 永不 allow-same-origin、`referrerpolicy="no-referrer"`、`esc()` 进 srcdoc、高度自适应）；`mcSimHook` 从单帧扩为遍历 `[data-sim-frame]` 按 `e.source===frame.contentWindow` 匹配（实验页+widget 两帧共存），下限按 `data-widget-frame` 区分 240/420。
- **成本口径**：`estimate_credits(page_count, widget_count=0)`，calls = 1 + 页数 + 图解数；estimate/create 端点按 `estimate_credits(_EST_PAGES, 1)` 折算，弹窗仍只报积分。存量课无图解（不重生成不补），A1 聚光灯对存量课直接生效。

### 19.7 五期：讲解页重做——PPT 式分步动画课堂（canvas + steps，取代 19.6 的 A1/A2 主体验定位）

- **新契约（explain/example，一次 LLM 调用产出）**：`{title, canvas_html, steps:[{caption≤40字, narration 30~120字}]×5~8}`——画面为主体（自包含动画舞台，与实验页同自由度同沙箱），页面文字只留字幕级注解；例题页题干并入舞台第 0 步（不再有单独 problem_md 文字区）。
- **同步协议（声画同源，根除句→块比例映射错位）**：宿主向舞台 iframe `postMessage({t:'mc-step', i, n, caption})`；服务端 `_STEP_STAGE_RULES` 与前端播放器双侧同口径（改一侧必改另一侧）；每步 narration 整条一个 utterance 不再切句，onend/onerror→推下一步；念的和亮由同一 step 序号驱动。
- **播放器状态机**：`cp={i,playing,gen,key,stoppedKey}`；代数守卫覆盖**所有异步入口**（cpSpeak 入口+onend 都查，评审 M-1）；600ms 补发消息**调用时冻结值**不读 live 状态（评审 M-3）；场景指纹 `cpSceneKey=key:seq:updated_time:steps.length`，**detail 端点必须下发 updated_time** 否则同步骤数重生成不重置播放态（评审 M-2）；轮询重建按当前步重放；手动暂停记 stoppedKey 防自动重发；跳步任意序同步推舞台+重读。
- **校验口径**：canvas 必填 ≤MAX_HTML_LEN；steps 脏步（非对象/空 narration）跳过不作废、空 caption 补「第 N 步」、>MAX_STEPS(8) 截断、有效步 <MIN_STEPS(3) 才抛 ValueError 置该页 failed（沿 interactive「非法即败、绝不重发」纪律）；外链只警告进 error_note。
- **A2 widget 链路退役**：大纲 prompt 删 has_widget 规则；`build_widget_prompt`/`validate_widget_html` 已删；旧大纲残留 has_widget 静默丢弃；`_gen_one_scene` 无追加调用；前端仅保留存量 `content.widget` 渲染。`estimate_credits(page_count)` 单参数、calls=1+N、tokens_per_call=13000。
- **超时与时长**：explain/example 正文调用 timeout **300s**（单输出 ~13k 字，实测 145~162s），其余页型 180s；单页约 1.5~3 分钟、整课 8~15 分钟；explain/example 成本约 ×1.5~2（token 实计量）。
- **兼容与降级**：存量 body_md 页原样走四期聚光灯兜底（A1 代码保留，不再宣传为主体验）；summary/quiz/interactive 不动；旧课不会自动画布化，**重新生成单页即画布化**；画布页 content 无页级 narration → 旧朗读条天然不渲染（无双控件）。

### 19.8 六期：错题深度讲解 + 相关错题直达筛选（同表双轨，零新表零新播放页）

- **错题讲解课形态**：错题行「讲解错题」→ 确认弹窗（预估+该题历史查重）→ 生成 3~5 页小型微课（**七期改 4~6 页**，固定互动页另算，见 19.9）→ 直达既有播放器。存 `micro_courses`/`micro_scenes`，`source_type='error'`、`source_ref={anchor_kp_id, error_ids, error_explain:true}`；生成两阶段/进度轮询/画布课堂/单页重生成全部直用五期管线；有锚课所有页行绑锚定 kp（quiz 判分入池依据），无锚课（独立错题）页行 kp_id=NULL、判分走错题轨，见下方参数校验条。
- **大纲硬结构（prompt 写死）**：①至少 1 页 explain 拆「这道题围绕哪些知识点」；②至少 1 页 explain 对照「你的作答 vs 正确答案」讲错因（素材必含学生错答原句）；③至多 1 页 example/interactive 巩固（**七期改为：至多 1 页 example，互动页固定另算**）；④必须 1 页 quiz 出 2~3 道变式题。输出 JSON 契约与知识点大纲完全一致，复用 `validate_outline`；新建兄弟 prompt 必须携带「教学大纲」分流词（生产/测试假 LLM 同口径判别）。
- **在飞去重双轨（DB+Python 两层同口径）**：`uq_mcourse_inflight = (user_id, source_type, (CASE WHEN source_type='error' THEN ref->>'error_ids' ELSE ref->>'anchor_kp_id' END)) WHERE status='generating'`（**PG 表达式索引键必须整体括号**）；Python 侧 kp 轨排除 `error_explain` 课、error 轨按 error_id 集合匹配，两轨互不误劫持；撞索引 IntegrityError 回滚后重扫复用。
- **history/estimate 单轨口径**：`history?kp_id` 恒排除错题课，`history?error_id` 只回错题课（查重永不串线）；`estimate?mode=error` 按约 4 页口径折算，积分仍走 `estimate_credits` 逐页计费同口径不单独定价。
- **素材采集纪律**：`_error_explain_pack` 一条 JOIN SQL（**双条件 `pr.user_id = eq.user_id` 纵深防御**）拼题干/选项/你的作答/正确答案/解析/累计答错次数/熟练度；只能请求线程调；单页重生成按 `error_ids[0]` 重跑采集，失败才回退知识点级素材。
- **参数校验**：`error_id` 归属双条件（不存在/跨用户同一文案）；bool 拒绝不得静默混当整数 id；**独立错题（kp NULL，手动录入）同样支持讲解**（用户裁定 2026-11-04 补丁）：无锚合成 kp_row（point_name 空串即形态开关），学科取错题行归属，大纲线索①改为从题干归纳知识点（不引用掌握度），页行 kp_id 落 NULL；**quiz 判分双轨**：有 kp 页行走 practice-submit，无 kp 回落 `error-set-submit` 每题挂源错题 error_id（与举一反三同链路，答对升源行 FSRS）；无锚课重生成若错题素材丢失则拒结（宁拒不空转防烧积分跑题）。
- **相关错题直达**：知识点卡「相关错题」写旗标 `pm_pending_error_filter={kp_id,kp_name,subject,ts}` 跳错题练习页；旗标契约与 `pm_pending_course` 一致：**10s 过期 + 消费即清 + 模块级兜底防 SPA 二次注入闪丢**；错题页消费：学科预选 + 查询串拼 `&kp_id=`（后端参数层筛选，与关键词/分页正交）+ 可移除筛选条「仅看知识点「xxx」[查看全部]」；**旗标学科与实际落地学科不符即清筛选**，手动换学科自动退出筛选态。

### 19.9 七期：每课固定互动页 + 翻开按需生成（用户原创方案，BA 裁定）

- **固定 1 页 interactive**：知识点课与错题讲解课大纲都必须恰好 1 页 interactive（LLM 定位置：相关讲解/例题之后），并输出 `interactive_worthy`（布尔，是否真适合动手探究）+ `interactive_note`（一句话理由，截 60 字）；知识点课仍 3~8 页，错题课机动位改「至多 1 页 example」、页数口径 3~5 → 4~6。
- **占位零消耗（standby）**：创建期 interactive 页直接以新状态 `standby` 落库（content 空、不烧 LLM，status 列无 CHECK 约束免迁移）；Stage2 生成循环跳过该页；课程状态聚合 `_recalc_course_status` **排除 standby**（全 done 即 ready，互动页不拉低课程状态）；启动/残页清扫只动 generating/pending **绝不碰 standby**；页数进度（detail/list/历史子查询）同口径排除 standby。
- **校验器补位保守纪律**：LLM 漏排互动页 → `validate_outline` 末尾自动补 1 页占位，**worthy 强制 false**（违约时其判断不可信，防误烧积分，走手动按钮）；补位页不受 MAX_SECTIONS 复核（8 页满也可补成 9 页）；多页 interactive 保留第一页、其余降级 explain（二期不浪费已扣分纪律沿用）；worthy/note 随 outline_json 落库并从 detail 透传。
- **两轨按需生成（前端）**：worthy=true → 学生翻到该页自动派发 `regenerate-scene`（同屏显示积分提示不拦截；一次性标记防重发，**派发失败回滚标记待快照刷新自然重试，卡上另留兜底按钮防假死**，评审 M-1）；worthy=false → 显示理由 +「生成互动实验」按钮，点击（confirm 后）才生成；复用 regenerate-scene 全套链路（双重乐观锁/素材采集/沙箱渲染），**不建新端点**；页乐观锁白名单扩为 `done/failed/standby`（pending/generating 仍拒，防双跑双扣）。
- **计费口径**：互动页费用按单页现行口径在真正生成时扣；`detail.scene_unit_cost = estimate_scene_cost()`（= 1×13000/换算比例，**不含大纲调用**，非 estimate_credits(1)，评审 N-1）；预估弹窗文案追加「互动实验页翻开时才计费（约 1 页正文的钱），不翻不扣」，`_EST_PAGES` 数值不变（创建期互动页零消耗）。
- **存量课天然不受影响**：旧 outline 无 worthy 字段 → detail 兜底 false；旧课无 standby 页行 → UI 无入口；不回填。
- **准备前置纪律（评审 M-2）**：`regenerate-scene` 易失败的只读准备（大纲解析/取节/素材采集/无锚拒结）全部前置到双重乐观锁之前，锁提交后只剩派发线程，杜绝课程卡 regenerating/页卡 generating 死态。

## 二十、语音黑板讲课连续性（2026-11-09 实弹事故后用户裁定，三道闸门）

背景事故：学生指派知识点「梯度下降」后，老师连写 #5~#9 五张卡不讲解直接结课道别；学生说「继续/没听懂」时老师再无反应——根因是指派素材被一次性消费后永久丢失，且服务端没有任何「写了没讲」的进度概念。

- **知识点素材课内常驻**：网页「AI老师讲」指派仍在首次取料时消费（既有口径不变），但 kp 型指派注入成功后素材全课有效：学生追问「继续/没听懂/再讲一下」时老师重新取料，拿回知识点描述与板面进度接着讲（「续讲」指导语）；知识点被删则常驻自动摘除、回落正常取料流程，绝不把老师往不存在的内容上引；错题新指派覆盖旧知识点语境；擦板不清常驻（与指派同口径）。
- **讲课进度镜**：老师连续写上 ≥2 张卡却一句没讲，之后每次工具返回都拦嘴提醒「先停笔把最近这张讲透」；口径：写卡进「待讲」队列、老师一句口播即清零——「讲到哪写到哪」的正常节奏永不触发；上题一次性铺素材卡、改写卡（=正在重讲）、擦板重开均不计入队列。
- **照板重讲**：状态行除卡号外附带每张卡正文前 10 字摘要（限长 380），学生求重讲时老师能复述板上内容；kp 开讲指导语随带讲课纪律句：「一张卡讲透再写下一张；板上所有卡讲完、学生点头之前，不要结课道别」。
- **写卡留痕**：board_write 落 write 事件日志（uid/卡号/卡型/字数），复盘可直接回答「哪张卡几点写的、写之前讲没讲」。

## 二十一、本机单桥闸门（2026-11-09「双桥抢接入点」事故后裁定）

背景事故：同机第二个服务实例（回归测试遗留、端口 6400）也起了 MCP 桥，与正式实例共用同一个小智接入点；云端下发的消息被两个进程随机拣走，老师会话卡死——学生说话全部上报成功但老师零应答、零工具调用、无任何报错。

- **一台机器只许一个桥**：桥启动前看本机锁文件 `data/xz_mcp_bridge.lock`（记录持有者 pid + 心跳时间）；其他进程持有新鲜心跳（45 秒内）时，本实例拒起桥并在日志记 `bridge_refused`（含持有者 pid）；锁陈旧或无锁则正常起桥并登记。
- **只拦桥、不拦服务**：拒起桥不影响本实例其他功能照常运行；设置页「连接」入口同口径预检——本机他实例已持桥时直接拒连并提示先停掉多余实例，不写入启用状态。
- **心跳与接管**：持有桥的进程周期性刷新心跳；进程死亡后心跳停止，约 45 秒内下一个实例自动接管，无需人工清锁。
- **口径**：凡「一个外部接入点只许一个客户端」的连接，单例约束必须落在本机文件锁级别，进程内约定不算防护。

## 二十二、原理图与语音讲课融合（2026-11-09 用户裁定：方案 A+默认开+「概念讲完就上舞台」）

目标：原理图不再只是独立弹窗，而是课堂资产——指派即预生成，讲完基本概念就在黑板舞台区边讲边推步。

- **指派即自动开工**：网页「AI老师讲」指派成功（知识点型/错题型）即自动后台生成本课原理图舞台，不阻塞指派；生成要几十秒到几分钟，期间老师照常讲课。
- **舞台=黑板画图板位置**：原理图复用既有分步动画舞台链（老师 board_anim_step 逐步推进，字幕+口播稿声画同源，前端舞台自动展示）；弹窗版原理图入口原样保留并存（用户：黑板的可能会擦，弹窗随时可以打开看）。
- **节奏定式**：开讲指导语附「先把基本概念卡讲完 → 舞台就绪提示出现后 board_anim_step(0) 切入 → 每讲一段推一步，照口播稿念」；重讲续讲时舞台若就绪可重新推步。
- **防重与覆写口径**：同源指派在生成中/已就绪时不重开（防重复扣分）；指派改口（换了目标）或上次失败 → 覆写重开，旧结果自动丢弃；并发指派也必须只开工一次（服务端原子去重闸）。
- **擦板不清舞台**：原理图舞台是课级资产，随新指派覆写终结，不随擦板消失（与指派同口径）。
- **静默回落**：素材取不到/积分不足 → 不开工不留痕，讲课链路零影响；生成失败 → 工具返回一次性「[舞台失败]」尾注，老师照现有讲法讲，同源再指派可重开碰运气。
- **画布契约不降级**：原理图产出必须过微课画布页同一校验（分步 3~8 步、字幕≤40、口播≤160、画面≤12000 字、按步消息协议监听在位），不过即判失败，宁失败不将就。
- **口径**：原理图用 html-explainer 方法论生成（模型写画面代码不画像素、一场景一焦点、术语与课程素材严格一致、不虚构）；约束云端老师的确定性信号（就绪/失败尾注）继续做在服务端工具返回里，不靠提示词自觉。

## 二十三、目标导向学习（体系化课程，2026-11-11 落地）

**来源**：`routes_courses.py`、`services/course_service.py`、`database/schema_postgres.py`（learning_goals / course_modules / course_lessons / course_tests / course_attempts 五表）、`templates/pages/learn_goals.html`、`llm_provider_factory.py`（场景白名单）

### 23.1 主流程与课文状态机

- 入口：侧边栏「学 → 目标导向学习」，输入学习目标 → LLM 生成课程结构（模块→课文，学科自动建档）→ 逐课文学习。
- 课文状态机单向推进：`new → pretested（前测判分）→ content_ready（课文落库）→ learned（后练完成）→ done（用户点完成）`，非法跃迁由 `advance_lesson` 统一拒绝。
- **详略判定**：前测得分决定课文模式（`decide_mode`：得分高→concise 精讲版，低→full 完整版；full 版 prompt 携带错题知识点名置顶详讲）。

### 23.2 complete 门禁（用户裁定）

- 标记完成必须同时满足：课文状态为 `learned` **且**存在至少一次课后小练习（postquiz）交卷记录；缺一律 409 拒绝。已 done 的课文重复请求幂等返回。

### 23.3 判分与生成解耦（评审 Major-1 裁定）

- 前测交卷的判分链（course_attempts / practice_records / 错题入池 / FSRS）与课文生成**解耦**：课文生成失败不回滚判分，成绩与 pretested 状态照常落库。
- 失败后走 `POST .../generate` **补生成**：不重复判分、不重烧出题、**不计重生成上限**；已有课文再补生成 400（要换版本须走重生成）。
- **重生成上限 3 次**：`POST .../regenerate` 每成功一次 regen_count +1，达 3 次拒绝；未生成过课文的课文拒绝重生成。

### 23.4 知识点提取确认（Task 12，复用既有链路）

- `POST .../extract` 只返回候选（含相似度匹配信息）**不入库**；入库确认复用既有 `POST /api/knowledge/confirm` 链路，不新建入库通道。
- **课程场景提取交互（用户裁定）**：候选默认全勾选，确认仅走「新建入库」路径（课程课文是新内容，不做 merge 候选操作）。

### 23.5 删除规则

- **删目标=级联五表**：attempts/tests 按归属删，再 lessons→modules→goal；**practice_records / error_questions 为独立学习资产，随目标删除不动**（Spec §5）。
- **学科删除防护**（Spec §9）：删除学科前检查该学科下是否存在未完成（status != done）的课程课文，存在则拒绝删除，防止学习中的课程悬空。

### 23.6 课程 LLM 调用口径

- 课程 7 场景（生成课程结构/课程前测出题/课程后练出题/模块考试出题/生成课程课文/课程扩展生成/课内AI问答）+ 课文追问讲解（2026-11-12 实弹后补入，入单时漏追加导致用户自备 GLM 追问默认思考撞 120s 超时回落系统）全部列入思考关闭白名单 `THINKING_OFF_SCENES`（结构化产出无需草稿推理，且经隧道端点时思考默认开会撞 Cloudflare ~100s 空闲掉线）。

### 23.8 模块考结果生效规则（用户裁定 2026-11-12：薄弱点驱动后续生成）

- **每次模块考必留历史**：交卷即追加 course_attempts 行（kind=moduleexam），含得分、时间、逐题过程明细（题干/我的选项/正确项/知识点/解析）；在「成绩历史」Tab 按目标展示，点行展开错题清单。错题同步进练习记录与错题本（与前测/后练同一判分链）。
- **薄弱点驱动生成**（本次裁定新增）：同目标下所有模块考，每个题包取**最近一次**作答的答错知识点，作为薄弱点合并进课文生成 prompt（与前测错题合并去重，前测在前，模块考侧上限 10 个）；三处生成入口同一口径：前测交卷即生成、重生成、补生成。
- **状态契约不变**：模块考仍不改变课文状态、done 前可反复考（Spec §7）；裁定只增加“结果影响后续课文内容”，未引入达标门槛/重学触发。
- 旧版口径冲突说明：此前“模块考只作参考”指状态机不推进，与“结果驱动生成”不矛盾，以本节为准。

### 23.9 题包提示与「我不会」规则（2026-11-12 用户裁定：前测/后练/模块考三处共用组件一次覆盖）

- **查看提示（hint）**：每题下方隐藏区，展开后解释题干关键术语 + 给思考方向，**不剧透答案**；hint 由出题 LLM 一次生成（三种 `_TEST_PROMPTS` 各加第 4 条要求，零额外调用），prompt 纪律「严禁指出或暗示哪个选项正确，严禁写入能推出答案的结论」；explanation（含答案讲解）仍只在判分后回传，不作提示复用。
- **hint 是软字段**：`validate_questions` 缺失/非法一律降空串（超 `_Q_HINT_MAX=300` 截断），**整包不因缺 hint 拒收**（模型漏写不报废重试成本，区别于 stem/options 硬闸）；前端 `q.hint` 空则静默不渲染提示按钮（旧题包零成本降级）；`_pub_questions` 对外透传 hint（只帮读懂题目不含答案，下发安全）。
- **「我不会」= 答案协议 -1**：前端共用 `renderQuiz` 每题注入 value=-1 radio（虚线分隔，不污染 4 选项 LLM 契约）；`grade_pack` 校验放开 `a == -1 or 0 <= a <= 3`（bool/越界仍拒）；选它=放弃作答，**按错题走同一链路**（FSRS 最低档/入薄弱点/入错题本），不给跳过豁免；全不会→score 0→full 模式合理。
- **负下标雷修复**：流水/错题本的「我的作答」`ans < 0` 时记文本「我不会」（Python `opts[-1]` 会静默取末选项造成假作答）；`per_question.user_answer` 保持数值 -1（可 JSON 落库回读），成绩历史/结果页只展示题干+对错不受影响。

## 二十四、课文图文结合规则（2026-11-12 用户裁定 A 方案：思路图自动画 + 原理图/实验按需展示位）

**来源**：`services/course_service.py`（生成 prompt + MD_MAX）、`services/board_explainer.py`（课文级视觉产物链）、`routes_courses.py`（visual 两端点）、`templates/pages/learn_goals.html`（mermaid 渲染 + 两展示位）

### 24.1 思路图自动画（进课文正文，零额外 LLM 成本）

- **配图纪律进生成 prompt**：凡有流程/结构/因果/对比/时间线/知识层次的段落，必须配 1~3 个 mermaid 围栏块（`graph TD`/`graph LR`/`sequenceDiagram` 为主），位置紧跟所配段落。
- **写图纪律与黑板闸门同源**（防渲染失败）：首行必须图型声明；节点文字简短中文；块内禁用 `$`、`<>`、`click`、`%%{init}%%`；每图不超过 12 个节点；subgraph 标题带空格或括号必须用括号式 `subgraph sg1["标题"]`，禁裸标题（追问 mermaid 实弹轮 2026-11-12 追加：裸标题带全角括号 Lexical error 整图掉图）。
- **前端纠偏 sanitizer**（同轮追加）：渲染前 `cgMmSanitize` 把裸标题带空格/括号的 subgraph 行确定性改写为括号式（已合规不动），存量产物免重生成直接可渲；其余未知语法错仍走降级保留源码纪律。
- **MD_MAX 8000→12000**：mermaid 块占正文字数，防合法带图课文被长度校验误杀；`validate_lesson_md` 剥外层围栏逻辑不动（内层 ```mermaid 围栏本就不受影响）。
- **渲染链**：课文页引入 vendor mermaid 10.6.1（securityLevel strict，与黑板同口径），`pre code.language-mermaid` 串行渲染成 SVG 就地替换；**单图失败降级保留原代码块**（`data-mm-fail`），不炸整篇课文；公式管线（MdRender.extract）的围栏保护天然护住 mermaid 块不被 KaTeX 抽取误咬，hljs 跳过 language-mermaid。
- 旧课文不强刷：点「重新生成」自然带图。

### 24.2 原理图/交互实验 = 课级按需产物（不新建生成链路）

- 课文正文顶部两个常驻展示位「原理图」「交互实验」：进页 `GET /api/course/lessons/<lid>/visual` 查两类产物状态（纯读库零外呼）；**有 done 产物直接内嵌显示（sandbox iframe srcdoc，零成本）**，没有才显示生成按钮（`POST /api/course/lessons/<lid>/visual/<kind>`，一次 LLM，之后永远复用）。
- **扩展既有链**：`board_explainer.start_for_lesson(uid, lid, kind, refresh)`，素材=课文标题+概要+正文（不再依赖黑板当前课堂快照）；输出契约、校验（`validate_scene_content("interactive")`）、外链警告、计费、作业轮询（复用 `GET /api/board/explain/<job_id>`）全部沿用黑板原理图纪律——「相似业务相似实现」。
- **键隔离**：产物缓存走 principle_cache `(uid, kind="course_lesson", ref=f"{lid}:{kind}")`，与黑板课级产物（kind="lesson"）完全隔离互不劫持；黑板 `start()`/`running_job()` 的在飞去重只认不带 `_ref` 的自家作业（评审 Major-1：防课文页在飞时黑板复用拿到基于课文正文而非板书快照的产物）。
- **计费口径**（用户裁定 A 方案「不烧没用的钱」）：done 产物秒回 `reused="cache"` 零外呼；同槽位在飞去重防双开双扣分；「深度重画」走 refresh（开思考、seq+1 新版本）；正文未生成拒收不扣分；生成失败只置 failed 不自动重发（防双扣）。
- 生成后关键节点写 `debug_trace.jsonl`；failed 展示错误文案，课文正文不受影响。

## 二十五、课文追问笔记树（2026-11-12 用户裁定：框选追问 + 服务端笔记本 + 全屏沉浸阅读）

**来源**：`database/schema_postgres.py`（lesson_notes 表）、`routes_courses.py`（notes 三端点）、`services/course_service.py`（generate_followup_chat）、`routes_board.py` + `services/lecture_board.py`（assign kind=text）、`templates/pages/learn_goals.html`（阅读步全套）

### 25.1 存储与端点（学习笔记本定位，跨会话不丢）

- 新表 `lesson_notes`：id/user_id/lesson_id/parent_id（NULL=挂课文锚点，非NULL=追问的追问，无限嵌套）/anchor_text/question/answer_md/created_time；索引 `(lesson_id, parent_id)`；前端组树（GET 平铺列表，后端不做嵌套查询）。
- 三端点鉴权/归属同课内问答现例：`GET .../lessons/<lid>/notes`、`POST .../lessons/<lid>/notes`（body `{parent_id?, anchor_text, question}`，生成回答落库返回节点）、`PUT /api/course/notes/<nid>`（仅本人节点，只可改 question/answer_md，anchor_text 创建后不可改——锚跟问题走）。DELETE 本期不做（笔记本只增改）。
- 硬限口径：锚定原文 ≤600 字（超限 400）、question 超 2000 静默截断、回答落库前统一截 `_NOTE_ANSWER_MAX=20000`（与 PUT 编辑同口径，防超长答案存进去后编辑保存永远 400，评审 Warn-3）、单课 500 条上限（「查上限→插入」在落库事务内用 `pg_advisory_xact_lock(lid)` 串行化，防并发双过白扣积分，评审 Warn-4）；父链上溯取最近 3 层问答作上下文（硬顶 50 步 + seen 集双保险防环）。
- 空回答即失败：502 不落脏行（同课内问答口径）；积分不足 402 透传充值引导。

### 25.2 锚定策略（文本内容锚定，不改 content_md）

- 节点只存 anchor_text；渲染后 TreeWalker 拼全文本 indexOf 定位、splitText 包裹 `<span class="cg-anchor">`（下划线可点击，点击 toggle 整组子章节收起/展开）。
- 锚失效（课文重生成/变更）→ 该节点降级右栏「未定位笔记」索引，内容仍可见可编辑，**不静默丢**。
- 重锚前必须清旧 `.cg-anchor-group`（全量重锚幂等，防子章节叠加重复，评审轮自查出的真雷）。

### 25.3 追问生成 prompt 纪律（图文并茂）

- `generate_followup_chat`：课文全文（截 6000）+ 框选原文「」+ 父链问答（各截 800）作上下文；纪律「尽可能图文并茂」——鼓励 mermaid 围栏思路图/流程、表格对照、$公式$；回答走课文同一 MD+mermaid+KaTeX 管线渲染。
- 追问 prompt 含与课文同源的写图纪律块（首行图型声明、节点短中文、禁 $/<>/click/%%{init}、subgraph 括号式标题、≤12 节点；追问 mermaid 实弹轮 2026-11-12 补齐，此前只鼓「尽可能画」未管「怎么画不炸」）。

### 25.4 「请老师讲课」= assign kind=text（扩展现有指派链，不另开链路）

- `POST /api/board/assign` 加 `kind='text'`（body `{kind:'text', text}`，≤600 字）：target_id 用 **md5 前 6 字节稳定哈希**（built-in `hash()` 有进程盐跨重启不稳，评审轮修复），label 走 `_assign_label` 截断；`raw_text` 随指派存内存（TTL 600s 分钟级短命语义）。
- 取料注入指导语与 error/kp 同机制：「📌网页指定讲解『选中原文』，请围绕这段内容讲课」，一次性消费按 ts 认账；`set_assign` 入口 `_ASSIGN_KINDS` 白名单生效（绕过路由直调非法 kind 抛 ValueError，评审 Suggest-5）。

### 25.5 阅读步形态（用户裁定）

- 阅读步全屏沉浸（fixed 铺满+遮罩隐）；前测/后练/模块考仍用原 860px 抽屉。
- 退出入口（用户反馈「没有退出的地方」后补，2026-11-12）：阅读步右上角显式「← 退出阅读」按钮（仅阅读步可见），Esc 同效；弹层（追问/编辑/查看等 z-50）开着时 Esc 不抢事件退出抽屉。
- 右上旧问答输入框移除（后端 `POST .../chat` 保留不动，仅前端入口删）；框选浮动菜单「追问 / 请老师讲课」替代。
