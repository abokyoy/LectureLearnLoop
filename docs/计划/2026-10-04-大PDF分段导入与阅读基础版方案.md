# 大 PDF 分段导入与阅读基础版 方案（2026-10-04）

> 状态：待审核。审核通过并经用户确认理解后进入开发。
> 范围裁定：本期做「分段转换 + PDF viewer 基础版（含段状态工具栏）」；PDF 圈画标注为二期，本方案只预留数据结构挂点，不实现。

## 1. 背景与目标

用户需要"学一本书"：400+ 页 PDF 一次性转单个 MD 存在三个实测确认的问题：

1. 扫描件走 PaddleOCR 整本转换必超 20 分钟轮询上限（`import_service.POLL_TIMEOUT_S`），且耗额度；
2. 单个 20~40 万字符 MD 超出现有"一次 LLM 调用"的知识点提取输入上限；
3. MD 阅读丢失原书版面，无法作为读书界面。

实测数据（本机真实样本，pypdf 文本层全文提取）：547 页 / 133MB → 23.3s；492 页 / 61MB → 11.4s。
结论：**文本层大 PDF 转换本身不是瓶颈，分段的主因是下游消费（提取/阅读/控制 OCR 成本）**。

目标：导入 PDF 时按页数与文本层情况分流，大 PDF 自动落"书籍文件夹"，按固定 20 页桶生成段 MD；提供 PDF 原件 viewer 与段转换状态面板，扫描件可勾选未转段逐段转换。

## 3. 总体架构

```
上传 PDF（routes_bridge./api/vault/import 改造）
  └─ pypdf 读页数 + 采样判文本层（≤6 页逐页计数，≥4 页有文本才判文本层）
       ├─ ≤20 页 ──────────────→ 现状单文件流程（小文件豁免：≤20页 或 ≤60页且≤10MB，不动）
       ├─ >20 页 & 文本层 ─→ 建书籍文件夹 → 预生成段占位 → 单整书 worker 串行逐段本地转换
       └─ >20 页 & 扫描件 ─→ 建书籍文件夹 → 预生成段占位 → 等待前端逐段手动触发
                                             │
前端（online_course_notes.html）             │
  ├─ 点任意 .pdf（原件或附件/内）→ 预览区 pdf.js viewer（新流式端点，支持 Range）
  └─ viewer 工具栏「分段转换」面板（仅书籍） ──────────┘
        段状态网格（已转/转换中/失败/未转）→ 勾选未转段 → 消耗确认框 → POST /api/import/pdf/segments/convert
（分流门槛与豁免阈值 60 页 / 10MB 实现时定义为 config 常量）
```

复用现有资产（架构收敛，不新建任务系统）：
- 任务模型：`import_tasks` 表 + worker 线程模式 + `recover_tasks_on_startup`（段等待态由文件系统承载，不新增持久状态机，审核 P1-5）；
- 转换器：`extract_pdf_text_layer`（加页码范围参数）、`_jsonl_to_markdown`、Paddle 客户端；
- 产物规范：附件/ 目录、`img_<task>_<页>_<序>` 命名、`upsert_note_content` 入库、笔记树自动可见；
- 清洗管线：`postprocess_pdf_text_layer` 三段清洗对每段文本各自生效。

## 4. 后端设计

### 4.1 文件夹与产物结构

以《书》400 页为例，落点沿用现有落点规则（未选中→vault 根；选中文件夹→其下；选中文件→其所在文件夹）：

```
<落点>/书/                ← 书籍文件夹（名=PDF 主名，重名加 _2/_3，沿用 uniquify_name）
├── 书.pdf                ← 原件（不再放附件/，这是本期与现状的差异）
├── 书·0001-0020.md       ← 段文件，导入时全部预生成空占位（文件名冻结）
├── 书·0021-0040.md
├── …                     ← 共 ceil(总页数/20) 个，页码 4 位补零保证字典序=页序
└── 附件/                 ← 段内嵌图切图，命名沿用 img_<task_id>_<页>_<序>
```

- 段 MD 首行 `# 书 (0021-0040页)`，正文每页以锚点注释分节（见 4.4）；
- 空段（0 字节）不进笔记树：笔记树两个文件扫描端点（**/api/vault/tree-nested**（前端主用，api.js getFileStructure）、/api/vault/tree）只隐藏**书籍文件夹内**匹配段命名模式（`·NNNN-NNNN.md` 且 0 字节）的文件，不做全局空 MD 过滤（审核 P2-11：避免连带改变 ≤20 页占位等既有行为；复审 P2-A：端点名写实）；
- 原件 PDF（书籍在文件夹根，小文件在附件/）**均不**作为笔记出现；但两个位置都提供 viewer 可点开入口（确认4=B）。

### 4.2 导入接口改造（routes_bridge.py）

`/api/vault/import` 现有 PDF 分支拆为三态（≤20 页分支代码路径零改动）：

1. 上传落盘后 pypdf 打开取总页数 + 文件字节大小；`len(reader.pages)` 秒级。**分流门槛（确认1=B）**：若 `页数 ≤ 20` 或 `（页数 ≤ 60 且 体积 ≤ 10MB）` → 走现状单文件分支（小文件豁免）；否则进入书籍文件夹分支。页数是分段主驱动，体积≤10MB 不能单独免除分段（防纯文字大书漏判）；
2. 文本层采样判定：取前 3、中间 3、后 3 页（去重）共 ≤6 页逐页 `extract_text` 计数（判据见第 4 条）。理由：避免 547 页全量探测的 20s 等待，混合 PDF 罕见采样足够；
3. 建文件夹 → `uniquify_name` 定名 → 原件写入 → 预生成全部段空占位 → 登记**主任务**（kind=`pdf_book`，一条）：记录原件路径、总页数、段数、`is_text_layer`；**不为每个段预建任务行**——段状态权威 = 文件系统（非空=已转、0字节=待转）+ 活跃 convert 任务行（审核 P1-5/P2-11）：
   - 文本层→投递一个**书籍 worker 任务**（新 kind 行 `pdf_segment`，parent=主任务，seg_from/seg_to 留空表示整书），worker 内部**串行**逐段提取→§4.4 写回→更新主任务 progress_json；单线程打开一次原件，避免 20 线程并发 `PdfReader` 200MB 文件（审核 P1-4）；
   - 扫描件→不投递任何任务，等待前端逐段手动触发（每段转换时动态建 `convert_segment` 任务行）；
   - 主任务状态聚合（审核 P1-3）：每段终态后回写 progress_json（done=已终态段数，total=段数）；文本层全部段终态→全成功置 done、有 failed 置 done+error="部分段失败"；**扫描件主任务占位建好即置 done**，同时初始化 progress_json=`{done:0, total:ceil(页数/20), is_text_layer:false}`，后续每次 convert_segment 终态回写 done 计数（不改 done 状态）（复审 P2-G）；前端收到 done 后对书籍改走 `/api/import/pdf/book` 专用轮询，不走通用"转换中/400tick 超时"状态机；
4. 文本层采样判据改**逐页判定**（审核 P1-7）：6 个采样页（前3/中3/后3去重）中 **≥4 页各自 ≥300 字符** 才判文本层，防"扫描书+文字版权页/目录页"误判。

### 4.3 转换 worker 改造（import_service.py）

- `extract_pdf_text_layer(pdf_path, att_dir, task_id, page_from, page_to)`：新增页码范围参数，循环 `range(page_from, page_to+1)`（pypdf 支持按索引取页，无需改写 PDF）；**段任务路径输出必须逐页拼 `<!-- llpage:N -->`（N=page_from+局部页序）**；返回契约改为 `(text_with_anchors, non_empty_page_count)` 或等价结构，供覆盖率判定；≤20 页旧调用点只消费文本部分且不开锚点开关，产物保持现状零 diff（复审 P2-C/D）；
- 段写回统一复用 `sync_note_content`（现 worker 已是"写文件+入库"双落，不新增 DB 写路径）；
- 扫描件段转换：pypdf `PdfWriter.append(reader, pg_range)` 切出段临时 PDF（落系统 temp，提交后删除）→ 走现有 `submit_job → 轮询 → _jsonl_to_markdown` 全链路；`POLL_TIMEOUT_S` 对 20 页段维持 20 分钟不变；
- **OCR 产物注入页锚点**（审核 P1-6）：`_jsonl_to_markdown` 增加按 `layoutParsingResults` 逐页切块并注入 `<!-- llpage:seg_from+局部页序 -->`，使 OCR 段与文本层段同构，裁定#6 的覆盖/重转/二期标注坐标对两路径一致生效（仅段任务路径启用注入，≤20 页整文件转换的产物形态保持现状零 diff）；
- 并发与队列（审核 P1-4，不改现有 `_SEM` 语义）：本地文本层提取不占 `_SEM`（现状），但书籍整书 worker 内部串行；手动段任务 kind=`convert_segment`——本地重转不占 `_SEM`、OCR 提交进 `with _SEM`（与其他扫描导入公平排队，上限 20min/段）；
- 段完成判定加**覆盖率门槛**（审核 P1-7）：段内"提取后非空文本页数 / 请求页数 ≥ 50%"才置 done，不足置 failed（面板可见、可重转/force_ocr），杜绝"非空但全是页码垃圾"的假绿；失败保留段文件旧内容（不 unlink）。

### 4.4 页锚点与段内合并算法

段 MD 正文结构（锚点为 HTML 注释，渲染不可见，marked 输出保留）：

```markdown
# 书 (0021-0040页)

<!-- llpage:22 -->
（第 22 页内容…含 ![图片](附件/img_…) 引用）

<!-- llpage:25 -->
（第 25 页内容…）
```

写入流程（段任务成功后，持段文件锁，`threading.Lock` 按段文件路径字典管理）；**转换中途异常不留半截文件**：段任务一律先写 `.tmp` 再 `os.replace` 原子替换（复审 P2-F，杜绝"非空但残缺"的假绿）：
1. 读现有段文件 → 按 `<!-- llpage:(\d+) -->` 切出 {页码: 内容} 字典；
2. 本次新转页逐页覆盖字典中同名键（重转覆盖规则）；**新转页清洗后为空 → 显式覆盖为空节**（审核 P2-9，防止重转修不掉脏页）；正文意外含同字面 `<!-- llpage:N -->` 概率极低，接受风险并记 §10；
3. 按页码升序重组写回 → 复用 `sync_note_content` 写文件+入库。

段待转状态由**文件系统承载**（0 字节=待转），表中不设 pending_manual 状态；**扫描件**每段实际转换才建任务行（kind=`convert_segment`，parent=主任务，seg_from/seg_to 记录范围）；文本层则由**一个** `pdf_segment` 整书任务（seg_from=seg_to=0）串行覆盖全部段，不逐段建行（复审 P2-B 与 §4.2 对齐）。任务行终态后按 30 天自然清理，不影响书籍元数据（主任务行永久保留）。

### 4.5 数据表变更（schema_import.py）

- `import_tasks` 追加 **3 列**（均 TEXT/INT NOT NULL DEFAULT，沿用原设计）：`parent_task_id`（段任务→主任务关联，主任务为空）、`seg_from`、`seg_to`（起止物理页，1-based 闭区间，整书任务=0）。语义约定：`pdf_book` 行记原件路径于 result_pdf、总页数/段数/is_text_layer 记于 progress_json；`pdf_segment`（整书串行）与 `convert_segment`（手动段）行用 seg_from/seg_to 定位；
- 迁移双方言写实：新库 CREATE TABLE 本体同步加 3 列；存量库 PG 用 `ADD COLUMN IF NOT EXISTS`，**SQLite 用裸 ALTER + try/except 吞 duplicate column**（与 knowledge_management.py 存量幂等模式一致，SQLite 不支持 IF NOT EXISTS）；
- **30 天清理保护**（审核 P1-5）：`recover_tasks_on_startup` 的 DELETE 加 `AND NOT (kind = 'pdf_book' OR error != '')`——主任务行作为书籍永久元数据；**带 error 的 failed 段行也保留**，否则清理后"非空但残缺"的段失去失败信号变假绿（复审 P2-F）；正常终态段行被清理无害（状态权威在文件系统，book 接口不依赖段任务历史行）。

### 4.6 新增 API（routes_bridge.py，bridge 模式）

| 端点 | 方法 | 功能 |
|------|------|------|
| `/api/vault/pdf` | GET | **新路径**（审核 P0-1：`/api/vault/file` 已被 routes_knowledge 占用为 JSON 文本读取，不得复用/遮蔽）流式返回 vault 内 PDF，支持 HTTP Range；路径校验 `_bridge_path` + 仅 `.pdf` 白名单；鉴权见下方签名说明 |
| `/api/import/pdf/book?main_task_id=` | GET | 段状态列表：逐段探测文件非空 + 联查活跃 `convert_segment`/`pdf_segment` 任务行（running/failed 状态与 error）；不依赖历史任务行 |
| `/api/import/pdf/segments/convert` | POST | body: {main_task_id, segs:[段号…]，confirm?:bool，force_ocr?:bool}；先校验该段"文件 0 字节或存在 failed 行"，再返回本次需 OCR 的页数与预计消耗（确认3=B）；仅当前端带 `confirm=true` 重调时才真正建 `convert_segment` 任务投递 worker；`force_ocr=true` 时文本层段也强制走 OCR 路径（防误判空段，§6） |
| `/api/import/pdf/segments/estimate` | POST | body: {main_task_id, segs:[段号…]} → 返回 {待OCR页数, 预计积分/额度消耗（复用现有 OCR 计费口径）}；供消耗确认框展示，不落任何任务（确认3=B） |

鉴权与用户隔离（审核 P0-2/P2-12，写实）：
- 流式端点无法走 `Authorization` 头（iframe src 普通 GET，项目无 URL 直读先例）→ **签名参数方案**：前端打开 viewer 前调带 `@require_auth` 的 `/api/vault/pdf/sign?path=`，服务端用 Flask secret_key HMAC(`user_id|path|exp`) 签发 **60 分钟** token（覆盖典型阅读窗口，复审 P2-E：pdf.js 分片 Range 请求固定使用同一 URL，iframe 内无法热换 t，10 分钟会造成阅读中途 401）；`/api/vault/pdf?path=&t=` 校验 t 签名+过期+解析出 user_id → `_bridge_path` → 206/200；过期兜底：父页监听 viewer 错误事件后重签+重载，并通过 `#page=` 参数还原当前页（§5.1 同步）。**book/convert 两端点仍 @require_auth**，且一律按 `(id, user_id)` 双条件查询（沿用 get_task 防横向越权先例）；
- pdf.js iframe URL：`web/viewer.html?file=<编码的 /api/vault/pdf?path=..&t=..>`。

### 4.7 上限与文案

- `config.IMPORT_MAX_BYTES = 200 * 1024 * 1024`；app.py 引用该常量不变；
- 前端 `MAXB`（online_course_notes.html:4855）→ 200MB，同文件预检文案（4857）与 413 错误文案（4875）一并同步；config.py 注释（L46）与 app.py 注释（L37）的"50MB"字样同步改（合计 6 处，见 §2 裁定#8）；
- 内存预算（审核 P2-10）：200MB 整读整写为单文件峰值开销；前端多选**并发**上传时 N 个 200MB 会 N 份在内存——本期约束：书籍 PDF（>20MB）前端导入对话框串行上传（其余小文件维持现状）；分块流式写盘非本期必需，记 §10。

## 5. 前端设计

### 5.1 pdf.js 基建

- `pdfjs-dist` viewer 完整包**本地化**放入 `server/static/pdfjs/`（含 worker，Electron 离线可用，符合批1"去 CDN"方向）；
- 展示形态：online_course_notes 预览区新增 `pdf-viewer` 面板（iframe 嵌 pdfjs `web/viewer.html?file=<编码的 /api/vault/pdf?path=..&t=.. 签名 URL>`，签名流程见 §4.6：打开前先调 `/api/vault/pdf/sign`，token 60 分钟）；笔记树点击原件 `.pdf` 文件时打开该面板，替代现有 MD 预览；签名过期兜底：父页监听 iframe 错误→重签→带 `#page=当前页` 重载还原阅读位置（复审 P2-E）；
- 现有 marked 渲染的 MD 中若出现指向 `.pdf` 的链接，同样路由到该面板（二期标注"从笔记跳原件页码"依赖此通路，本期只需能打开）。

### 5.2 分段转换面板（viewer 工具栏）

- viewer 顶部条追加"分段转换"按钮 → 右侧滑出面板（沿用现有浮层样式规范，Tailwind，禁手写 CSS）；
- 面板数据源 `/api/import/pdf/book`，渲染段网格：每格显示 `21-40`，状态色：已转（绿）/ 转换中+进度（黄）/ 失败（红，悬停显 error）/ 未转（灰）；
- 未转/失败段可勾选（支持"全选未转"），点"转换所选" → 先调 `/api/import/pdf/segments/estimate` → **弹确认框（"本次将转换 N 页，预计消耗 X 积分/额度"，沿用现有二次确认弹层样式）→ 用户确认后带 `confirm=true` 调 convert** → 轮询刷新（沿用现有导入任务轮询模式与频控）；文本层段本地重转不耗远端额度，重转不弹消耗框（仅提示“将覆盖该段已有内容”）；
- 文本层书籍面板全部显示"已转"（导入即自动完成），仅提供"重转此段"操作；
- 点击段格跳转 viewer 对应起始页（pdf.js `page=` 参数）。

### 5.3 笔记树与导入对话框

- 导入完成提示语区分：小 PDF"已生成笔记 书.md"；书籍"已创建文件夹 书/，文本版已转换 N 段 / 扫描版请在阅读器中逐段转换"；

## 6. 错误处理与边界

| 场景 | 行为 |
|------|------|
| pypdf 打不开（加密/损坏） | 导入即失败报错，不留半截文件夹（整段落盘前完成打开校验） |
| 加密文本层 PDF | 判定文本层后仍可能提取为空 → 段产物空则置 failed，错误提示"文件可能加密" |
| 文本层与扫描件混合判据冲突 | 以采样判定为准；误判为文本层导致某段空 → 该段标 failed，面板允许手动重转（重转走本地文本层路径，若仍空提示改用 OCR 重转：段任务加 `force_ocr` 参数） |
| 服务重启 | running 的整书/段任务置 failed（现有 recover）；待转段无任务行、状态由文件 O 字节探测，不受影响；30 天清理跳过 pdf_book 主任务行（§4.5） |
| 同段并发重转 | 段文件锁串行化；任务表状态先校验再投递，重复点击返回"该段正在转换中" |
| 400 页文本层 | 单整书 worker 串行逐段（内部无 `_SEM` 占用），实测基准全文提取 23s → 分段总耗时约分钟级，进度逐段可见（主任务 progress_json） |
| 删除文件夹 | 沿用现有文件夹删除；book 接口对主任务存在但文件夹已删的行返回"原件丢失"错误态，convert 接口拒绝建任务（状态权威在文件，文件没了即无状态可转） |

## 10. 风险与已知限制

- PaddleOCR-VL 对 20 页扫描段的转换时长未实测（现有整本 SLA <3min 对应讲义规模），若单段超 20 分钟会触发 POLL_TIMEOUT——缓解：面板可把大段拆多次勾选（切段提交按勾选段，超时只影响该段）；上线前用真实扫描段实测一次并记录掉坑笔记；
- 200MB 文件 pypdf 打开+采样在秒级（实测 133MB open=0.3s），无风险；
- pdf.js iframe 与主面板的 postMessage 通信是重转跳转/页码联动的唯一通道，遵循既有桥方法兼容层规格，不新增全局耦合；
- 正文意外含 `<!-- llpage:N -->` 字面量会切出幻影页（概率极低，审核 P2-9b），接受风险不加 task 盐；
- 200MB 整读整写非流式（>20MB 书籍前端已约束串行上传缓解），`MAX_CONTENT_LENGTH` 是全局放宽、影响所有端点请求体上限（本地单用户可接受）；
- 签名 token 有效期 10 分钟内 URL 可被同一浏览器会话重复使用（本地单机场景风险可接受，泄露面限于本人 vault 内的 PDF 只读）；
- 段 MD 注入的 llpage 注释对 LLM 知识点提取是极少量噪声（HTML 注释惯例），实测后如需可再过滤，本期不改提取 prompt。
