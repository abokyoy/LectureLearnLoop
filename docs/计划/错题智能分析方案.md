# 错题「智能分析」方案

## 一、需求（用户已裁定）

错题编辑弹窗中，上传图片或输入文字后，点「智能分析」：
1. 用 PaddleOCR-VL 分析题目图片 → 得出**文字区域**（内容+bbox）与**图形区域**（bbox）
2. 图形区域按 bbox **本地裁剪成切片图**存 vault（用户裁定："图就用 Paddle 识别出来的矩形切片"）
3. 把 Paddle 结构化结果 + 原始 MD 内容 + 图片（原图与切片）统一打包发给**能看图的大模型**（方案 B，用户已裁定）
4. 大模型重新组织排版，输出规范 MD：题干是什么、图是什么、用户解答**如实**列在下面、错在什么地方的解析、正确答案
5. OCR 与大模型识别做对比防识别错；解析中写清错在哪、大概率哪个知识点薄弱
6. 结果**直接回填**弹窗三字段（题干编辑器 / 正确答案 / 解析），用户可编辑，点保存入库（用户已裁定）
7. 模型路由：用户配置的大模型若支持视觉则用用户的，否则用系统配置的视觉大模型

## 三、技术设计

### 3.1 数据流

```
前端点「智能分析」
  → POST /api/kb/error-analyze {content: 编辑器当前MD}
     后端：解析 MD 中 ![...](相对路径) 图片清单 → 建 task_id → daemon 线程启动
  → 前端轮询 GET /api/kb/error-analyze/<task_id>（复用 error_ocr 模式）
后台线程三步：
  A. Paddle 版面分析（每图）：图→PDF→submit→poll→jsonl
     → 提取 text/image 块（label+bbox+content）
     → image 块 bbox 按 width/height 比例映射到本地图 → PIL 裁剪 → 存 vault 截图/crop_<ts>_<i>.png
     → 产出 paddle_struct: {texts:[{bbox,content}], figures:[{bbox,local_path}], page_size}
  B. VL 整合：OpenAI 兼容 vision 请求
     content = 指令 prompt + 原始 MD 文本 + paddle_struct JSON + 原图与切片的 image_url(dataURL)
     → 要求输出 JSON 契约 {stem_md, user_solution_md, correct_answer, error_analysis, explanation}
  C. 对比防错（在 prompt 内约束）：VL 文字转录必须与 paddle_struct.texts 一致，
     以 Paddle OCR 为文字准确性基准，VL 只负责排版/理解/分析，不得自行改写题干文字
回填响应 data = {stem_md, correct_answer, explanation}
  stem_md 末尾含「我的解答」小节（user_solution_md 如实保留，图片引用切片路径）
前端：ed.setValue(stem_md)、kbm-answer、kbm-explain 回填（回填前 confirm，“将替换当前题干/答案/解析”，防静默覆盖用户已录内容），用户确认后走原有保存
```

**安全校验**：MD 中解析出的图片路径逐个过 `routes_knowledge._safe_vault_path`（路由层现有口径）+ 拒绝 http/https/data URL 与非图片扩展名。
**多图策略**：逐图串行分析，任务总超时 = `180 + 60×(图数-1)`；后台任务并发用 `Semaphore(2)` 限流（同 import_service 惯例）。

### 3.2 模块落点（遵循公共函数注册制，不新建重复件）

| 模块 | 动作 | 说明 |
|---|---|---|
| `llm_provider_factory.py` | 扩展 | **注册 `SiliconFlowVisionProvider(LLMProvider)` 子类**（遵守公共函数注册制，不另开第二条 LLM 链路）：基类 `call()` 加可选 `images` 参数，`_provider_from_cfg` 增加视觉路由；新入口 `call_llm_vision(uid, prompt_text, images, ...)` 接受**显式 uid**（后台 daemon 线程无 Flask g，必须直传计费，不得走 `_current_user_id()`）。路由：用户模型名含 vl/gpt-4o/gemini 等视觉标志→用用户配置；否则系统 VL 配置（env `VL_API_BASE/VL_API_KEY/VL_MODEL`，默认 SiliconFlow Qwen3-VL-32B）。计费/日志链与 call_llm 同源（用户自备 Key 不扣、系统 Key 扣分、LLM 日志入库；**日志 prompt 字段只存文本部分，不含 base64 图片体**，images 数量记入 context） |
| `services/error_analyze.py` | 新建 | 三步管线；Paddle 调用复用 paddle_doc_client；裁剪用 PIL；**image bbox 每次从 `prunedResult.width/height` 动态换算缩放比（不硬编码倍率）**；任务表用新建公共类 `services/task_registry.py`（dict+lock+TTL sweep，error_ocr 同步切换复用，禁止两套近似实现）；对外 requests 统一 `session.trust_env=False` 直连 |
| `routes_knowledge.py`（或 memory 路由现属文件，以错题 API 现状为准） | 追加 | `POST /api/kb/error-analyze`、`GET /api/kb/error-analyze/<tid>`；归属校验同 error_ocr（发起者 user 才能取结果） |
| `templates/pages/knowledge_base.html` | 追加 | 按钮行后加「智能分析」btn；编辑器非空才启用；点击→postJSON→轮询（间隔/上限同 startOcr）→done 回填三字段 + toast；error 降级提示手填 |
| `server/.env` + `config.py` + `.env.example` | 追加 | `VL_API_BASE`、`VL_API_KEY`、`VL_MODEL`（key 只落 .env，不落代码/文档；config.py 用 os.getenv 加载、.env.example 同步模板，与项目惯例一致） |
| `logger_module.debug_logger` | 接入 | 每个关键步骤写 `debug_logger.log('analyze', action, status, {...})`：提交 Paddle、切片完成、VL 调用、任务终态（项目硬性规范） |

### 3.3 VL 输出契约与 prompt 要点

- 输出 JSON：`{"stem_md": "...", "user_solution_md": "...", "correct_answer": "...", "error_analysis": "...", "explanation": "..."}`
- prompt 硬性约束：
  1. 题干文字**逐字采用 Paddle texts**，禁止改写/补全（防幻觉）
  2. 图形只引用切片路径（编号对应 figures），禁止描述图片内容替代图
  3. 用户解答区如实转录学生笔迹（含错误步骤），不得修正
  4. error_analysis 指出错在哪一步、大概率薄弱的知识点；explanation 给出正确推导
  5. correct_answer 与 explanation 分开；若图中无标准答案栏则依据题目求解给出
- 解析容错：VL 返回 markdown 围栏/JSON 混合 → 提取首个 JSON 对象（本地修复尝试，允许尾逗号/代码围栏剥离）；仍失败 → 任务置 error 降级，**不重发 VL 请求**（避免重复扣积分）

### 3.4 降级兜底（核心功能必须有兜底）

| 故障 | 行为 |
|---|---|
| Paddle 失败（提交/轮询/超时） | 跳过版面分析，原图全量直接发 VL（paddle_struct=null，prompt 说明无 OCR 基准） |
| VL 失败/超时/JSON 不可解析 | 任务 error，前端 toast「智能分析失败，请手动补录」，编辑器原内容不动 |
| 图多张 | 逐图分析，figures 汇总；单图失败不拖垮整任务（该图按原样引用） |
| 任务超时 | 上限 `180 + 60×(图数-1)` 秒，超时置 error |
| 任务结果读取 | done/error 结果 TTL(600s) 内可重复读取（不 pop-即弃），防前端处理异常后无法重试 |

### 3.5 安全与归属

- 端点需登录态；任务结果仅发起者可取（同 error_ocr user 校验）
- 图片路径限制在用户 vault 内（复用 error_ocr 的路径校验口径）
- VL key 仅 .env；日志脱敏（LLM 日志不存 base64 图片体）

## 五、已知限制 / 待拍板细节

- 用户解答放在题干 MD 末尾「我的解答」小节（弹窗只有 3 个可回填字段，无独立解答栏）——见确认问题
- 回填前加 confirm 确认替换（评审阻塞项 L3 采納）——若用户觉得多此一举可去掉，见确认问题
- 切片图落盘即永久保存（vault 本为文件系统），弹窗关闭未保存不回滚——已知限制，接受
- 系统 VL 调用扣分口径：按现有 call_llm 系统链的 token→积分规则执行——见确认问题
- ModelScope key 失效事实不写入本项目配置（已实测不可用），仅保留 SiliconFlow 通道
