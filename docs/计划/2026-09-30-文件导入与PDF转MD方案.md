# 网课笔记文件导入（PDF/MD/TXT）与 PDF 转 MD 方案

> 日期：2026-09-30　状态：已按子代理评审修订（v2）
> 来源需求：用户第五轮反馈（详见对话）——"新建文件夹/新建文件"右侧加"导入"；PDF/MD/TXT；
> 未选位置→根目录，选中文件夹→其下，选中文件→其所在文件夹；PDF 转 MD（PaddleOCR 调接口形式，
> key 复用 guiji/AIFinFlowX-dev 已验证的官方 Job API）；原始 PDF 落"附件"文件夹；图片要支持学习（大模型识图）。

## 一、已核实事实（代码/官方样例，非推测）

1. **PaddleOCR-VL Job API**（AIFinFlowX-dev `services/coordinate_fusion/paddle_client.py` + `doc/paddleocr.md`，同一 token 已在生产使用）：
   - `POST https://paddleocr.aistudio-app.com/api/v2/ocr/jobs`，multipart（file + model + optionalPayload），头 `Authorization: bearer <token>`；模型 `PaddleOCR-VL-1.6`；返回 `data.jobId`。
   - `GET {JOB_URL}/{jobId}` 轮询：`state` pending/running/done/failed；running 时 `extractProgress.{extractedPages,totalPages}` 提供页级进度；done 时 `resultUrl.jsonUrl`。
   - JSONL 每页 `result.layoutParsingResults[]`：`markdown.text`（该页 Markdown，**混排版面已还原**）、`markdown.images`（{MD内相对路径: 可下载URL}）、`outputImages`。图片需逐个下载并按 MD 中引用路径改写成本地相对路径。
   - 即：**文图混排、表格、公式、阅读顺序由官方接口统一处理，无需本地模型、无需分流判断**。
2. 本工作区现状：
   - 按钮头区 `online_course_notes.html` L1559-1565（新建文件夹/新建笔记/折叠），导入按钮插在此行；页面函数须挂 window（P034 教训，统一挂现有暴露块 L10425+）。
   - vault 写文件已有安全模式：`routes_bridge._bridge_path(user_id, path)` 强制用户目录内；重名风格"新建笔记N"。
   - 前端选本地文件：Electron 渲染进程 `input[type=file]` 即弹系统文件框，无需动 preload/main。
   - MD 预览渲染器仅对 `attachments/` 前缀的 img src 走 `getImageAsBase64` 转 base64（主渲染器 L9760-9765、备用 L9646-9649），其他相对前缀按 HTTP origin 解析必 404；`截图/` 前缀历史上只验证了入库未验证渲染。MathJax/GFM 表格渲染可用。
   - 既有唯一权威写文件路径：`PUT /api/vault/rawfile` 写盘后同步 `upsert_note_content`（routes_bridge L297-300）——新写入必须保持同样两步，否则笔记主面板看不到导入文件。
   - PG 为 ThreadedConnectionPool，`db_manager.get_connection` 线程安全（worker 内 try/finally 归还）；但**生产代码尚无后台线程先例**，需显式约束（见 3.2）。
   - 右键四项菜单 `#file-context-menu`（深入学习/开始练习/重命名/…）；文本划词链路 `handleDeepLearning`。
   - 配置模式：`server/.env` + `config.py` 集中读取（禁止明文散落代码）。
   - 后端 Python 3.12 + Flask + PostgreSQL；HTTP 用 requests/httpx（已在 requirements）。
3. 用户已确认的规则：
   - 落点：未选→根目录；选文件夹→其下；**选文件→其所在文件夹**。
   - **原始 PDF 保留**，放导入目标位置的**同级"附件"文件夹**。
   - 耗时交互：**后台任务 + 轮询通知**。
   - 图片要支持"学习"（用户认为大模型可识图）——评审指出当前 LLM 通道（LLMProvider.call 仅收字符串，无 OpenAI 兼容消息数组；DeepSeek 为文本模型）不具备视觉能力，需独立设计视觉 provider 与计费接入，**拆二期**（本轮交付：图片完整保留在 MD 中可看，右键图片学习二期做）。
4. 评审修正记要（v2 新增，均为必须落实项）：
   - **MF-1 图片引用**：渲染链路只认 `attachments/` 前缀 → 扩展渲染器：任意相对路径前缀（含 `附件/`）统一按"所在笔记文件的绝对目录"解析后走 getImageAsBase64（改动约十几行），从而同时满足"同级附件"用户规则与渲染可见；实现时以真实图片渲染断言验证（非仅入库断言）。
   - **MF-2 上传治理**：Flask `MAX_CONTENT_LENGTH=50MB` 在 app 级配置；服务端扩展名白名单；文件名清洗复用 routes_bridge L329 正则模式并显式处理 `\\` `/` 分隔符注入（不用 secure_filename，它会清空纯中文名）。
   - **MF-4 落点冻结**：在打开文件选择框**之前**一次性解析目标并冻结（多文件队列复用同一路径），避免 jsTree 刷新销毁选中态导致后续文件错落根目录；父目录用 `inst.get_parent(node)`，根级 `'#'` 特判映射回 vault，禁止对 Windows 路径字符串 split。
   - **MF-5 入库同步**：PDF/MD/TXT 落盘后一律调用 `upsert_note_content`（仅需 user_id+abs_path，worker 线程可直接调）。
   - **优化项采纳**：任务表加 `remote_job_id`；`GET /api/vault/import/<id>` 按 user_id 过滤防越权；JSONL 解析按"逐行 × 逐 layoutParsingResults[]"两级循环（一行可含多 result）；图片整体重命名为 `附件/img_<页>_<序号>.png` 并同步替换 MD 引用（含 URL 编码防御）；导入任务全局信号量并发≤2（Paddle 队列满 400/10010 时排队而非打爆）；jobId 字符集校验后再拼 URL；时间列统一库内 UTC TEXT 风格；建表点名双方言模式（参照 schema_credits.py 先例，PG 幂等 `CREATE TABLE IF NOT EXISTS` 进 create_app 初始化）。

## 二、总体架构

```
[导入按钮] → input[type=file] 选文件 → 读为 FormData
   → POST /api/vault/import (file, folder_path)      立即返回 {task_id}
        ├─ MD/TXT：后端直接解码落盘，任务秒完
        └─ PDF：原件写 <目标>/附件/<名>.pdf；建任务，后台 worker 线程：
              提交 PaddleOCR Job → 5s 轮询(进度回写任务) → 下载 JSONL
              → 逐页拼接 markdown.text + 下载 markdown.images 到 附件/img_*.png 并改写引用
              → 写 <目标>/<名>.md → 任务 done
[前端] 每 3s GET /api/vault/import/<task_id> → 面板顶部细条显示"转换中 n/m 页"
   → done：loadFileStructure() 刷新 + 打开新 MD 预览；failed：红色提示原因（原件保留）
```

## 三、后端改动

### 3.1 新文件 `services/paddle_doc_client.py`
从 AIFinFlowX 的 paddle_client.py 提炼同形三段：`submit_job(file_path)` / `query_job(job_id)` / `download_jsonl(url)`；参数来自 config；差异：
- optionalPayload：`{useDocOrientationClassify:false, useDocUnwarping:false, useChartRecognition:false, useSealRecognition:false, formatBlockContent:true}`（讲义无印章；关 seal 与 AIFinFlowX 发票场景取舍不同，明示差异）。
- 提交重试 3 次指数退避（沿用）；轮询超时 20 分钟（讲义一般 <50 页，实测后再调）。
- 瞬时可重试错误沿用其分类（400/408/409/422/429/5xx）。

### 3.2 新文件 `services/import_service.py`
- `create_task(user_id, filename, folder_rel, kind)` → 入库；`run_pdf_job(task_id)` 在 daemon 线程执行全流程，进度回写；`finish/fail` 更新。
- **worker 线程显式约束**（评审 MF-3）：数据库连接一律 worker 内部 `db_manager.get_connection()` + `try/finally close()` 归还池；不触碰 Flask `g`/请求上下文，user_id 等全部显式传参；全局信号量限并发 2（PG_POOL_MAX=20 预算充裕）；启动时将 status=running 的遗留任务置 failed("服务重启中断")（在 create_app 里执行）。
- 命名：清洗非法字符；重名自动 `_1/_2` 后缀（对齐现有风格）；图片文件名 `img_<页>_<序号>.png`。
- TXT 解码：utf-8 → gb18030 回退（网课常见 Windows 记事本 TXT）；MD 按 utf-8。
- 图片 URL 下载走 requests（百度域名，**不需要** V2RAYN 代理；实现时连通性实测，失败才走 HTTP_PROXY_URL 配置项）。
- 单文件上限 50MB；页数不做硬限制（接口侧自然约束），超 200 页时前端提示"页数较多，转换需要几分钟"。

### 3.3 新端点（routes_bridge.py 或新建 routes_import.py，倾向前者，同 vault 语义聚合）
- `POST /api/vault/import`（require_auth，multipart）→ `{task_id}`
- `GET /api/vault/import/<task_id>` → `{status, progress:{done,total}, result_name, error}`（**查询强制带 user_id 条件**，防横向越权）
- 全部经 `_bridge_path` 路径校验；失败也写 debug_logger（AGENTS 第八节）。

### 3.4 数据库
新表 `import_tasks`（PG，schema 沿用 database/ 现有模式）：
`id TEXT PK, user_id TEXT, file_name TEXT, folder_path TEXT, kind TEXT(pdf|md|txt), status TEXT(pending|running|done|failed), progress_json TEXT, result_md TEXT, result_pdf TEXT, remote_job_id TEXT, error TEXT, created_at, updated_at`
任务记录保留 30 天（启动时懒清理），不追求完善归档。

### 3.5 配置（.env + config.py）
`PADDLE_OCR_JOB_URL` / `PADDLE_OCR_TOKEN`（值取自 AIFinFlowX，落 .env 不落代码）/ `PADDLE_OCR_MODEL`。

## 五、图片"学习"（拆二期，评审 MF-6）

本轮交付：图片完整保留在转换后的 MD 中（渲染可见、可预览）。**右键图片→学习 不做**，原因（代码事实）：`LLMProvider.call(prompt: str)` 全链路只收字符串，DeepSeek 通道为纯文本模型，不存在可直接加 image_url 的结构；二期需新增独立视觉调用函数（OpenAI 兼容 image_url 段）并强制走 `call_llm` 计费入口，视觉模型选型需与用户另行对齐（本项目 provider 工厂已支持多 provider，扩展点现成）。

## 八、风险

1. PaddleOCR 免费 API 政策变化（现 20000 页/日）→ provider 配置化，故障时任务报明确错误，不静默。
2. 外网连通（百度域名直连 vs 需代理）→ 实现首日实测。
3. 后台线程与 Flask 重启：进行中任务丢失 → 启动时将 running 任务置 failed("服务重启中断")，用户重导即可（讲义场景可接受，不引入持久化队列）。
4. 图片学习依赖视觉模型可用性（第五节降级路径已设计）。
