## 2. 数据层（三处同步维护：PG_TABLES / SQLite init_database / migrate 工具表清单）

DDL 风格：PG 用 `ADD COLUMN IF NOT EXISTS`；SQLite 用既有 try/except 吞 duplicate-column；`NUMERIC(3,1)` 在 SQLite 侧为 `REAL`。**用户已授权**：加列/新表/存量 question_hash 回填直接在本机 PostgreSQL 正式库执行；回滚=停用新写回路径，不删列不删表。

### 2.1 knowledge_points / error_questions 加列（全部可空；difficulty_score/importance_score 带 DEFAULT 5.0——存量行回填为「默认 3 星」，属可接受业务语义，与「未评估」判定无关）
| 列 | 类型 | 说明 |
|---|---|---|
| difficulty_score | NUMERIC(3,1) DEFAULT 5.0 | 难度 0-10（星×2），**避开既有字符串 difficulty（"中等"）字段名冲突** |
| importance_score | NUMERIC(3,1) DEFAULT 5.0 | 重要程度 0-10，同上避开 importance |
| fsrs_stability REAL / fsrs_difficulty REAL / fsrs_state INT / fsrs_reps INT / fsrs_lapses INT | | FSRS 状态 |
| last_review_time TEXT / due_time TEXT | | UTC 文本，与全库时间口径一致 |

- error_questions 另加 `question_content TEXT` + `question_hash TEXT`（入池时题干快照，先例=favorite_questions），**错题入池即冻结题干**，`update_error_question_content` 不再作用于已入池错题；`practice_records` 同步加 `question_hash`（规范化题干 md5，由写入路径落值 + 一次性存量回填脚本）；错误率按 `question_hash` 聚合，新增索引 `idx_pr_user_kp_qh ON practice_records(user_id, knowledge_point_id, question_hash)`——**不对长题干 TEXT 建 btree 索引**（PG 索引行 2704 字节上限会让长题干 INSERT 硬报错）。
- 既有字符串 `difficulty/importance`（LLM 旧输出、mastery_stars 等）**保留不动**；前端原 `mastery_stars` 展示位改名标注为"正确率星"，与"难度星/重要星"三组星明确区分。

### 2.2 新表（PG 与 SQLite 双写，均带索引与 user_id 隔离）
```
kp_proficiency_history(id, knowledge_point_id, user_id, timestamp, mastery, retrievability)
  INDEX (knowledge_point_id, timestamp)
memory_cards(id, user_id, card_type 'kp'|'error', ref_id, subject_name,
  front_text, back_text, added_time, UNIQUE(user_id, card_type, ref_id))
  INDEX (user_id, card_type, subject_name)
```
- 标注幂等：`INSERT ... ON CONFLICT DO NOTHING`（db_adapter 已有 OR IGNORE 翻译）；移除后再加不清空已有 FSRS 状态（ref 指向对象的状态延续，卡片只删行）。
- 卡片文本标注时快照；**知识点合并时**：被合并方的卡片按规则重挂/去重（同 ref_id 已存在则删除被合并方卡片）。
- 删除知识点/错题时服务层显式清理两张新表关联行（PG 无外键，靠服务层收敛）。
- `update_subject_name` 级联清单追加 `memory_cards.subject_name`。

### 2.3 熟练度统一口径（FSRS 派生 + 惰性衰减回写）
- `mastery_score`（知识点）/ `current_proficiency`（错题）= round(100 × R)，`R = (1 + t/(9S))^(-1)`；**不做 SQL 端实时计算**，由 `fsrs_service.decay_flush()` 惰性回写。**两阶段口径**：列表/详情/脑图端点先 flush 涉及行再按 SQL 查询；统计端点（dashboard COUNT 类，SQL 谓词在 Python 见行之前完成过滤）执行「按 user 全量 flush → 再发统计 SQL」，每 user **10 分钟节流**（last_flush 记录于 system_config）抑制写放大；全量 flush 单事务批量 UPDATE（非逐行）；PG 后端为权威路径，SQLite 兼容路径逐事务 flush 不启用节流。
- 「未评估」判定唯一保留 **-1 哨兵**：`mastery_score = -1` ⇒ 未评估（灰）；新建知识点照旧写 -1，**不引入 NULL 语义**（存量 50 视为已评估值继续，首评后被 FSRS 派生值覆盖）。routes_bridge/knowledge_management 现有 6 处「返回体回填 50 / 脑图节点回填 -1」收敛为 fsrs-core 提供的单一函数 `fsrs_service.mastery_view(score)`（分支归属 fsrs-core）；前端仅保留 `-1/null/undefined ⇒ 未评估` 判定，`|| -1`、`|| 0` falsy 陷阱统一改 `??`（否则「完全忘记=0 分」会被误判为灰色）。
- dashboard「已掌握/待复习」统计改基于 `due_time <= now()` / `mastery` 阈值，废除 `review_status=0` 旧口径（review_status 列保留不删）。
- 脑图缓存失效在惰性回写后自动触发（沿用 clear_mindmap_cache），并给缓存加 24h TTL 兜底。
- 并发安全：FSRS 读写回事务内 `SELECT ... FOR UPDATE`（PG）/事务包裹（SQLite），防止多窗口并发交卷双写 history。
- **唯一写入口**：熟练度/状态变更只经 `fsrs_service`；`routes_knowledge.py` 旧端点 `POST /api/kb/errors/<id>/proficiency`（标量直写）改为 `rating` 语义并转调 fsrs_service；`append_proficiency` 只改 `ErrorQuestionManager` 实现，`LegacyKnowledgeManagementSystem` 标 deprecated 不动。

## 3. FSRS-5 算法服务（server/services/fsrs_service.py）

- FSRS-5 标准公式（与 open-spaced-repetition 参考实现逐式对齐），19 参数取官方公开默认值，常量集中 + `params_override` 预留；间隔 `I = S × (R^(-1/0.9) - 1)^(-1)` 形式按参考实现为准（`desired_retention` 默认 0.9）。
- rating 映射（用户确认：LLM 细粒度评分）：答错=`Again(1)`；答对按判分质量分档——扩展 evaluatePracticeAnswer 判分 prompt 输出 `answer_quality`（勉强答对/正常答对/精准流畅）→ Hard(2)/Good(3)/Easy(4)，字段缺失默认 Good(3)；卡片自评 4 档 `很不熟悉=Again/不熟悉=Hard/熟悉=Good/非常熟悉=Easy`。
- 初始化：`fsrs_stability IS NULL` 时首评直接用 `S0(rating)` 查表 + `D0(rating, 知识点难度星)` 初始化，**不做存量分数等效 t 折算**（评审 F4 结论：无 S 不可反解，简化为查表）。
- 时间基准：fsrs_service 入参统一 `datetime`（tz-naive UTC），禁止 SQL 内做时间算术；Python 侧解析现有 TEXT 时间。
- 复习使 mastery 可能下降（Again/Hard）：曲线图同时画 mastery 与 retrievability 并配说明文案，避免"复习反而变笨"的观感。
- 单元测试与参考实现样例值比对（确定性断言，不依赖 LLM）。

### 3.1 推荐/出题策略
- Sprint（用户确认：**一次性生成全卷**入库，可中途退出/重进不丢题；会话复用 practice_sessions/submissions 体系）：候选池按「R 升序 → importance_score 降序 → difficulty_score 升序」取 N（5/10）；池不足返回可用数并提示。知识点/错题两种 kind。
- 出题难度搭配：mastery<40 简单为主；40-70 简+中混合；>70 中+难。题型选择/填空/主观/判断，手选或智能搭配。
- `sprint_plan` 取代 `generate_targeted_questions` 的选题职责；题型判定复用现有 `_qtype`，上移到服务层，不新增分支。
- **计费链路强制复用**：所有新出题/推荐端点走现有 LLM 出口，保留 `InsufficientCreditsError` → `credits_insufficient` 返回语义（与 routes_knowledge 现有 402 处理一致），Sprint 不得绕过扣费。

## 4. LLM 提取提示词与确认页（学）

- 提取输出 JSON 增 `suggested_importance / suggested_difficulty`（1-5，可 0.5）；解析端（含 processed_points 链路）透传；**字段缺失/非数值/越界一律回退 2.5 星（=存储 5.0）且不阻断提取**；旧字符串字段 importance("中等") 原样保留兼容。
- 确认页两组五角星可点（左半=+0.5，右半=整星；键盘可达：左右键步进 0.5），默认 LLM 建议；合并到已有知识点不覆盖既有星值（用户显式改动除外）。
- 星值范围：最低 0.5 星（=1 分），上限 5 星（=10 分）；`set_star` 服务端截断。0 分不作为录入值（=不允许"清零"）。
