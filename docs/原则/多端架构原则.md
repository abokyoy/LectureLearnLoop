# 多端架构原则

> 本系统规划两个终端：**Web 端**（完整功能）+ **移动端**（核心采集功能）  
> 两端共享同一后端 API，禁止各自实现业务逻辑。

---

## 一、功能边界划分

### 1.1 Web 端（完整学习功能）

Web 端是主要的使用场景，承载完整学习闭环：

```
✅ 工作台（数据总览、最近活动）
✅ 资料学习（文本输入 → 知识点提取 → 确认入库）
✅ 网课笔记（录音 → 语音转文字 → AI 摘要 → 笔记）
✅ 练习系统（三类练习：基于资料/知识点/错题）
✅ 知识脑图（生成、可视化、熟练度展示）
✅ 学习路径（线性规划图）
✅ 知识库管理（知识点/错题/收藏 CRUD）
✅ 设置（LLM 提供商切换、API Key 配置）
✅ LLM 调用日志（调试、监控）
✅ AI 助手浮窗（即时问答、文本总结）
```

### 1.2 移动端（核心采集功能）

移动端定位是**随时随地的学习素材采集工具**，不做复杂操作：

```
✅ 录音 → 语音转文字（网课/讲座随时录）
✅ 拍照 → OCR → 文字笔记
✅ 快速笔记（Markdown 文本编辑）
✅ 笔记列表浏览（只读）
✅ 知识点收藏查看（只读）

❌ 练习功能（不在移动端）
❌ 脑图查看（屏幕太小，体验差）
❌ 设置（在 Web 端完成）
❌ 知识点确认/合并（复杂交互，留到 Web 端）
```

### 1.3 共享层（后端统一提供）

```
✅ LLM 调用接口（同一工厂。注：工厂层降级链规划中未实现，但 KnowledgePointManager 有历史降级代码，应收敛）
✅ 知识点存储与查询（同一 SQLite 数据库）
✅ 笔记文件存储（vault/ 目录，两端共享）
✅ 练习数据（practice_history.db，两端共享）
✅ 用户配置（app_config.json）
```

## 二、技术选型约束

### 2.1 Web 端（已确定）

| 层 | 技术 | 理由 |
|----|------|------|
| 框架 | Flask | 当前已使用，不引入新框架 |
| 模板 | Jinja2 | 服务端渲染 + 内联 JS（当前模式） |
| API | RESTful JSON | 与移动端共享同一 API |
| 样式 | Tailwind CSS | 已使用，统一设计语言 |
| 交互 | jQuery + 原生 JS | 已引入，不追加新框架 |

### 2.2 移动端（规划中，技术选型待定）

以下是候选方案，**Agent 不要自行决定，必须与用户确认后再选型**：

| 方案 | 优点 | 缺点 |
|------|------|------|
| **PWA（Web 套壳）** | 复用现有 Web 代码，开发快 | 拍照/录音能力受浏览器限制 |
| **Flutter** | 一套代码 iOS+Android，原生相机/麦克风 | 引入新语言（Dart），学习成本高 |
| **React Native** | JS 技术栈与 Web 端一致 | 需新建工程，与 Flask 后端交互需封装 |
| **微信小程序** | 用户无需安装，国内普及率高 | 功能受限，审核严格 |

> **[待确认]** 移动端技术选型尚未确定，Agent 在开始开发前必须先确认此选型。

### 2.3 禁止的选型

- 不在未与用户确认前引入新框架（React、Vue、Next.js 等）
- 不为移动端单独实现一套业务逻辑
- 不在移动端本地存储核心学习数据（应通过 API 操作后端数据库）

## 三、API 设计原则（两端共享）

### 3.1 统一 API 契约

两端使用同一套 RESTful API，通过 `User-Agent` 或 `/api/mobile/*` 前缀区分，业务逻辑不变：

```
/api/*          ← Web 端使用
/api/mobile/*   ← 移动端调用（内容相同，前缀区分）
```

### 3.2 API 设计规则

```
1. 所有响应统一格式：
   成功: {"success": true, "data": {...}}
   失败: {"success": false, "error": "错误描述"}

2. 分页统一参数：?limit=N&offset=M
   响应统一包含: {"items": [...], "total": N}

3. 文件上传统一用 multipart/form-data，其他用 JSON

4. 认证（未来多用户时）：
   - 当前版本无认证，user_id 固定 "0001"
   - 升级路径：在 Header 加 Bearer Token，不修改 URL 结构
```

### 3.3 移动端特有 API 需求

以下 API 是移动端特有需求，当前 Flask 后端**尚未实现**：

| API | 用途 | 优先级 |
|-----|------|--------|
| `POST /api/mobile/upload-audio` | 上传录音文件，触发转文字 | 高 |
| `POST /api/mobile/upload-image` | 拍照上传，触发 OCR | 中 |
| `GET /api/notes/list` | 笔记列表（分页） | 高 |
| `GET /api/notes/detail` | 单篇笔记内容 | 高 |

## 四、数据同步原则

两端共享后端数据，无本地缓存冲突问题。但需注意：

1. **笔记文件**（`vault/` 目录）是唯一的数据源，两端都通过 API 读写
2. **SQLite 数据库** 不支持多进程并发写入，Web 和移动端不会同时写（移动写时 Web 只读，或用户只用一端）
3. **LLM 调用日志** 两端都写入同一 `logs/debug_trace.jsonl`，通过 `source` 字段区分（`web` / `mobile`）

## 六、Agent 开发移动端时的规则

1. **不要自行决定技术选型**，必须先向用户确认方案
2. **不重复实现后端业务逻辑**，移动端只调用 API，不直连数据库
3. **UI 优先**：移动端的交互设计要符合手机操作习惯（单手操作、大按钮）
4. **离线能力**：拍照/录音在网络断开时暂存本地，有网时自动上传
