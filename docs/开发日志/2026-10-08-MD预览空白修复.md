# 2026-10-08 MD 预览空白修复（网课笔记页）

## 问题（用户报告）

直接点击 MD 文件时，预览区有时空白，必须先点一下「编辑」、再点一下「预览」，才能看到内容。

## 根因（全部来自代码 + CDP 断言复现）

`server/templates/pages/online_course_notes.html` 中存在**两套同名全局函数** `switchToPreview / switchToEdit`：

1. **完整版**（约 L6052 / L6100）：用 `hidden` class 切换显示/隐藏，预览时自动保存未编辑内容并重载渲染 —— 原本的正确实现；
2. **补丁版**（约 L11545-11613，页面尾部）：后定义，**覆盖了完整版**，改用行内 `style.display='none'/'block'` 切换，并写 `window.isEditMode`。

由此产生空白链条：

- 用户点「编辑」→ 补丁版给 `#preview-content` 写上**行内** `display:none`；
- 再点 MD 文件 → `loadFileContent` 正常渲染内容进该容器，但「确保预览模式」代码只做 `classList.remove('hidden')`，**清不掉行内样式**（行内样式优先级高于 class）→ 内容渲染进了一个隐形容器 → **预览区空白**；
- 点「编辑」再点「预览」→ 补丁版把 `display` 设回 `block` → 内容露出 —— 与用户描述的症状逐字吻合。

附带缺陷：补丁版写的 `window.isEditMode` 与主逻辑读取的 IIFE 闭包变量 `isEditMode`（L1907）状态分裂，导致「编辑模式下切换文件」等分支永远走不到。

## 修复内容（业务语言）

- 删除页面尾部的补丁版预览/编辑切换函数，统一回归完整版：切换预览时若有未保存修改会**先自动保存再展示**，且始终重新渲染最新内容；
- 清除无效的 `window.isEditMode` 复位残留；
- 加载文件内容的预览分支加防御：显式清掉可能残留的行内 display，保证容器可见性只由 class 控制；
- 体验小改善：没有选中任何文件时点「编辑」，现在会提示「请先在左侧选择一个笔记文件」（此前是静默无反应）。
