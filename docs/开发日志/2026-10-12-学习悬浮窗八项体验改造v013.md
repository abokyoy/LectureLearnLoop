# 2026-10-12 学习悬浮窗八项体验改造（v0.1.3）

## 用户反馈的 8 个问题与业务结论

| # | 反馈 | 处置 |
|---|------|------|
| 1 | 录制中应显示已录时长 | 标题栏"录制中"后新增 `· mm:ss` 计时（暂停显"已暂停"停表），每秒心跳刷新 |
| 2 | 段落总结间隔必须在点开始前设好，体验差；默认 60s 太短 | 默认改 **300s**；录制中随时可改，**下一次总结即按新值**（链式 setTimeout 取代固定 setInterval）；设置记入 localStorage，下次开机恢复（限幅 10~3600s） |
| 3 | 段落总结应有倒计时 | 间隔输入旁新增 `· 下次 mm:ss` 倒计时；总结请求进行中显示"生成中…" |
| 4 | 段落总结展示不该是 MD 源码 | 改为渲染后格式（列表/加粗/标题/KaTeX 公式），**笔记落盘内容不变**，仅展示层；渲染库全部本地化（marked@9.1.6 + DOMPurify@3.0.6 vendor + 已有 KaTeX），客户机无 CDN 也能离线渲染 |
| 5 | **（最重要）插耳机后声音就录不到了** | 根因：WASAPI loopback 绑定的是"开始录制那一刻的默认输出设备"，插/切耳机后系统默认输出换了 endpoint，旧音轨变哑管道。新增三层自愈：①音轨 ended/mute 事件立即重取；②设备枚举变化（devicechange）延迟 1.2s 重取；③24 秒连续无声看门狗兜底（最多自动重连 2 次，真·安静课程不被反复打扰）。重取走主进程免弹框通道**静默完成、录音不中断、字幕不丢**；万一缺用户手势被 Chromium 拒绝，降级为 toast 提示"点一下悬浮窗任意处"，一次点击即恢复且失败可反复重试 |
| 6 | 电平图一直不显示（只在拖拽时才出现） | 双根因：①悬浮窗没关后台节流——未聚焦小窗的动画帧被 Chromium 压到停走，拖拽时窗口被系统提升才短暂出帧；②旧波形每帧 `ctx.scale` 不重置变换，缩放帧间累积把画面推出画布。修复：overlay 窗 `backgroundThrottling:false`（与主窗同口径）+ 每帧 `setTransform` 重置 |
| 7 | 拖拽悬浮窗越拖越宽 | 根因：旧实现逐 mousemove 走 IPC `setPosition`，Windows/DWM 对高频 SetWindowPos 产生被拉宽的窗口拖影。整体废弃 JS 拖拽，改 CSS `-webkit-app-region: drag` 原生拖动（按钮区 no-drag），旧 IPC 桥与主进程 handler 一并删除 |
| 8 | 无法改悬浮窗尺寸 | 右下角新增把手，拖拽实时调窗口尺寸（内容区 320×420 ~ 960×1280 钳制）；悬浮窗位置/尺寸在应用会话内记忆，关掉重开不丢 |

## 过程中发现的独立事实（与本次改动无关但影响环境）

1. **p7 日志声称的悬浮窗 1.75 缩放从未进过 git 历史**（`git log -S setZoomFactor` 为空），当前代码无缩放，坐标 1:1，本次 resize 实现按此口径。
2. **本机 WGC 屏幕级捕获故障插曲**：跑到一半断言全红卡"获取 ASR 配置…"，取证实锤是 `desktopCapturer.getSources({types:['screen']})` 返回空（断开远控/会话切换的典型后遗症，stderr `Failed to start capture: E_INVALIDARG`），窗口级捕获正常。顺手把免弹框 handler 从"盲取 screen 第一个源"改为 **screen 优先、空则回退 window 源**——业务只消费 loopback 音频轨，视频轨仅为权限载体，回退不改变语义，且给无头/会话损坏机器上的产品加了防线。详见掉坑笔记 2026-10-12。
3. **积分业务规则再证实**：注册用户 balance=0，**登录**才触发每日赠送 100，`/api/asr/config` 对无分账号 402 拒发 key——测试夹具必须显式 login（掉坑笔记 P012 同族）。
