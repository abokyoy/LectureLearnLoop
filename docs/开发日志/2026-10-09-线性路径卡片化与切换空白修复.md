# 2026-10-09 线性学习路径卡片化改造 + 树↔线性切换空白 bug 修复

## 背景（用户反馈）

1. **切换空白 bug**：技能树显示正常，但点 Tab 切回"线性路径"时画布空白，必须再点一次"梳理知识点"才能出图
2. **样式统一诉求**：技能树的卡片节点 + 曲线连线效果好，希望线性路径也用同样的画法（节点和线沿用技能树，路径结构保持线性）

## Bug 根因（代码事实）

- 线性渲染用 d3 力导向图，但所有节点本就钉死 fx/fy 固定坐标——力引擎纯空转，却留下隐患
- `forceLink` 初始化时**就地**把边的 source/target 从字符串 id 改写成节点对象，污染了 `currentLearningPathData` 原始数据
- 第二次渲染（树→线性切回）时被污染的边全部被"端点必须是 id"的校验判为无效，且在 `validEdges` 块级作用域处抛 ReferenceError → 画布空白
- 双保险修复：① 边数据浅拷贝 + `validEdges` 提升到函数作用域；② 彻底删除力导向，改为确定性坐标布局，从根源消灭污染路径

## 线性卡片化改造

- **确定性鱼骨布局**（替代力导向）：主线卡（起点→阶段→终点）按学习进度水平排列在 `MAIN_Y=350`；知识点按父阶段分组、上下两行挂载（±150px）；列宽由该阶段上下行较多的一行决定（每张卡 204px 间距，防叠卡）；缺父阶段的孤儿知识点挂主线末端之后，旧类型节点兜底排第二排——保证任何数据都不吞节点
- **公共卡片函数 `drawLpCard`**：技能树与线性共用单一实现（168×52 白底圆角卡 + 左侧状态色条 + 投影，主线/目标卡蓝底白字），消除同款样式双实现；技能树原 43 行内联绘制块改为调用它
- **三种连线 `lpEdgePath`**：主线=水平直线裁到卡片边界 + 橙色箭头（统一指向学习进度）；挂载线=S 形三次曲线（与技能树曲线观感一致）；其它=直线裁卡片边界
- **交互对齐卡片语义**：点阶段卡高亮本组知识点（无关卡片整组淡化到 0.2）、悬停 tooltip 看全名/掌握度/描述、图例更新为卡片版说明
- **删除堆积代码**：硬编码"云运维"词表分支（4 处重复，与树口径统一后 `existing_kp + original_kp_id` 已完整覆盖）、节点拖拽、tick 回调、节点下方描述文字标签，文件净减约 400 行

## CodeReview 结果与修复（1 轮）

2 警告 + 2 提示 + 1 既存项，全部采纳修复：
1. 高亮子节点集合误含主线相邻阶段（计数虚高、相邻卡跟着亮）→ 收集时跳过 main 边
2. 切 Tab 重绘后 `currentHighlightedStage` 未复位 → 再点同一 stage 走"重复点击=复位"空转，表现为"点了不亮"；两个渲染入口统一复位
3. 主线箭头方向按 level 判定与坐标排序口径不一致（同 level 并列可能画反向箭头）→ 改按已定坐标 x 判定
4. 旧类型节点在退化数据下坐标重叠成一张 → 加保底步长
5. 阶段信息框名称未转义（既存）→ 与 tooltip 同口径 escape
