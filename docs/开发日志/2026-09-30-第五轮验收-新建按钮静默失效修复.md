# 2026-09-30 第五轮验收：网课笔记"新建文件夹/新建文件"点击无反应修复

## 一、用户反馈

> 网课笔记里面，文件结构上新建文件夹没反应，新建文件也没反应，点了都没反应。

## 二、排查过程（事实链）

1. **按钮与函数**：`online_course_notes.html` 中按钮内联 `onclick="createNewFolderInRoot()"` / `onclick="createNewNoteInRoot()"`，函数体在模板 L4648-4732，内部经 `window.pybridge.createNewFolder/createNewNote` 调后端。
2. **桥与后端排除**：CDP 现场直调 `window.pybridge.createNewFolder(...)` 成功建出文件夹 → 桥方法（api.js `/api/vault/folder|note`）与后端端点（routes_bridge.py）链路完好，问题在前端。
3. **语法排除**：取运行时渲染后的片段（450,414 字符），抽出两大 `<script>` 块交 `node --check`，全部通过 → 不是脚本整体解析失败。
4. **根因锁定**：CDP 探测 `typeof window.createNewFolderInRoot === 'undefined'`。模板主逻辑包在 L1853 `(function() { 'use strict';` ~ L10422 `})();` 的大 IIFE 内，**IIFE 内的函数声明不在全局作用域**；而 HTML 内联 `onclick` 在全局作用域求值 → `ReferenceError: window.createNewFolderInRoot is not a function` 只打到 console（用户不可见），表现即"点了没反应"。页面本有"IIFE 末尾统一暴露"模式（如 `window.p3ForcePreviewRefresh = ...`），但这两个按钮及另外 4 个入口新增时漏挂。
5. **全量缺口扫描**：写临时脚本比对"模板内所有 `on*="…"` 内联事件引用的函数名 vs IIFE 内 function 声明 vs window 暴露集合"，缺口共 **6 个**（不止用户报的 2 个）：
   - `createNewFolderInRoot`、`createNewNoteInRoot`（用户报出的新建按钮）
   - `selectFile`（jsTree 相关内联调用）
   - `retryEvaluation`、`retryQuestionGeneration`（评估/出题失败后的重试按钮）
   - `addDebugLog`（调试日志按钮）

## 三、修复

`server/templates/pages/online_course_notes.html`：在最外层 IIFE 末尾（所有嵌套 IIFE 关闭之后、`})();` 之前）按页面既有模式补暴露块，6 个函数一律 `window.xxx = xxx;`，并加注释说明清单来源（静态扫描）与"内联事件必须挂全局"的约束。**仅此一个文件，纯增量 +10 行，未改动任何既有逻辑。**
