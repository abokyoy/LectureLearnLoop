# 2026-09-29 悬浮窗与主面板录音笔记二期（实时保存 · 正文入库 · 双端同引擎）

## 需求回顾（用户原话要点）
1. 悬浮窗状态机：开始按下变"录制中"不可点；新增暂停键；停止改"完成"，点击提示"正在保存学习笔记"。
2. 学习笔记自动保存：ASR 出几句即防抖保存；录制中约每分钟兜底写入。
3. 点开始时选择/新建目标笔记（独立窗口）；选定后醒目显示"笔记保存到 <文档>"。
4. 笔记双存：MD 文件落盘 + 正文同步进用户隔离数据库（notes 表此前只有元数据）。
5. 主面板打开录制中的笔记可见实时更新（轮询），缓解"没记上"焦虑。
6. 录制中截图（全屏/框选）实时嵌入笔记。

确认决策：轻量轮询(3-5s)；范围=悬浮窗+主面板；独立 Electron 选择窗；主面板实装真录音
（原 pybridge 录音为死代码——electronBridge 从未定义，以 llAsr 同源引擎替换）。

## 架构与关键设计
### 数据模型（PG+SQLite 双后端）
- `notes` 加列：`content TEXT`、`recording INTEGER DEFAULT 0`、`word_count INTEGER DEFAULT 0`。
- PG：schema_postgres.py CREATE 内加列 + `ADD COLUMN IF NOT EXISTS` 幂等 ALTER + `idx_notes_recording`，
  服务启动 init_postgres_schema 自动补列；SQLite：knowledge_management.py 轻量 try/ALTER 迁移。
- `updated_time` 由 Python 统一写 UTC 'YYYY-MM-DD HH:MM:SS'（轮询水位），双后端语义一致。

### 端点（routes_notes.py 蓝图，全部 require_auth + g.user_id 隔离）
- `POST /api/notes/autosave`：写 MD 文件 → upsert 库正文，返回 {success, updated_time, note_id, note_uuid}。
- `GET /api/notes/content?path=`：轮询权威源，库优先（source=db），无记录回退文件（source=file）。
- `GET /api/notes/list`：DB ∪ vault 磁盘 .md，供选择窗。
- `POST /api/notes/recording {path,on}` / `GET /api/notes/active`：录制中标识（横幅数据源）。
- 路径统一 `_bridge_path` 校验必须位于用户 vault root 内，越界 403（穿越攻击已测）。
- 旧写通道同步：`/api/vault/rawfile` PUT（MD 类）与 `/api/vault/screenshot`（note_path 追加后）
  均同步 upsert 入库，保证文件与库一致。

### 单一写者原则（防双写覆盖）
录音会话内容（转写全文/段落总结/截图）全部由客户端引擎 buildContent 全量 → autosave 写入；
截图**不再**带 note_path 让服务端追加，而是拿返回的 markdown 调 `recorder.addScreenshot()`
纳入会话块——否则服务端追加与客户端全量覆盖互相打架。

### 共享引擎 static/js/recorder.js（LLRecorder）
- 状态机 idle ⇄ recording ⇄ paused；暂停仅门控 _feedInt16/文件游标，不关 WS 会话。
- 实时保存：final 句防抖 1.5s + 周期 60s 兜底；saveNow Promise 链串行化防交错。
- start 时读既有正文为 base，会话块以 `\n\n---\n\n` 追加其后（选择已有笔记不丢旧内容）。
- done：提示"正在保存学习笔记" → 末次全文保存 → 清 recording 标志 → 关会话 → 回 idle。
- 事件总线 onEvent {status/state/interim/final/saving/saved/error/done}，UI 只做渲染。

### 桌面端
- `llNotePicker.open()`：main.js 仿 capture:selectRegion 的 Promise 模式开 460x600 置顶窗
  加载 /note-picker；选择页回传 {action:'open'|'new', path, name}（new 已在页内经 autosave
  创建并重名检测），ipc notepicker:choose/cancel 收敛；悬浮窗由谁调起决定隐藏/恢复。
- note_picker.html：列表 /api/notes/list + 搜索 + 录制中徽标 + 新建（重名拒绝防覆盖）。
- 悬浮窗高度 480→560 容纳三态按钮与横幅。

### 前端两端
- overlay.html：开始/暂停/完成 + 按下态样式 + "📝 正在保存到 <doc>（已保存 hh:mm:ss）"横幅；
  非 Electron 回退 POST /api/vault/note 新建。
- online_course_notes.html：window.toggleRecording/start/pause/resume/stopRecording 整体重接
  LLRecorder（保留函数名兼容壳）；顶部横幅；截图走 llCapture；**预览轮询 4s**：
  updated_time 水位变化才重渲染（isEditMode/编辑焦点内不打断），截图后强制刷新一次。

## 坑与教训
1. **notes 表"存在即已登记"陷阱**：老库 notes 行只有元数据无正文——轮询权威源必须判
   `content IS NOT NULL` 而非仅判记录存在，否则读空正文当作最新（get_note_record 已处理）。
2. **双写覆盖**：screenshot 服务端追加 + 客户端全量 autosave 会互相抹掉；以"单一写者"收敛，
   服务端追加通道仅保留给非录音场景（且追加后立即 upsert 保持库一致）。
3. **死代码发现推动范围确认**：主面板 pybridge 录音委托 electronBridge（从未定义）——
   改造前必须先验证"现有入口是否真的活着"，避免在死路上叠加功能。
4. psycopg2 异常归一教训延续（见 2026-09-28 日志）：类名匹配不可靠，用 isinstance 类层级。
