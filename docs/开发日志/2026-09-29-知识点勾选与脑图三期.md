## 需求（用户原话归纳）

## 坑与教训
- HTTP 自证脚本 GET 调用把 token 传入 `req()` 的位置参数 data（第三参是 body）→ 读回 401 连环 5 断言 FAIL；教训：封装含多可选参数的请求函数时，token 等关键参数一律用关键字传参。
- mock LLM 返回固定代码时，隔离断言不能假设"知识点名出现在正文"（代码内容来自 mock 而非入参），改断言标记段存在性。
- prompt 中 root 双括号合法但要求"禁括号"针对普通节点，标题必须服务端预清洗，否则模型把引号/括号带进 root 行。

## 约束与后续项
- 脑图基于**勾选**知识点（与部分保存同口径）；录音中禁止生成（409），完成后再生成。
- 脑图段落标记依赖 MD 预览渲染；用户手工删除标记注释会导致下次生成改为追加。
- LLM 输出的 mindmap 若仍有个别语法不合（模型自由度高），前端回退显示源码 pre（既有 try/catch），可再次点击重新生成。
