# 2026-10-12 考卷内容呈现三修复（v0.1.8，用户验收第三轮反馈）

## 用户反馈（业务语言）

1. 练习助手考卷里题干带公式时**原样显示 `$x_1$` 源码**，不对。
2. 填空题也应该提供**拍照上传**——填空的答案可能是公式，键盘根本输不了。
3. 这次生成的题里有围绕笔记图片出的题（如"红色线一侧可以通过什么方式得到""第三个蓝色保险与什么要素有关"），**图必须显示在题干里**，否则学生看不到出题依据。用户裁定方案：**A 先行 + B 智能兜底**（默认文本出题，选段含可读图片时自动切视觉模型看图出题）。

## 改动内容（按三段链路）

### 一、考卷富文本渲染（base.html）

- 新增 `quizRichHtml/quizRichBlock/quizRichInline/finishQuizRich` 渲染管线：图片引用先摘成私用区占位（防手写 MD 正则咬坏）→ 公共件 `MdRender.extract` 公式保护 → 既有 `formatMarkdownContent` → 图片占位回填为 `<img data-quiz-img-path>` → `innerHTML` 后统一 `applyMath`（KaTeX 本地 vendor）+ `bridge.getImageAsBase64` 异步水合（`isConnected`+`hydrated` 双守卫防竞态）。
- 接入点：答题页题干/选项、结果页题干/正确答案/AI 点评/答案解析。MdRender/katex 缺失时整体降级原文展示，不阻断。
- 注意：公共件货币防误判规则照旧（`$2ab$` 以纯数字开头不当公式），与错题/知识库口径一致。

### 二、填空题拍照上传（前端 base.html + 后端 routes_bridge.py）

- 填空卡片加与简答同款三件套（拍照按钮/文件框/缩略图区）；作答同步泛化到 input（存 `文字\n\n![手写解答](rel)`，输入框本身保持纯文字）；输入框 placeholder 提示"公式输不了可拍照"。
- `_grade_practice_set` fill 分支：作答含 MD 图引用 → `_resolve_vault_images` 有效图走视觉看图批改（与简答同 `_call_vision` 计费链，评审后场景名区分「填空题/简答题拍照判分」）；无图/坏图回落本地精确匹配，判分口径不破。
- 评审 W-1 修复：`restoreQuizFromHistory` 照片提取泛化到 fill（原只认 short，恢复后编辑填空会把照片引用静默丢弃导致判分走偏）。

### 三、图题：图进题干 + 看图出题（online_course_notes.html + routes_bridge.py）

- 笔记图片占位 `<img>` 增加 `data-ll-src`（encodeURIComponent 原路径，与 pm 侧 `data-nb-src` 同思路）；`resolveNoteImgSrc` 挂到 window 供菜单片段复用。
- 新增 `llSelectionMarkdown()`：选区含笔记图片时克隆选区、把图片替换为标准 `![名](vault相对路径)` 文本节点再离屏 innerText 提取；无图/异常回退纯文本——**只对「开始练习」通道生效**，深入学习等其它菜单零影响。
- 新增 `llNormalizeNoteImgWiki()`：笔记全文兜底把 Obsidian `![[名]]` 归一化为标准 MD（与主渲染器同口径，保证后端可提取）。
- 出题 prompt 增「图片规则」段：需看图作答的题必须**原样复制**图片引用进题干，禁止编造路径；与图无关的题不得提图。
- `quiz_generate`：选段含可读图片（最多前 4 图）自动切 `_call_vision` 真"看图出题"；积分不足直接返回提示，其它视觉异常降级文本模型；成功日志带 `vision` 标志。

## 已知限制

- `$2ab$` 这类以纯数字开头的行内"公式"沿用公共件货币防误判，原样显示（数学惯例不以纯数字开头写行内公式）。
- 看图出题按用户裁定为兜底路径：仅当选段真的带可读图片才触发，费用走视觉模型同一计费链（Qwen3-VL 兜底）。
- 考卷渲染管线与 AI 消息通道同基于 `formatMarkdownContent`（正则拼接、对 LLM 文本不做 HTML 转义），既有风险面未扩大也未收敛，评审建议 S-2 记录在案未动（改动会影响所有既有富文本行为，需单独立项）。
