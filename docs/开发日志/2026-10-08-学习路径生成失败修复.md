# 2026-10-08 学习路径生成失败修复（知识脑图 → 梳理知识点）

## 问题（用户报告）

点击「知识脑图」再点「梳理知识点」（生成学习路径）报错「生成学习路径失败」，功能不可用。

## 根因（全部来自代码实证）

`server/knowledge_management.py` 中生成学习路径时调用 `_get_knowledge_points_by_subject(subject_name)` **漏传 `user_id`**，落到默认用户查知识点 → 真实用户查到 0 个知识点 → 生成结果为 None；接口层对 None 没有守卫，返回 HTTP 200 `{data:null}`，前端只能报笼统错误。

排查中还遭遇**Windows 双绑定端口劫持**（掉坑笔记 P051）：一个 10/8 的旧 python 进程与新进程同时监听 6001，请求被旧进程接走，造成"改了代码仍返回旧行为"的假象；枚举全部 python 进程比对启动时间后杀光残留、重拉服务，新代码行为才显现。

## 修复内容（业务语言）

- 生成学习路径时按**当前登录用户**查知识点，与脑图/统计等模块同一口径；
- 学科无知识点等生成不出结果的情况，接口明确返回 500 + 具体原因文案（如「该学科暂无知识点，请先提取知识点」），不再让前端猜。

## 验证

- 断言脚本 `server/tests/_lp_postcheck.py`（保留作可复用回归）：修复后 HTTP 500 + 明确文案，PASS；
- 独立 CodeReview 子代理评审：PASS 无阻塞（user_id 透传覆盖所有调用点、守卫不可绕过、无知识点时短路不消耗积分、与脑图同口径）；
- 排障教训入掉坑笔记：P051（双绑定劫持）、P052（jsonify ensure_ascii 中文断言永远 False，需 r.json() 解析后断言）。

## 涉及文件

- `server/knowledge_management.py`（user_id 透传）
- `server/routes_knowledge.py`（None 守卫 + 明确错误文案）
- `server/tests/_lp_postcheck.py`（新增断言脚本）
