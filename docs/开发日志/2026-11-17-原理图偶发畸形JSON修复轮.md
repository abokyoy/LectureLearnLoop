# 2026-11-17 原理图偶发畸形 JSON 修复轮

## 背景（用户实弹报障）

课文页点「原理图」生成失败，界面报「模型返回的内容不完整或不合格式，再点一次试试」。
真因（debug_trace 实锤）：GLM（glm-5.3-flash）返回 11236 字、HTTP 200 自然完成，但
`extract_json_object` 解析失败——**模型偶发在长 HTML JSON 字符串值里写未转义双引号
（如 class="x"）/裸反斜杠（如 JS 正则 /\d+/）**，这是 2026-11-13「偶发畸形 JSON 轮」
（裸控制字符，strict=False 已救）之外未被覆盖的另一半失败模式。

实弹重放定性（同课文 lid=5346、同 prompt_len=3853、同调用链重跑一次）：10235 字解析
全 OK——坐实**偶发**畸形而非系统性截断。

## 改动（业务语言）

1. **原理图/实验台/薄弱点报告共用的 JSON 解析层新增「畸形修补层」**：模型偶尔把
   网页代码里的引号、反斜杠直接写进返回里，以前遇到就整单作废；现在本地按结构
   启发式把这些畸形字符修好再试一次，救回来就不白等 74 秒。修不好照旧报失败，
   绝不自动重发（防双扣分纪律不变），合法返回完全不受影响。
2. **「输出被截断」检测补强**：以前只有返回里一个 `}` 都没有才判截断，但半截网页
   代码里本来就有 `}`，导致截断被误报成"格式不合"；改按花括号开合失衡判定，
   截断与畸形两种病各报各的。
3. **失败文案分流**：真因是"模型输出被截断（容量不足）"时原样告诉用户，不再一律
   "再点一次试试"（重跑照样同处砍断，误导）；其他格式问题保持友好文案，内部
   报错细节不外泄。失败日志补记返回体首尾 80 字，下次定性不用重放。

## 业务变更（对用户的可见差异）

- 原理图/交互实验/薄弱点报告遇到模型偶发畸形返回时自动救回，不再白扣一单。
- 真截断时提示改为「模型输出被截断……」，用户/老师能看懂该去调上下文而不是反复重点。

## 已知限制

- 修补层是启发式：裸引号恰好紧贴逗号（`..."，` 形态）仍会误判闭合而救不回，
  此时落回原失败文案（不产生静默半成品），偶发概率低，暂不加深修。
- llm_calls 日志 response_preview 仍只存 100 字（全量落盘有敏感与体积代价），
  事后定性依赖本轮新增的 raw_head/raw_tail 失败留痕。
