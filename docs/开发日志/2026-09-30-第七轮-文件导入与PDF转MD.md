# 2026-09-30 第七轮：文件导入（PDF/MD/TXT）与 PDF 转 Markdown

> 需求：网课笔记「文件结构」标题行新增"导入"按钮，支持 PDF / Markdown / TXT 一键导入到个人知识库；PDF 自动转成可学习的 Markdown 笔记。

## 一、业务口径（与用户逐项确认，1a 2a 3a 4a）

1. **PDF 产物结构**：转换后生成**同名 .md** 落在目标文件夹（可直接学习），**原 PDF 移入同级 `附件/` 子目录**留档；MD 内的图片引用改写指向 `附件/` 中下载回来的图片。
2. **图片右键学习**：本轮只保证导入产物中的图片在预览中**正常显示**；"右键图片发起学习"拆为二期。
3. **OCR 服务 Key**：复用 AIFinFlowX 已申请的 PaddleOCR-VL  token，写入 `server/.env`（不入库不入代码）。
4. **多文件**：一次可选多个文件，各自独立上传、独立任务、状态条逐行显示进度（队列式）。

**落点规则**：未选中→vault 根目录；选中文件夹→该文件夹下；选中文件→该文件所在文件夹。落点在点击按钮瞬间一次性解析冻结（防止弹框期间树刷新改变选中态）。

## 二、实现内容（业务语言）

- **入口**：文件结构面板新增"导入文件（PDF/MD/TXT）"按钮（upload_file 图标），文件选择框限 `.pdf,.md,.txt`、可多选，单文件上限 50MB。
- **MD/TXT**：落盘（GB18030/UTF-16 自动识别转 UTF-8；重名自动加 `_2/_3` 序号）→ 同步写入笔记库（notes 表 upsert），完成后立即在文件树可见并自动打开预览。
- **PDF**：原件存 `附件/`，后台任务提交 PaddleOCR-VL Job API → 轮询解析结果 → JSONL 转 Markdown（版面块/公式/表格→MD，图片下载进 `附件/` 并改写引用）→ 同名 .md 落盘并入库 → 前端 3 秒轮询任务状态，状态条显示 ⬆️上传 / 🔄转换 N/M 页 / ✅完成 / ❌失败（含原因）。
- **渲染器扩展**：笔记预览对 `附件/`、`截图/` 等相对路径图片按笔记所在目录解析并走 `/api/vault/image` 以 data:img 内嵌显示（导入的图文笔记无需手动挪图）。
- **任务治理**：服务重启时把中断任务置为 failed（"请重新导入"）；7 天前任务记录自动清理。

## 六、交付后用户验收反馈修复（2026-10-01）

用户真实使用中报两个问题，均从日志/探针取证定位后修复（掉坑笔记 P038/P039）：

1. **"点导入没反应"**：实为 15:13 导入时 V2RAYN 瞬时 SSL 抖动，worker 轮询一次失败即判死整单（❌），旧失败行残留干扰后续体验。修复：轮询/下载区分瞬时与永久异常，连续 12 次（约 1 分钟）失败才判死；新导入开始时自动清旧终态行；失败时自动删除预占空 .md。
2. **转出 MD 只剩零碎片段**：用户样本是"网页打印导出的超长单页 PDF"，内嵌完整文本层；PaddleOCR-VL 视觉模型对整页降采样只认出 719 字碎片（非丢页 bug，是路径不匹配）。修复：**PDF 转换改为文本层优先**——pypdf 直读内嵌文本，总字符≥300 本地秒转（零误差、不耗额度）；不足才回落视觉 OCR（扫描/拍照版）。新增显式依赖 pypdf。
3. **验证**：pytest 12 项全绿（新增：抖动重试、占位清理、文本层直转跳过远端、扫描件回落 OCR 四个用例）；用用户桌面同一份真实 PDF 走运行中服务端到端复核：产物 **4350 字完整正文**（此前 719 字碎片），临时用户已清理；用户库内旧低质产物与空占位已删除。
4. **二轮验收反馈：文本层"完整但乱"需清洗**（掉坑笔记 P041）：重导后正文虽全但不可读——① 版面硬换行把句子腰斩（168/219 行无句末标点）；② 字体 ToUnicode 映射出康熙部首变体字（⼈⾼⻢⻓等 155 个）；③ 公众号打印页侧栏/广告/尾部推荐位文字混入正文。新增 `postprocess_pdf_text_layer()` 三段清洗：NFKC+手工部首表归一正字；软换行合并重排成段（句末标点断段、纯英文标题行独立、URL 跨行不插空格）；装饰行特征剔除+尾部推荐位区丢弃。用户库内笔记已从附件原件重提取修正入库（3666 字/50 段，零残留变体字）。新增后处理断言用例 3 个，pytest 15 项全绿；服务已重启加载新管线。
   - 已知限制：装饰行清单是公众号类版高置信特征，极小概率误杀以同词句开头的正文；图文混排版中图片绝对定位的文字块可能仍按内容流顺序而非视觉顺序排列。
5. **三轮验收反馈：PDF 内嵌图片未导入**（2026-10-01，掉坑笔记 P042）：文本层路径此前只提文字不提图。新增内嵌图提取：解析页面内容流跟踪 q/Q/cm 矩阵得每张 Image XObject 的页面 top_y；与文本 run 的页面坐标（tm 经 CTM 变换）做降序分桶+比例秩映射，把图按视觉位置插入正文；PIL 解码存 `附件/`，MD 写 `![图片](附件/img_…)`。噪声过滤：初版按短边<120px 图标、近正方形≥250px 二维码/名片图剔除（本样本 9 图去 6 留 3）；**与用户对齐后改为保留全部图片**（新增开关 PDF_IMG_NOISE_FILTER 默认 False，过滤逻辑保留但默认不启用，本样本 9 图全提）。坐标不可用时兜底追加页尾。新增显式依赖 Pillow。验证：真实 PDF 复核关过滤后 **9 张图全提取**（3 正文图表+3 头像图标+3 二维码），PIL 逐张验证尺寸/像素正确；pytest 16 项全绿（新增带图 PDF 端到端用例）；CodeReview 子代理评审——采纳补 Pillow 依赖声明；用户库现有两份笔记已从原件带图修复入库（db sync True），服务已重启加载新管线。
6. **四轮验收反馈：桌面端图片“全部加载失败”**（2026-10-01，掉坑笔记 P043）：图片文件与引用都已在磁盘，但 Electron 打开笔记时 9 图全显“图片加载失败”。取证分两步：① 服务端签发 JWT 直打运行中 6021 `/api/vault/image`，四种路径形态（相对/绝对/正反斜录/vault 前缀）均 success=True → 排除后端；② CDP（Electron --remote-debugging-port）注入 Runtime.evaluate 读真实 `<img>.alt`，发现 alt=“图片加载失败: %E9%99%84%E4%BB%B6/img_…” → 拿到两个前端根因：**（a）** 点笔记走的加载器 `loadFileInSelectFile` 用裸 `marked.parse`、未调用带图片 base64 后处理的统一渲染器 `renderMarkdownContent`，且 `currentFilePath` 赋值晚于渲染；**（b）** marked 将中文路径段 URL 编码，与 `getImageAsBase64` 内 `encodeURIComponent` 叠加二次编码，后端目录名解不回真实“附件”。修复：该加载器渲染前先设 `currentFilePath` 并改走 `renderMarkdownContent`（保留回退）；`resolveNoteImgSrc` 先 `decodeURIComponent` 还原真实文件名；补 `renderMermaidDiagrams`（CodeReview 发现统一渲染器会把 ```mermaid``` 转成待出图 div、该加载器缺后续出图处理会退化）。CodeReview 子代理评审（结论：可接受，唯一应修项 W1=mermaid 已采纳）；pytest 16 全绿（后端未改动无回归）；真实登录桌面端 CDP 回测：9 图全 real（data:image/png）、fail=0。服务与桌面端已重启加载新代码。

## 七、第七轮追加需求：导入菜单升级——DOCX/图片本地导入 + URL 抓网页转笔记（2026-10-01）

> 需求：“导入”按钮升级为下拉菜单；本地导入增加 DOCX 与图片两种类型；新增“从 URL 导入”，抓取网页（重点微信公众号文章）自动转成笔记。

### 业务口径（与用户确认）
- 图片导入 = **仅嵌入图片建新笔记，不做 OCR**（Q21）；
- URL 抓不到时 = **明确报错并提示改走本地导入，不引入浏览器兜底**（Q22，不装无头二进制）；
- DOCX/URL 转换均为**纯本地/纯 HTTP**，不耗任何远端额度。

### 实现内容（业务语言）
- **入口升级**：“导入”点击弹出下拉菜单（本地文件导入 / 从 URL 导入）；本地文件框 accept 扩为 `.pdf,.docx,.md,.txt,.png,.jpg,.jpeg,.gif,.bmp,.webp`；URL 弹窗支持一次粘多行（每行一条），逐条建任务复用同一状态轮询（新增 🔗抓取中 状态）。
- **DOCX**：原件存 `附件/`，后台线程 mammoth（DOCX→HTML 含内嵌图）→ markdownify（→MD）纯本地转换；内嵌图解码存 `附件/img_<task>_<n>.<ext>` 同 PDF 命名规则，表格保留 MD 表格，失败清理空占位。
- **图片文件**：即时同步处理——原图存 `附件/`，新建 `<原图名>.md` 嵌图引用并入库，任务直接 done；文件名含空格时引用做百分号编码保证渲染。
- **URL 导入**（新端点 `POST /api/vault/import-url` + `_url_worker`）：浏览器 UA 拉 HTML（超时 30s、体积上限 20MB）→ 微信预处理（懒加载 `data-src` 回填、代码块占位还原、标题取 `#activity-name`）→ trafilatura 正文提取（与正文容器 markdownify 版双通道择优，取图片保留更全者）→ 远程图逐张本地化存 `附件/`（mmbiz 图床去尺寸后缀取原图，单图失败保留远程 URL 不整单失败）→ 笔记名 = 清洗后标题（重名加序号）。失败文案进任务 error 可见：不可访问/反爬验证页/正文不足 50 字/非网页直链，均附本地导入指引；端点与重定向逐跳防 SSRF。
- **新增依赖**（纯 Python 轻量 pip 库）：trafilatura / markdownify / mammoth / beautifulsoup4（显式声明）+ lxml_html_clean。

### 质量闭环
- **CodeReview 子代理评审**：2 项必修全部吸收——**R1** `_fetch_html` 原 `allow_redirects=True` 使 SSRF 预检可被 302→内网绕过，新增 `_safe_get` 重定向逐跳 `is_safe_http_url` 复检（页面与图下载同源共用）；**R2** 图片导入文件名含空格使 MD link destination 不合法、marked 不渲染，引用改百分号编码（落盘仍用原名）。建议项本轮顺手处理：抓取/单图 20MB 体积上限、前端轮询先验 `r.ok` 防未捕获 rejection、bs4 显式入 requirements；余下（每任务一线程并发预算、同名竞态占位）进后续。
