# 2026-11-16 实弹学习反馈轮：举手发言 PTT + 讲了没写镜

## 背景

用户半小时实地学习（机器学习→矩阵基本概念追问）后反馈三问题：

1. **追问阶段板书不更新**——「讲到矩阵基本运算时板书不再跟着更新，一直在一问一答，不画板书不画图」；
2. **一个问题两三句就停**——「需要学生说继续才接着讲，感觉问题没讲完就停住了」；
3. **点击说话被抢话**——「话没说完它就接话了」。用户明确裁定交互：点「举手」后系统必须持续聆听，
   直到点「发言完毕」才提交，按键在 举手↔发言完毕 两态间切换。

## 根因（全部代码实锤）

1. 抢话：手动模式点「说话」后走 `listenStart('auto')`——判停权在云端服务端 VAD，
   学生换气/想词零静默即被提前提交 STT，老师接话。
2. 板书脱节：服务端只有「写了没讲镜」（连写≥2 卡不讲解拦嘴），没有反方向的
   「讲了没写镜」；一问一答循环里老师没有任何上板压力。
3. 两三句就停：回答长度大头由小智云 console 提示词控制（[推测]，已如实告知用户，
   console 加提示句是最有效一刀）；客户端 lever 为工具描述常驻纪律 + 镜检。

## 修复

### 客户端（desktop/xz_voice.js + xiaozhi_voice.html）：举手发言 PTT 协议

- 待机=无听话窗且零上行（旧「静音帧保活」手法随 VAD 窗一并废除）；
- 举手=`abort + listenStart('manual')`（mode=manual 告诉云端不得自行判停，持续收流）；
- 发言完毕=`listenStop()` 整段提交——本路发言唯一提交点；引擎 emit `talk/commit` 事件，
  面板提示「发言已发送，等老师回答」；
- 老师 tts start 自动闭麦兜底保留；回答落地后 manual 不自动开窗（下句由举手主动开始）；
- 边界（评审修复）：退下一律闭麦归位；连接未就绪举手拒绝不置位；断连中提交发 `lost`
  不发虚假 `commit`（面板提示「这句没有发出去」）；重连 onReady 按 micWinOpen 重开
  manual 窗或归零陈旧 listenOpen；
- 面板按钮三态：打断（auto）/举手/发言完毕（manual），模式选项文案改「举手发言」；
- 声控打断（auto）模式行为保持现状不变。

### 服务端（server/services/lecture_board.py）

- **讲了没写镜**：`q_unboarded` 学生每句 +1（上限 9），任何上板/改写/擦板动作清零；
  ≥2 时 execute_tool 尾链在工具返回拦嘴「答了 N 次追问黑板一个字也没添…每答完一问
  挑关键结论 board_write 上板」；只盯当下不翻旧账，老师口播不计数；
- **追问纪律入取料工具描述**（每轮常驻老师上下文）：讲透一个问题（结论→为什么→举例子）
  再停嘴，别回两三句就停下等学生催「继续」；答完把关键结论上板（描述保持 ≤400 字符）。
