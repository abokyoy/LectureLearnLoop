# 2026-10-15 客户测试 exe 打包与 9992 公网发布

## 业务变更

要给客户发一个可直接双击的桌面客户端 exe，通过互联网连接我们的网站（不再要求客户本机跑服务）。

关键决策与事实（用户裁定）：
- 贝锐穿透 `289f32s031.oicp.vip` 的 **9000-9999 为整段同端口映射**（外网 9xxx → 本机 9xxx，无需逐条建线），但回源走局域网 IP，**本机服务必须监听 0.0.0.0**（只监听 127.0.0.1 时外网表现为 ECONNREFUSED，曾误判为"没有映射线"）。
- 网站主服务从 `127.0.0.1:6001` 迁到 `0.0.0.0:9992`，公网入口 `http://289f32s031.oicp.vip:9992`。9991 仍归手机拍照服务，互不影响。

## 改动内容（业务语言）

- 桌面客户端服务器地址改为三级解析：`LL_SERVER` 环境变量 > 随附 `server_url.txt`（打包时写入公网地址，改地址无需重打包，直接改 txt）> 本地默认 127.0.0.1:9992。开发流程完全不受影响。
- 打包脚本（p7_package.ps1）默认注入客户版公网地址；断线提示文案改为客户语境（"检查网络/联系管理员"，不再显示"请先运行 python server/app.py"）。
- 全项目端口口径 6001 → 9992 统一（.env、config.py 默认值、start_app.ps1、两个调试脚本、app.py 注释）。
- Flask 监听 0.0.0.0（暴露面由 JWT 认证控制，用户明确裁定）。

## 已知边界

- 客户机需能访问公网 `289f32s031.oicp.vip:9992`；本机 Flask / 贝锐客户端一停，客户就连不上（测试期可接受）。
- 语音听写（ASR）走 Deepgram 直连，客户网络若到不了 Deepgram 则该功能不可用，网页核心功能不受影响。
- 隧道为免费穿透线路，带宽/稳定性有限，正式对外需换正式部署。
- 客户注册后积分为 0，练习类消耗积分的功能需管理员在后台发放。
