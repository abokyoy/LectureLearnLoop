# 2026-10-12 知识点管理面板改造（v0.1.5）：按钮防误操作 + 相似知识点编辑自动保存

## 需求（用户原话要点）

「学」菜单提炼知识点→点保存→进入"知识点管理"面板：左边是当前笔记的知识点，点选后右边出现库内相似知识点匹配。本次改两条业务规则：

1. **按钮互斥防误操作**：只有"左边当前笔记知识点 + 右边相似知识点都选中"时，「合并知识点」才可点、「新增知识点」置灰；只选了左边知识点时反过来——「合并」置灰、「新增」可点。杜绝"没选目标就误合并""两边都选中还误新增重复点"两种手滑。
2. **相似知识点可直接编辑，失焦即自动保存**：合并前用户常发现"库里这个知识点其实就是它，但标题/描述写得不够好"。现在选中相似知识点后，点它的标题或描述就能原地改，改完鼠标一移开就自动落库，然后再点「合并知识点」——合并进来的是修正后的版本。

## 实现要点（业务语言）

- **按钮状态机**：面板内新增统一的状态刷新函数，在"选左项、换科目、右侧匹配加载中/出错/出结果、选中相似项、合并成功、新增成功、编辑保存前后"共 8 个时机重算两个按钮的可用性。规则严格互斥：合并=左右都选中；新增=只选中左边。
- **编辑即落库语义**：标题/描述的自动保存走真实后端接口**立即生效**——即使之后不点合并（比如改完反悔去点"新增"），库内那个知识点的标题/描述也已经是用户改过的版本。这是有意设计：编辑的对象本来就是库内已有知识点。
- **新端点（改名）**：库内知识点此前没有改名接口，新增 `PUT /api/knowledge/points/<id>/name`（名称非空、≤200 字、只能改本人的知识点）；描述端点沿用已有的 `PUT .../description`（允许清空、≤5000 字）。前端 api.js 桥新增 `updateKnowledgePointName` / 接入 `updateKnowledgePointDescription`。
- **编辑保护细节**：
  - 保存请求进行中，两个操作按钮暂时置灰（按"进行中请求数"计数，防重叠提交抢先点合并/新增）；
  - 保存失败自动回滚显示原值并提示，不会把界面改成没落库的内容；
  - 描述清空后显示占位文案「（点击添加描述）」且仍可再次点击编辑（占位文案永不入库）；
  - 输入框长度上限与后端校验一致（200/5000）。
- **安全收口（评审驱动的架构级改动）**：知识点标题从"只读展示"变成"用户可写字段"后，本页面 6 个列表渲染函数的插值点全部统一走 HTML 转义，防止有人在标题里写入脚本造成存储型 XSS。断言里用带 `<&>"'` 的恶意名实测：入库、回显、dataset 三处往返一致且 DOM 注入元素数为 0。

## 验证（全部自动化断言，无需用户手动测试）

- 断言集 `desktop/v015_kp_panel_assert.js`（留存为回归资产）：**30/30 ALL PASS**（后端 10 项 + 面板 UI 20 项）。UI 侧走真实页面链路：打开笔记→提取结果注入（免耗 LLM 积分）→保存进面板→选科目→点左项→右侧相似命中→编辑标题/描述失焦落库→合并→再走新增，含数据库独立复核（改名落库、新点入库、合并后 sources 关联当前笔记）。
- 相似匹配断言不依赖 Ollama：Ollama 停机时后端自动回退字符相似度启发式，完全同名给 0.99 分，右列表首位必命中预置的同名库内点。
- CodeReview 子代理两轮：一轮 2 Major（空描述后零高度点不中无法再编辑；标题变用户可写后的裸 innerHTML 注入面）+ 6 Minor（其中 2 项经论证豁免：再点标题=继续编辑符合直觉；updated_time 写法与既有 merge 端点同式且全库无消费方）；二轮复审指出第一轮修复有 2 个渲染函数漏改 + 保存中标志应计数化 + loading 分支漏刷状态机——三修全部落地后复跑全绿。详见掉坑笔记 P059/P060。
