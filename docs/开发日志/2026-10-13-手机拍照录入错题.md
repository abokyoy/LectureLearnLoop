# 2026-10-13 手机拍照录入错题（photo-drop 局域网/公网传图）

## 业务变更（用业务语言）

新增错题时，弹窗里多了一个「📱 手机拍照」按钮。点它会出现一个二维码：

- **同一 Wi-Fi 场景**：手机相机直接扫码，打开一个极简上传页，两个大按钮——「拍照（可连续拍）」「从相册选择」。照片在手机本地压缩到长边 2000px 后直传到电脑，立刻出现在题目编辑器里，并自动走既有的 OCR 识别管线（识别文字填入题目描述）。
- **外网场景**：用户自备贝锐 DDNS/内网穿透（`289f32s031.oicp.vip`）指向本机后，把公网完整前缀配进 `.env` 的 `PHOTO_PUBLIC_BASE`，二维码地址下拉里会出现「外网」选项，手机用流量也能传图。以后部署到服务器时同样只需改这一条配置。
- 二维码是**一次性会话**：点按钮时创建，10 分钟无操作或 30 分钟绝对过期自动失效；PC 关闭弹窗立即作废（手机再传会被拒）。别人拿到二维码链接也无法读取或上传（token 与创建者绑定）。
- 支持连拍多张（每次最多 30 张、单张解码后 ≤20MB），每张独立插入 + 独立 OCR。

## 架构与安全决策

- **主 Flask 保持仅监听 127.0.0.1 不变（P006 口径）**。手机传图是独立的第二个小 Flask 实例（`services/photo_drop.py`），监听 `0.0.0.0:9991`（占用时在 9900-9999 内自适应），与主服务**同进程 daemon 线程**运行、共享内存会话表。它只有「手机页 + 带 token 传图 + /ping」三类端点，不含任何业务 API，局域网/公网暴露面被压缩到最小。
- 上传凭证 = 一次性 token（uuid4 16hex，64bit 熵，不可枚举）；只收 JPG/PNG/WebP/BMP（magic bytes 校验，RIFF 需二次 WEBP 签名）；落盘文件名服务端生成（`截图/手机_时间戳_毫秒.ext`），无路径注入面。
- 防火墙已加 private profile 入站规则 `LectureLearnLoop PhotoDrop 9900-9999`。

## CodeReview 处置（1 轮，3 Major + 3 Minor 全修）

- **M-1/m-1**：写盘与会话登记间锁空窗可产生孤儿文件、30 张上限 TOCTOU → 登记与上限判定并入同一把锁，失效/超限回滚删除已写文件
- **M-2**：`MAX_CONTENT_LENGTH` 按编码体积算导致 20MB 解码校验不可达 → 按 base64 4/3 膨胀折算
- **M-3**：前端轮询成功回调缺存活守卫（在途关窗会往已销毁编辑器插图/发 OCR）→ 与 catch 对称补 `modalCtx.photo !== ph` 检查
- **m-2**：`since` 负值经 `images[-n:]` 会重复下发旧图 → clamp 到 0 + 回归断言
- **m-3**：`/ping` 泄露端口 → 去掉 port 字段（PC 端经主服务拿端口）

## 用户验收步骤

1. 知识库 → 选学科 → 错题页签 → 「+ 新增错题」→ 点「📱 手机拍照」→ 出现二维码
2. 手机（连同 Wi-Fi）扫码 → 拍照或选相册图 → 电脑编辑器立即出现图片并开始识别文字
3. 手机可连续拍多张；点「取消/×」关弹窗后再扫旧二维码应提示「已失效」
4. （可选）配好贝锐隧道 + `.env` 后，手机关 Wi-Fi 用流量扫「外网」地址验证跨网传图
