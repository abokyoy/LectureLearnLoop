# 2026-10-04 · PDF 正文标题/题注识别二期修复

## 背景（用户产品反馈）

《机器学习实战》导入后：第一个 MD 文件（前置页：内容提要/前言/目录等）格式全部正确，但从第二个 MD 文件（正文）起格式退化——`6.5.1`、`图x-x` 等标题全是白字普通段落，`7.1` 类小节标题完全丢失。用户要求分析原因并尽量实现正文标题与图表题注的格式化。

## 诊断（探针实测，21~336 页全量扫描）

三个根因，全部有探针证据（`server/tests/_probe_body2_result.txt`）：

1. **主导字体被空格/数字 run 抢走**（134 个编号标题的败因主体）：标题汉字是黑体 SimHei 14/12pt，但行内数字与空格片段属 /BKMDOH+Arial，按字号加权的"主导字体"判为 Arial，不含黑体特征 → 标题规则不命中。
2. **正文基准字号被代码页污染**：代码/图表页大量 12pt 短碎片把基准抬到 12pt，12pt 小节标题过不了 1.15× 门槛（9 例）。
3. **矩阵变换残留异常坐标致正文误删**（附带发现的严重 bug）：344 行正文 y 坐标残留异常值（-12/0/6138 等），落入页脚带判定区间被整行误删。
4. 图/表题注实测仅 9~10pt 宋黑混合，靠字号无法识别，但行首模式规整（`图2-1 + 空格 + 文字`），可用纯文本规则。

## 业务规则变更（用业务语言）

- **正文章节标题找回并分三级**：编号标题（1.1 / 1.1.1 / 第7章）按字号相对正文基准的倍数分层——≥1.8× 一级、≥1.3× 二级、1.15~1.3× 三级，分别渲染 `#`/`##`/`###`。
- **标题识别加双保险**：整行主字体是黑体，或"行内黑体片段字号够大且覆盖行内 ≥ 半数汉字"均可认定——前者防漏、后者防正文里个别黑体强调词被误当标题（评审 Warning 修复）。`1.6 Python语言的优势` 这类拉丁占比高的标题不受影响。
- **正文基准字号防污染**：基准只按"含中文且 ≥30 字的长行"统计众数，代码行不再抬高基准。
- **图/表题注格式化**：行首 `图x-x 文字` / `表x-x 文字` → 编号加粗并独立成段；正文叙述引用（`图1-1集中展示了…`，数字后无空格）与句末带句号/问号/叹号/分号的叙述句不改。
- **修复正文误删 bug**：页眉/页脚带剔除仅作用于"合法页内坐标 + 短行（≤34 字）"，异常坐标行与正文长行一律保留。

## 改动文件

## 已知限制

- 题注识别为纯文本规则（行首编号+空格），若某书题注排版不带空格则不命中（保守不误伤优先）。
- 极端排版"标题汉字全部非黑体、仅数字黑体"理论上会漏标，本库样本不存在该形态。
- 用户需**重新导入** PDF 才能看到正文文件格式改善（已生成的 MD 不会自动更新）。
