# 2026-10-01 · 基于笔记练习/举一反三：结构化多题型页内作答

## 概述

用户实机验收发现：知识点详情页「基于笔记练习」生成的题目（选择/判断/填空/简答/应用混合）是**整段纯文本贴出，无法在网页上作答**。本轮把「基于笔记练习」「举一反三」两个通道从旧 Qt 时代的自由文本路径，改造为**结构化四题型（单选/判断/填空/简答）页内逐题作答模板**，并补齐 2026-09-29 已裁定却未在 Flask 版落实的 A 方案：三通道提交后**全部作答落库、答错自动入错题池、掌握度难度加权重算**。

## 用户业务裁定（AskUserQuestion）

- **简答题判分方式 = LLM 判分**：提交后学生答案与参考答案一起交 LLM 判对错并给一句中文点评，消耗积分。
- **熟练度评估通道保持纯选择题不变**（判分纯净），多题型能力只落在「基于笔记练习」「举一反三」两个通道。

## 后端改动（`server/routes_bridge.py`）

- **新增第七节：结构化出题与判分端点**
  - `POST /api/knowledge/points/<pid>/generate-practice`（body `source: "notes"|"analogy"`）：
    - notes → 服务端直连读取关联笔记（最多 5 篇各截 3000 字），无笔记返回 `{success:false, no_notes:true}`；
    - analogy → 从 practice_records 按题干聚合找正确率 <100% 的错题，无错题返回 `no_errors:true`；
    - 以 8 题混合题型 prompt（单选3/判断2/填空2/简答1，按此顺序）调 LLM，`_parse_llm_json_array` 剥 ```json 围栏后 `_validate_practice_questions` 逐题严格类型校验，非法即报错（与 generate-assessment 同风格）。
  - `POST /api/knowledge/points/<pid>/practice-submit`：客观题本地判分（单选=首字母大写相等；判断=`_judge_norm` 归一到「正确/错误」；填空=`_fill_norm` 去空白+大小写归一+全角标点转半角后与 `correct_answer` 按 `|`（兼容全角｜）分隔任一答案相等）；简答题批量 LLM 判分；每题调 `kms.practice_manager.save_practice_record` 落库并答错自动入错题池；难度加权（容易1.0/中等1.2/困难1.5）正确率重算 `mastery_score` 并失效脑图缓存。
  - **简答判分失败策略**：LLM 判分失败或结果不完整 → 整体报错**不落库**（避免半套留痕），用户可重试。
- **评估通道补落库留痕**（履行 9-29 A 方案）：`mastery_assessment` 循环内每题追加 `save_practice_record`，异常仅记日志不阻断。

## 前端改动

- **`server/static/js/pm_pages.js`**：删除旧的文本渲染路径（bridgePracticeText/mdLite/genPractice/showPracticeText 等），新增四题型轮播答题模板（单选 radio / 判断二选一 / 填空 text input / 简答 textarea）+ 上一题答案回填 + 必答拦截 + 判分结果页（分数圆环、答对 N/M、错题入本提示、逐题明细含 AI 点评、同步刷新掌握度与进度条）；`startNotePractice`/`startAnalogyPractice` 瘦身为共用 `startPointPractice(btn, source, 标题)`。
- **`server/static/js/api.js`**：新增 `generatePointPractice`/`submitPointPractice` 桥方法（`as:'json'`）。

## CodeReview 白盒评审（4 项 m 级健壮性修复）

- m-1 简答判分改按 index 排序后**位置对齐**回写，避免 LLM 返回 index 错位静默判错；
- m-2 practice-submit 成功响应并入 `billing_for_response()`，扣分后余额展示可刷新；
- m-3 填空判分分隔符兼容全角 `｜`（校验放行全角但判分此前只切半角）；

## 连带修复的存量生产 bug

- **`point_questions` PG GROUP BY 缺陷**（见掉坑笔记 P038）：GROUP BY 后相关子查询引用外层非分组列，SQLite 容忍、PG 报错；空结果组时子查询不执行所以此前无流水从不触发，落库上线后必 500。GROUP BY 补齐被引用外层列修复。
