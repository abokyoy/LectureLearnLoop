# 2026-09-28 用户积分与充值系统

## 需求（用户原话归纳）
1. 仿会计软件的积分换算：可配置「多少 Token = 1 积分」（默认 4000），所有 AI 操作按此扣分。
2. 需要扣分的操作：AI Chat、生成练习题、答案评判、总结、脑图、提炼知识点、录音转文字（1 分钟 = 1 积分）。
3. AI Chat 窗口上方显示积分计数器；每条回复尾部提示本次扣分；非 Chat 界面用 toast 提示扣分。
4. 每日登录赠送积分（默认 100，可配置）。
5. 充值走**卡密模式**（放弃 Stripe）：管理员批量生成卡密 → 电商售卖 → 站内兑换；100 积分 = 1 元。
6. 管理后台（仅管理员）：统一配置积分参数 + 系统级大模型。
7. 系统级 / 用户级 Key 拆分：设置页为**用户级 Key**；自备 Key 不扣分并提示；未配置或调用失败**回落系统 Key 扣分**。
8. 余额不足拦截并提示充值；管理员豁免（流水留痕）；录音转文字只走系统 Deepgram Key。

## 架构与关键决策

### 计费单点收敛（第一原则：架构收敛）
- **所有 LLM 调用汇聚到唯一入口** `LLMProviderFactory.call_llm()`，新增内部路由 `_call_billed`（有登录用户）/ `_call_legacy`（无用户上下文，如启动任务/脚本，不计费）。业务代码不得再自行扣分。
- 计费结果写入线程本地 `last_billing`，端点统一用 `credits_service.billing_for_response()` 附加响应字段：`{credits_deducted, credit_note, credit_balance, credits_insufficient}`。
- `app.py` `before_request` 每个请求入口清理上一次计费上下文（worker 线程复用，防缓存命中路径串读旧 billing）。
- **usage 缺失兜底**：部分网关不返回 token 用量，此时按 `(prompt+response) 字符数 / 2.5` 估算扣分，流水 note 标注「usage缺失，按字符估算」，杜绝免费调用。

### 数据层（5 张新表，双后端方言）
`database/schema_credits.py`：`user_credits`（余额+累计+日赠幂等日期）、`credit_transactions`（全量流水）、`system_config`（积分参数+系统大模型）、`user_llm_config`（用户自备 Key）、`activation_codes`（卡密）。SQLite/PostgreSQL 双 DDL，靠 `db_adapter` 翻译占位符与 `INSERT OR IGNORE → ON CONFLICT`。启动时建表 + 一次性迁移 `runtime_config.json` 存量密钥进 `system_config`（仅当表内无值）。

### 并发与幂等（防刷 / 防重复）
- **每日赠送**：条件 UPDATE（`last_bonus_date <> 今日`）+ `rowcount` 判定，同自然日只发一次。
- **卡密兑换**：PG `FOR UPDATE` 行锁 / SQLite 事务原子性；`active → used` 条件更新保证同一码只成功一次。8 线程并发兑换断言仅 1 次成功。
- **管理员调整 / 充值 / 扣分**：一律相对更新 `balance = balance ± ?`，防 lost update；拒绝使余额变负的调整，校验目标用户存在。

### 系统 Key vs 用户 Key
- 用户配置自备 Key（`user_llm_config`）→ 调用不扣分，但记 `delta=0, use_own_key=1` 流水供审计；失败/空结果自动回落系统 Key 正常扣分。
- 设置页留空 = 保持原 Key 不变；显式清除需 `clear_key=true`（防误删 Key 后静默回落系统 Key 扣分）。
- **掩码防护**：`_looks_masked()` 拦截含 `****`/`•` 的提交值写入密钥字段；GET 一律掩码返回，比对基准用 `effective_llm_config` 而非仅表内值。

### 余额不足拦截
- LLM 调用：预检 `balance ≤ 0` 抛 `InsufficientCreditsError`，Chat 显充值引导、非 Chat toast 提示。
- 录音：`/api/asr/config` 下发密钥前预检（不足 402 拒绝开录）；停止后 `asr-charge` **允许扣成负余额**（录音已发生，欠费后补），自报时长封顶 24h。
- 连接测试 `/api/llm_test` 同样走预检（不足不调用）。

### 前端呈现
- **base.html**：Chat 顶部积分徽章（余额 ≤ 0 变红）；回复尾部打字机播完追加「本次消耗 N · 余额 M」注脚（带 `chatSeq` 守卫，会话中断/取代不追加，防串话）；`llHandleBilling` 全局钩子（toast + 刷新徽章）。
- **api.js**：`req()` 统一 `billingHook`，白名单提取计费四字段回调；Chat 端点 `skipBilling` 避免与尾注双弹。
- **online_course_notes.html / learn_from_materials.html / overlay.html**：脑图/转写等非 Chat 场景接 `llHandleBilling` / `credits_insufficient` 分支。

### 页面
- **settings.html（重写）**：我的积分（余额卡+流水+卡密兑换+充值文案）+ 用户级 Key 配置 + 管理入口 + 总结/日志设置。**清除了历史硬编码的明文 Qwen Key**（安全整改）。
- **admin_credits.html（新建）**：积分业务参数（6 键）/ 系统大模型（掩码保存不覆盖）/ 用户积分总览+手工调整 / 卡密生成·筛选·作废。路由 `/admin/credits`（`@require_auth`），API 全部 `@require_admin`。

## 安全整改
- `routes_bridge.py config_save`：系统级密钥（deepseek/gemini/qwen_api_key）仅管理员可写，普通用户提交跳过这些键（堵住越权改系统 Key）。
- 移除 settings.html 中硬编码 API Key；密钥存储走 `system_config` / `user_llm_config`，GET 掩码返回。

## 交付说明（用户业务验收步骤）
1. 登录 → 设置页「我的积分」应显示余额（首日 +100 赠送），流水表出现「每日登录赠送」。
2. AI Chat：顶部看到积分徽章；发一条消息，回复尾部出现「本次消耗 N 积分 · 余额 M」，徽章同步减少。
3. 自备 Key：设置页填自己的 Key 保存 → 再对话提示「使用自备大模型，不扣积分」，余额不变。
4. 非 Chat（如脑图/生成练习题）：操作完成后 toast 提示本次扣分。
5. 余额耗尽：Chat 显充值引导、录音开不了并提示充值。
6. 管理员：设置页进入「管理后台」→ 改积分参数 / 系统大模型 / 批量生成卡密；用卡密在设置页兑换入账；管理员自身调用不扣分但流水留痕。

## 已知限制 / 待办
- ASR 服务端 WebSocket 帧时长对账未做（当前信任客户端停止上报的秒数，已封顶 24h），记为技术债。
- 若干低优先级 P2（时区统一 utcnow、SQLite WAL、扣分失败补记队列、兑换限流、卡密碰撞重试、void 审计、sendBeacon、服务端时长复核）本轮评估后未做，留待后续。
