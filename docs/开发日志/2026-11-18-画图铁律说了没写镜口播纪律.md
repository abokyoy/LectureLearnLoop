# 2026-11-18 实弹反馈轮：画图铁律 + 说了没写镜 + 口播术语纪律

## 需求（用户实弹验收后原话归纳，三件事）

1. 「图画得还是太少了，很多东西都是干巴巴地讲。能不能增加一个强烈约束：基本上能画图的都要画图，通过图形去讲解。」
2. 「面板里面一直在说话，但板书上没有更新——老师说话的时候，底下更新得比较少。」
3. 「专业术语说什么 A 和 B，读不出来时只说一个字，字幕里看到的也是'空格和空格'。哪怕念不出来，字幕当中也应该显示正常的格式。」

## 事实核查（问题 3 的归因链）

- 字幕链路逐段核实：云端 `tts sentence_start` 逐句下发（xz_socket.js 原样透传）→ EXE 字幕队列跟播放上报（xz_voice.js，只排队不改字）→ `/api/board/speech` → 服务端 `append_speech` 只剥控制字符+压空白（不碰 $ 等符号）。**全链不丢字**。
- [推测→已核实为] 丢字发生在小智云的 TTS 文本归一化（TN）：裸 LaTeX 符号（$A$）被归一化吞掉，下发的句子本身已是空格，且协议没有另一路原文可回补（tts start 不带全文）。
- 结论：客户端无法从根源恢复被吞的字，唯一可行杠杆是让模型**别产出会被吞的口播文本**——口播里符号必须带中文名（「矩阵A」），这同时在 console 人设提示词与客户端工具描述两层落。

## 第二轮（同日实弹追加）：镜检拦不住开局干讲——日志定位 + 锚图定场

用户重启后再测，反馈「还是光说了很久没有画图」，要求查最近日志。

### 日志实证（debug_trace.jsonl，16:05:46 指派 → 16:09:57）

逐事件重建那一轮课：
- 16:05:46 assign lesson → 16:06:19 老师取料消费 → 16:06:20~21 连写 topic+note 两卡；
- **16:06:23→16:08:12 近 2 分钟只口播（约 313 字）零工具调用**——黑板静止，即用户看到的「光说很久」；
- 16:08:12 老师终于想起来 board_draw（画图铁律生效），但连撞 3 次 geometry DSL 格式拒收（字段写错），16:08:17 第 4 次才画成。

### 定性：结构性限制，非阈值问题

所有镜检都搭 execute_tool 返回尾链递到老师嘴边，**开局老师不调工具这段窗口任何镜都送不进去**；降 260 阈值会误伤「把一张卡讲透」的合法停顿，不是正解。

### 修法：纪律前置进开课一次性指导语（不受「不调工具」限制）

改 lecture_board.py 三处文案：
- lesson/text 型指导语：建完 topic 主干卡「第二步就 board_draw 一张总览图定场」（尤其 lesson 型故意不开原理图舞台，靠这张图给学生第一眼视觉锚）；
- lesson 指导语新增独立「讲课节奏」段、「text 纪律」补句：黑板要跟着嘴走，板上没出新卡/新图前不要往下赶新内容；
- _lesson_txt_replay 重放句同步补「讲完一个关键点就上新卡/新图，别干讲不推进」。

测试：test_course_notes test_51/test_52 加正向断言（总览图定场/讲课节奏/别干讲不推进）锁住新口径防回归；32 passed。纯文案改动无逻辑变更，未起子代理评审（上轮同向改动已 PASS）。已重启 9992 生效。
