# 2026-10-14 批量新增错题（知识库·错题本）

## 业务功能

知识库选学科后，「+ 新增错题」弹窗升级为两页签：

- **单题录入**：原有方式，保持不变。
- **批量录入**（本次新增）：
  1. 「拍照 / 上传图片」支持本地多选图片（单批最多 20 张），或「手机拍照」扫码上传；上传中/就绪状态实时显示，可删除、可勾选。
  2. 勾选图片点「提取错题」进入**全屏框选**：逐张展示，开启框选后在图上拖拽画矩形，一题一框；每个框右上角显示编号与删除按钮，**删除后编号不重排**（删第 2 个后剩 1、3），新框顺延取号；切下一张图编号独立从 1 起算；最后一张点「完成」提交。
  3. 后台按记录的**归一化坐标**对原图分辨率裁剪出每题图片，逐题走智能分析管线（Paddle 版面切片 + Qwen3-VL 识别，几何题配图完整保留），每题消耗 1 次大模型积分（提交前有确认提示）。
  4. 进度条实时推进，完成后显示结果列表：**成功题默认全选**（Markdown 预览题干/答案/解析），失败题置灰注明原因（如框选区域过小）；支持全选/取消。
  5. 点「入库」：勾选的题批量写入当前学科错题库（一律为**独立错题**，不绑知识点，入库后可再编辑）；未勾选的直接丢弃。

## 业务规则要点

- 识别失败的题不毁整批：单题失败（区域过小/模型异常/原图损坏）只标记该题，其余继续。
- 框选区域不足 24 像素在服务侧直接判失败，**不消耗积分**；只有真正送大模型的题才计费。
- 批量任务绑定用户，跨用户不可见；结果在任务 TTL 内可重复查询。
- 单批上限：20 图 / 每图 10 框 / 总 50 框。

## 追加修复（2026-10-14 晚，客户现场反馈两问题）

用户实测反馈：① 点「提取错题」后框选层被新增错题弹窗盖住，无法框选；② 在弹窗外点一下，弹窗、已传图片、框选层全部消失，一切重来。

- **根因 1（层级被旧缓存吞）**：框选层的 z-[92] 是 Tailwind 新编译类，而 cl.css 引用不带版本号，客户端命中旧 cl.css 长缓存 → 框选层无 z-index 被弹窗（z-[90]，旧类）盖住。开发机 headless 测试无缓存所以全绿，客户现场才暴露。
- **根因 2（遮罩误关丢状态）**：弹窗遮罩点击直接关闭，批量上传/结果阶段无丢弃确认，与问题①叠加后用户感知为「卡死重来」。
- **修复（三处）**：
  1. `knowledge_base.html`：`#kbo { z-index: 92 }` 写进模板自有样式，不再依赖构建产物，旧缓存下也正确；
  2. `app.py` + `base.html`：cl.css 引用加 `?v=文件mtime` 版本参数（启动时计算），从此重建 CSS 后客户端自动拉新版，根治此类缓存问题；
  3. `knowledge_base.html` closeModal：批量已有图片/结果时关闭（含点遮罩）弹「关闭将丢弃本批图片与识别结果」二次确认，取消则一切保留；框选层「返回列表」不触发确认不丢数据。
- **验证**：新增定向断言 `server/tests/kb_batch_zfix_verify.py` 13/13 ALL_PASS：用 route 拦截删除 cl.css 中 .z-\[92\] 规则精确模拟客户旧缓存，断言计算样式 z-index=92、canvas 中心命中测试在框选层、旧缓存态下拖框成功；另断言遮罩确认弹窗出现/取消后数据保留/返回列表不弹确认。截图存档 design/walkthrough/b28_zindex_cached_css.png。
- **客户侧生效条件**：重启正式服务（加载新 app.py/模板）后刷新客户端即可；即使客户端仍持旧 cl.css，框选层层级也由模板内兜底保护。

## 追加增强（2026-10-15，客户实测反馈四项）

用户反馈：① 框选时应支持图片放大/缩小/拖拽移动；② 提交确认文案术语太多（「版面分析」「N 次大模型积分」用户看不懂），只需告知大概消耗多少积分；③ 质疑能否一次大模型调用识别整批（待裁定，见下）；④ 实测出现识别失败：217x27 裁剪被 Qwen3-VL HTTP 400 拒（要求宽高均 >28px）。

**修复与实现**：
1. **框选层缩放/平移**（knowledge_base.html）：工具条新增 −/百分比/+/适应 按钮，滚轮任意位置缩放（0.2x~6x）；关闭「框选选题」开关后图上拖拽=平移画布；布局从 flex 居中改 block+margin auto（避开放大后滚动死区）；坐标仍基于实时 rect 归一化，缩放不改变数学。
2. **框选默认开启**：进层即可直接拖框（旧版默认关闭、需先点开关，为客户困惑点之一）。
3. **确认文案简化**：改为「本次将识别 N 道题，预计共消耗约 (N×0.2) 积分，需要几分钟」，去除「版面分析/大模型」术语（0.2/题来自实测 token 计费口径，有「约」字）。
4. **过小裁剪下限 24→32px**（error_batch.py）：Qwen3-VL 硬限制宽高>28，27px 穿透到供应商才报错；现服务层拦截（零外呼零扣分），文案不含像素数字。

**验证**：新增 `server/tests/kb_batch_zoom_verify.py` 19/19 ALL_PASS（默认开框、195% 放大态框选归一化坐标仍精确、滚轮/按钮缩放、关闭开关后拖拽平移 scrollLeft 变化不产生新框、确认文案含「约 0.4 积分」且不含术语、取消不提交）；回归 kb_batch_ui_verify 28/28、kb_batch_zfix_verify 13/13、test_error_batch_service 10/10、test_error_batch_api 14/14 全绿。CodeReview 无 Critical/Major；截图 b29_zoom_overlay.png 识图核对。同步修正两旧脚本对 kbo-draw 的无条件点击（改幂等保护）。

**「一次大模型调用」分析结论（待用户裁定）**：积分按 token 计费而图片 token 占大头且 batching 不可省，合并调用只省提示词重复（约两成）；真正收益在等待时长（串行 N×30-60s → 一次调用）。可行方案为「多切片一次调用返回数组 + 失败逐题回退」；「原图+坐标框」方案因 VL 对大图降采样致小字模糊不推荐。

## 分组批量调用落地（2026-10-15，用户裁定：「把切片图一次全给大模型，返回一组题」）

**业务变更详述**：批量识别从「每题一次大模型调用」改为「同一源图的裁剪图分组（每组≤3 题），每组一次调用返回一组题」；组内单题失败/缺题逐题回退原单题管线，不拖垮同组已成功题。收益：整批等待时长大幅缩短（实测两题一组 VL 段仅 15.3s，旧串行需两次往返）；提示词重复开销合并，总 token 略降。分组上限 3 题的原因：输出上限 4096 token，每题全量输出约 500~1000 token，再大易截断致整组回退得不偿失。

**防串题机制**（评审后强化）：模型返回元素带题号 q；仅当 q 恰构成 {1..n} 无重复全集才采信 q（乱序归位）；否则带合法 q 的按 q 落位、重复声明丢弃、无 q 的按位置填空槽，落不满的题自然落「缺题」走逐题回退——**宁缺题回退，绝不静默串题**。

**改动文件**：
- `services/error_analyze.py`：新增 `recognize_group`（组管线）、`_build_group_vl_request`（多题清单组装）、`extract_json_array`；硬性规则 1~7 抽为单题/组共享 `_HARD_RULES`（单题 prompt 字节级不变，评审脚本实测 EQUAL）。
- `services/error_batch.py`：`_run` 重构为裁剪收集→`_chunks`(≤3/组)→`_run_group`（一次组调用+逐题回退）；失败题连带清理 Paddle 派生 `_figN` 切片（防孤儿）；原图句柄显式 close（防 Windows 文件锁）。
- 前端无改动（进度/结果结构契约不变，确认文案仍按 N×0.2 积分估算）。
