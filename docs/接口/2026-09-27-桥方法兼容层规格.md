# 桥方法兼容层规格（CorgiWebBridge → Flask+Electron）

> 来源：`e:\LLM\LectureLearnLoop_new\overlay_drag_corgi_app.py` 中 `class CorgiWebBridge(QObject)`（L89 起）。
> 前端页面通过 `window.pybridge.X(...)` / `window.bridge.X(...)` 调用。目标：Electron 兼容层 1:1 还原返回结构。
>
> **全局回调约定（务必先读）**
> - Qt `@Slot` 方法在 QWebChannel 下**永远是异步**的：无论方法在 Python 里是同步 return 还是发信号，前端都必须用"最后一个参数传 callback"取值，例如 `window.bridge.getFileStructure(function(json){...})`。
> - 部分页面（learn_from_materials.html L909/L4807 等）把 `saveMarkdownFile` 等写成 `const ok = window.bridge.saveMarkdownFile(...)`（同步取返回值）。**这在 QWebChannel 下本拿不到返回值**，属于页面写法瑕疵。兼容层为兼容此类页面，建议：这些"纯同步返回 bool/str/JSON"的方法既支持 callback 也支持直接 return（Electron 同步 IPC 或返回 Promise 均可被 `await`），双保险。
> - 少数方法不通过返回值/回调，而是**主动 `runJavaScript` 推送到全局函数**（如 `chatResponseReady` 信号、`takeScreenshot`→`insertScreenshotToDocument`、`loadTranscriptHistory`→`window.onTranscriptHistoryLoaded`、`testDeviceRecording`→`onTestRecordingFinished`）。兼容层需以 IPC/事件方式复刻这些全局函数调用。
> - 路径基准：vault 相关方法（getFileStructure/createNewNote/createNewFolder）以**进程 CWD 下的相对 `vault/` 目录**为根（`Path("vault")`），不是绝对路径；文件读写方法（loadMarkdown*/save*）直接用传入的绝对/相对路径。新后端以 `VAULT_DIR/<user_id>` 为根（见 routes_knowledge.py），兼容层需做路径映射。
> - 下方"返回"栏描述的都是 **Python 方法本身产出**（JSON 字符串/纯字符串/bool/文件名等），即 QWebChannel 回传给 callback 的那一个值。

## 二、文件树 / Markdown 读写

### getFileStructure
- 签名: `()` → `@Slot(result=str)`
- 返回: `json.dumps(structure, ensure_ascii=False, indent=2)`，structure 为**递归数组**，元素两种：
  - 文件夹节点：`{"name": str, "type": "folder", "path": str(绝对路径), "level": int, "children": [<同结构>]}`
  - 文件节点：`{"name": str, "type": "file", "path": str(绝对路径), "level": int, "is_markdown": bool, "extension": str(小写含点，如 ".md")}`
  - **folder 节点无 `is_markdown`/`extension` 字段；file 节点无 `children` 字段**。
  - 跳过以 `.` 开头的隐藏项；`path` 是 `str(item)`（含 `vault\...` 平台分隔符）。
- 行为要点: 根为 `Path("vault")`（CWD 相对），不存在则 `mkdir`。仅目录扫描，无写库。
- 页面调用示例要点: learn_from_materials.html 用 `function(jsonString){...}` 再 `JSON.parse`。后端已有 `/api/vault/tree` 但**返回结构不同**（扁平 `[{path,size,mtime}]`），兼容层须转换成上面的嵌套树并保持字段名。

### loadMarkdownFile
- 签名: `(file_path: str)` → `@Slot(str, result=str)`
- 返回: **HTML 字符串**（markdown→html）。文件不存在或异常返回**空字符串 `""`**。无 markdown 库时返回 `f"<pre>{content}</pre>"`。
- 行为要点: 用 `markdown.markdown(content, extensions=['codehilite','fenced_code'])`。不写 self.current_file_path（与 loadMarkdownRaw 不同）。
- 页面调用示例要点: 仅 backup 页/旧页用；主流程改用 loadMarkdownRaw + 前端渲染。

### loadMarkdownRaw
- 签名: `(file_path: str)` → `@Slot(str, result=str)`
- 返回: **原始 Markdown 文本字符串**；不存在/异常返回 `""`。
- 行为要点: 读取前设置 `self.current_file_path = file_path`（供 getImageAsBase64/takeScreenshot 解析相对目录）。
- 页面调用示例要点: 页面 `function(markdownContent){...}` 拿原始串自行 marked 渲染。兼容层映射 `GET /api/vault/file?path=` → 取 `data.content`（注意后端返回 `{path,content}` 需剥壳为纯串）。

### saveMarkdownFile
- 签名: `(file_path: str, content: str)` → `@Slot(str, str, result=bool)`
- 返回: **bool**（True 成功 / False 失败）。非 JSON。
- 行为要点: 设 `self.current_file_path`；`path.parent.mkdir(parents=True)`；utf-8 写文件；写后 `path.exists()` 判定成功。
- 页面调用示例要点: 既有 callback 写法也有同步 `const success = ...` 写法。映射 `PUT /api/vault/file`（body `{path, content}`），成功返回 true。

### save_file
- 签名: `(file_path: str, content: str)` → `@Slot(str, str, result=str)`
- 返回: JSON 字符串：成功 `{"success": true, "message": "文件保存成功", "file_path": str}`；失败 `{"success": false, "error": "文件保存失败", "file_path": str}`；异常 `{"success": false, "error": str(e), "file_path": str}`。
- 行为要点: 内部调用 `saveMarkdownFile`，再包成 JSON。online_course_notes.html 大量用（22 处）。
- 页面调用示例要点: 与 saveMarkdownFile 语义同，但返回 JSON（含 `file_path`）。兼容层两者都映射 `PUT /api/vault/file`，仅返回壳不同。

### createNewNote
- 签名: `(folder_path: str = "vault")` → `@Slot(str, result=str)`
- 返回: **文件名字符串**（如 `"新建笔记1.md"`，不含路径）；失败返回 `""`。
- 行为要点: 目标目录不存在则建；在 `folder_path` 下找未占用的 `新建笔记{counter}.md`；写入模板（`# 标题 / ## 概述 / ## 内容 / 创建时间`）。
- 页面调用示例要点: 页面拿返回的文件名再拼路径刷新树。兼容层需新增端点（后端无创建笔记端点），返回**纯文件名字符串**。

### createNewFolder
- 签名: `(parent_path: str = "vault")` → `@Slot(str, result=str)`
- 返回: **文件夹名字符串**（如 `"新文件夹1"`）；失败 `""`。
- 行为要点: 父目录不存在则建；找未占用的 `新文件夹{counter}` 并 mkdir。
- 页面调用示例要点: 返回纯文件夹名。B 类需新增端点。

### renameFileOrFolder
- 签名: `(old_path: str, new_name: str)` → `@Slot(str, str, result=bool)`
- 返回: bool（成功/失败）。
- 行为要点: `new_path = old_path.parent / new_name`；原路径不存在或目标名已存在返回 False；`Path.rename`；验证新存在且旧不存在。
- 页面调用示例要点: 无专用端点，B 类。

### moveFileOrFolder
- 签名: `(source_path: str, target_folder: str)` → `@Slot(str, str, result=bool)`
- 返回: bool。
- 行为要点: `target = target_folder / source.name`；源不存在或目标已存在→False；确保目标目录存在后 rename。
- 页面调用示例要点: B 类。

### deleteFileOrFolder
- 签名: `(path: str)` → `@Slot(str, result=bool)`
- 返回: bool。
- 行为要点: 目录用 `shutil.rmtree`，文件 `unlink`；不存在→False。
- 页面调用示例要点: B 类。

### getImageAsBase64
- 签名: `(image_path: str)` → `@Slot(str, result=str)`
- 返回: JSON 字符串：成功 `{"success": true, "dataUrl": "data:<mime>;base64,<b64>", "mimeType": str, "size": int(字节数)}`；文件不存在 `{"success": false, "error": "图片文件不存在"}`；异常 `{"success": false, "error": "图片转换失败: <err>"}`。
- 行为要点: 相对路径时以 `os.path.dirname(self.current_file_path)` 为基准 join；MIME 由扩展名映射（png/jpeg/gif/bmp/webp，默认 image/png）。
- 页面调用示例要点: online_course_notes 渲染笔记内嵌图片。D/C 类（可用前端 fetch 或自定义协议 `app://` 处理）。

## 四、知识点提取 / 相似 / 合并 / 新建 / 批量

### extractKnowledgePoints
- 签名: `(file_path: str)` → `@Slot(str, result=str)`
- 返回: JSON。成功 `{"success": true, "knowledge_points": [{"name","description","category","importance"}...], "total_count": int}`；文件不存在 `{"success": false, "error": "文件不存在"}`；空内容 `{"success": false, "error": "文件内容为空"}`；模块不可用 `{"success": false, "error": "知识管理模块不可用"}`；其它 `{"success": false, "error": str}`。每个知识点固定四键：`name`(←point_name/concept_name), `description`(←core_description/core_definition), `category`, `importance`(默认"中等")。
- 行为要点: 读文件→`_extract_knowledge_with_llm`→`km_system.extract_knowledge_points("通用学科", content)`（**默认学科"通用学科"**）。仅提取，不入库。
- 页面调用示例要点: 页面 `function(resultJson){ JSON.parse }`。后端 `/api/knowledge/extract` 需 `subject_name` 且返回 `processed_points` 结构（不同），兼容层须把 file_path→读文件→text、并把结果规整为上面 `knowledge_points` 四键结构。

### findSimilarKnowledgePoints
- 签名: `(request_data: str)` → `@Slot(str, result=str)`
- 请求 JSON: `{"subject": str, "point": {"name": str, ...}, "limit": int=10}`
- 返回: **JSON 数组**（顶层即 list）：`[{"id","name","description","similarity": float, "mastery_score", "sources": [...]}, ...]`；无知识点/异常返回 `[]`。`similarity`=匹配分（ImportError 回退固定 0.5）。`sources` 来自 `km.get_knowledge_point_sources(id)`。
- 行为要点: `km.get_knowledge_points_by_subject(subject)` + `similarity_matcher.rank_matches(query=point['name'], ..., min_score=0.0)`。只读。
- 页面调用示例要点: 数组合并/新建对话框候选列表。后端无相似匹配端点 → **B 类**（建议 `POST /api/knowledge/similar` body `{subject, point_name, limit}`）。

### mergeKnowledgePoint
- 签名: `(merge_data: str)` → `@Slot(str, result=str)`
- 请求 JSON: `{"noteInfo": {"filePath": str, ...}, "currentPoint": {"name","description",...}, "targetKnowledgeId": <id>}`
- 返回: 成功 JSON：
  ```json
  {"success": true, "message": "知识点合并成功", "merged_knowledge_id": <targetKnowledgeId>,
   "updated_point": {"id": <target>, "name": str, "description": str, "mastery_score": <..>, "sources": [...]}}
  ```
  目标不存在 `{"success": false, "error": "目标知识点不存在"}`；异常 `{"success": false, "error": str}`。
- 行为要点: `_findOrCreateNoteRecord` 得 note_uuid → UPDATE 目标知识点 core_description（当前保持原描述）→ `km.link_knowledge_point_to_note(target, note_uuid)`。
- 页面调用示例要点: 无对应端点（confirm 只新建不合并）→ B 类。

### createNewKnowledgePoint
- 签名: `(create_data: str)` → `@Slot(str, result=str)`
- 请求 JSON: `{"noteInfo": {"filePath": str}, "subject": str, "point": {"name","description",...}}`
- 返回: 成功：
  ```json
  {"success": true, "message": "新知识点创建成功", "knowledge_id": <new_id>,
  ```

## 七、AI 对话

### chatWithAI
- 签名: `(message: str, conversation_history_json: str = "[]")` → `@Slot(str, str, result=str)`
- 返回: 立即返回占位 `{"success": true, "message": "processing", "status": "processing"}`（**不做实际处理**）。
- 行为要点: 无副作用；真正的异步在 chatWithAIAsync。
- 页面调用示例要点: 多数页面直接用 chatWithAIAsync。

### chatWithAIAsync
- 签名: `(message: str, conversation_history_json: str = "[]")` → `@Slot(str, str)`（**无 result，走信号**）
- 返回: 无直接返回。后台线程调 `call_llm`，结果通过 **`chatResponseReady` 信号**推送（见下）。
- 行为要点: 新线程构造带最近10条历史的 system_prompt → call_llm；成功/失败/异常都 `self.chatResponseReady.emit(json)`（失败用随机柯基 fallback 文案，仍 `success:true`）。
- 页面调用示例要点: 前端不 await 此调用，靠监听信号取结果。

### chatResponseReady信号
- 类型: `Signal(str)`（非方法）。
- 载荷: JSON 字符串 `{"success": true, "message": <AI回复或fallback文案>}`。三种路径都带 `success:true`（连异常也用友好文案，不返回 error 字段）。
- 行为要点: Qt 中经 `QWebChannel` 信号→JS 槽，前端形如 `bridge.chatResponseReady.connect(function(json){...})`。
- 页面调用示例要点: 迁移后须以 **Electron IPC/事件**（主进程→渲染进程 `ipcRenderer.on('chat:response')` 或 SSE）复刻"推送 + 前端注册回调"，字段保持 `{success, message}`。后端可映射 `POST /api/llm/call`（但需自行加异步推送通道）。

### summarizeConversation

- 行为要点: 历史拼文本（`role`→"用户"/"AI助手"）→ call_llm。
- 页面调用示例要点: 映射 `POST /api/llm/call`（prompt 前端拼）。

### saveConversation

- 返回: 成功 `{"success": true, "message": "对话已保存"}`；异常 `{"success": false, "error": "保存失败: <err>"}`。
- 行为要点: 写 `<脚本目录>/conversations/conversation_<id>.json`（id 缺省用时间戳 `%Y%m%d_%H%M%S`）；存前加 `conversation_data['timestamp']=isoformat`。indent=2。

### 附：本次核对到的、迁移须特别注意的"字段/返回类型陷阱"
1. `loadMarkdownFile`/`loadMarkdownRaw`/`generatePracticeQuestions`/`evaluatePracticeAnswers`/`testLLMConnection`/`validateAllFileOperations`/`saveTranscriptSession`/`createNewNote`/`createNewFolder` 返回**纯字符串**（HTML/原文/文本/路径/文件名），不是 JSON。
2. `saveMarkdownFile`/`saveConfig`/`saveMindmap`/`clearLLMLogs` 返回 **bool**（非 JSON）。
3. `getSubjects` 返回**学科名数组**；`getAllSubjects` 返回 `{name,knowledge_count,can_delete}`；`getSubjectsWithKnowledgeCount` 返回 `{name,knowledge_count}` 且仅 kp>0——三者字段/过滤各异。
4. `getPracticeHistory` 的 practices 每条含多组**兼容别名字段**（id/practice_id、questions/question、user_answers/answer、evaluation_result/evaluation），须原样保留。
5. `findSimilarKnowledgePoints`/`getSubjectKnowledgePoints`/`getNoteKnowledgePoints`/`getSubjectsWithKnowledgeCount`/`getSubjects`/`getAllSubjects` 顶层是**数组**（无 success 包装），错误时也返回 `[]`。
6. `getSelectedDevice` 未选设备用 `message` 而非 `error`；`startRecording` 未选设备额外带 `needDeviceSelection: true`。
7. `createNewKnowledgePoint` DB 写 mastery_score=-1 但返回体回填 50；`getKnowledgePointNotes` 的 `content` 是占位串非正文。
8. `render_markdown`/`copyFileOrFolder`/`resumeRecording`/`testDeviceCompatibility` **桥类未定义**（页面仍在调），兼容层需补桩或前端化。
