# 截图路径修复说明

## 问题描述
用户反馈截图存储位置错误，应该存储到当前打开的MD文件路径下的attachments目录中。

### 示例
- 当前打开文件：`E:\LLM\LectureLearnLoop\vault\新建笔记1.md`
- 应该存储到：`E:\LLM\LectureLearnLoop\vault\attachments\`
- 如果目录不存在，则自动创建

## 修复方案

### 1. 后端修复 (`overlay_drag_corgi_app.py`)

#### 1.1 在文件加载时保存路径
在 `loadMarkdownRaw()` 方法中添加：
```python
# 保存当前文件路径，用于截图等功能
self.current_file_path = file_path
self.logger.info(f"已保存当前文件路径: {self.current_file_path}")
```

#### 1.2 在文件保存时更新路径
在 `saveMarkdownFile()` 方法中添加：
```python
# 保存当前文件路径，用于截图等功能
self.current_file_path = file_path
self.logger.info(f"已更新当前文件路径: {self.current_file_path}")
```

#### 1.3 增强截图路径处理
在 `_on_screenshot_captured()` 方法中添加详细的日志记录：
```python
current_file_path = getattr(self, 'current_file_path', None)
self.logger.info(f"当前文件路径: {current_file_path}")

if current_file_path:
    # 获取文档所在目录
    doc_dir = os.path.dirname(current_file_path)
    attachments_dir = os.path.join(doc_dir, 'attachments')
    self.logger.info(f"文档目录: {doc_dir}")
    self.logger.info(f"attachments目录: {attachments_dir}")
```

## 修复后的工作流程

### 文件路径跟踪
1. **文件加载时**: `loadMarkdownRaw()` → 保存 `self.current_file_path`
2. **文件保存时**: `saveMarkdownFile()` → 更新 `self.current_file_path`
3. **截图时**: `_on_screenshot_captured()` → 使用 `self.current_file_path`

### 目录结构示例
```
vault/
├── 新建笔记1.md              # 当前打开的文件
├── attachments/              # 截图存储目录（自动创建）
│   ├── screenshot_20250926_091234.png
│   └── screenshot_20250926_091456.png
└── 其他笔记.md
```

### 路径处理逻辑
1. **有当前文件**: 使用文件所在目录的attachments子目录
2. **无当前文件**: 回退到course_notes/attachments目录
3. **目录不存在**: 自动创建attachments目录

## 技术细节

### 路径处理
- 使用 `os.path.dirname()` 获取文件所在目录
- 使用 `os.path.join()` 构建attachments路径
- 使用 `os.makedirs()` 创建目录（如果不存在）

### 错误处理
- 如果没有当前文件路径，回退到默认目录
- 添加详细的日志记录便于调试
- 确保目录创建的异常处理

### 兼容性
- 支持Windows路径格式
- 支持中文文件名和路径
- 保持与现有功能的兼容性

## 总结
通过在文件加载和保存时跟踪当前文件路径，截图功能现在可以正确地将图片保存到对应文档目录的attachments子目录中，实现了用户期望的文件组织结构。
