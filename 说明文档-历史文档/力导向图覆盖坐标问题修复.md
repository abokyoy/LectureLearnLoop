# 力导向图覆盖坐标问题修复

## 🚨 **问题根因发现**

用户反馈子节点仍然往左偏移，我添加了详细的调试日志后发现了真正的问题：

### **关键问题**：力导向图配置覆盖了手动设置的坐标！

```javascript
// 问题代码（第2881行）
.force('y', d3.forceY(d => {
    if (d.type === 'start' || d.type === 'stage' || d.type === 'end') {
        return 350; // 主线固定在水平线上
    }
    // 🚨 这里使用随机分布，完全覆盖了我们的手动设置！
    return 350 + (Math.random() - 0.5) * 300; // 增加分布范围
}).strength(d => {
    return 0.3; // 知识点节点较弱的力 - 但仍然会影响位置
}))
```

## 🔍 **问题分析**

### 1. **Y坐标被随机覆盖**
- 我们手动设置：`kp.y = stageY ± verticalSpacing`
- 力导向图覆盖：`return 350 + (Math.random() - 0.5) * 300`
- 结果：所有精心计算的Y坐标都被随机值替换！

### 2. **X坐标也受影响**
- 虽然`forceX`使用了`return d.x`，但力的强度和其他力的相互作用仍然会改变位置
- 碰撞检测、连线拉力等都会影响最终位置

### 3. **为什么看不到我们的布局算法日志**
- 布局算法确实在执行，但力导向图立即覆盖了结果
- 用户看到的是力导向图的最终结果，不是我们的预设位置

## ✅ **修复方案**

### 1. **修复Y坐标力**
```javascript
// 修复前
return 350 + (Math.random() - 0.5) * 300; // 随机分布

// 修复后  
return d.y; // 使用预设的Y坐标，不再随机分布
```

### 2. **增强坐标保持力度**
```javascript
// 修复前
return 0.3; // 知识点节点较弱的力

// 修复后
return 0.8; // 知识点节点也使用较强的力保持预设位置
```

### 3. **完善X坐标力配置**
```javascript
// 修复前
}).strength(0.8))

// 修复后
}).strength(d => {
    // 知识点节点也使用较强的力保持预设位置
    if (d.type === 'existing_kp' || d.type === 'supplement_kp') {
        return 0.8; // 知识点使用较强的力保持预设X坐标
    }
    return 0.8; // 其他节点也保持较强的力
}))
```
